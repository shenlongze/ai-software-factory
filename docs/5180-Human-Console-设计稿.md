## 1. 定位（一句话）

**5180 = 用户把一个想法做成软件产品的端到端工作台**（创建项目→发现→PRD→看板→执行→质量→交付）。
board（8011）= 开发者/运维/集成者的控制台（战役/员工/API/成本/审计/决策链）。

## 2. 布局（Codex 风格, 用户指定）

```
┌─────────┬──────────────────────────────────┬──────────────┐
│ 左栏 项目列表│ 顶栏: 项目名 · 生命周期状态 · 当前页      │ 右栏 上下文   │
│ ➕ 新建    ├──────────────────────────────────┤ (按需出现)    │
│ 🔍 搜索   │ 中央 项目工作区                     │ 审批卡片      │
│ ──────   │   [概览][发现][PRD][看板][执行][质量] │ 质量分       │
│ ● 进行中   │  ┌────────────────────────────┐  │ 执行日志      │
│ ● 墨笺    │  │ 发现对话 / 页面内容           │  │ 最近产物      │

│          │  ┌────────────────────────────┐  │ (平时收起)    │
```

- 左栏 = 项目列表（Codex 任务列表的形态）：新建/搜索/分组(进行中·已交付)
- 顶栏 = 项目名 + 状态 + 当前页 + 设置 + 「🛠 开发者控制台」链接(→board)
- 中央 = 项目工作区（项目内 7 页）
- 底部 = 全局对话输入（发现澄清/改需求/命令，与 AI Factory 对话）
- 右栏 = 上下文面板，按当前上下文出现（审批/质量/日志/产物），不常驻

## 3. 信息架构（3 套 → 1 套）

**砍掉**:
- ModeToggle（普通 ↔ Expert 双模式）

**移去 board（开发者控制台）**:
- 决策链 / 智能 / 审计 / 成本监控 / 战役 / 员工 → board 已有或待补

| 目标页 | 合并来源 |
|---|---|
| 概览 | ①Dashboard + ③overview + ③vision/roadmap → 生命周期进度 + 路线 |

- 设置 = ②settings + ①Providers（expert）→ 全局设置（模型/Provider/团队）

## 7. OS v2（Founder 第二轮确认, 2026-08-26）

> 修正: 5180 不是"项目管理器", 是 **AI Factory OS**——公司/行业/部门/项目都是被管理对象。

### 7.1 OS 层级（默认一人公司根）
- 默认根 = **"我的公司"**（虚拟根目录, 当公司用）→ 项目直接挂下面
- 支持 **rename** / **复制出去**（copy 成独立公司）
- **部门**: 仅用户显式创建时才出现（默认无部门层）
- 左栏 = OS 层级树（公司/行业 → 部门(可选) → 项目）, 可折叠; 新建: 公司/行业/部门/项目

### 7.2 init 指定目录
- `factory init --dir <路径>` → 默认创建必要文件/文件夹（agents/skills/projects/providers/workspace + "我的公司"）

### 7.3 对话分域（入口要有说法）
- **项目外** = 全局对话（创建/讨论想法/发现）
- **项目内** = 只针对当前项目（改需求/发命令/状态）
- 同一个 Composer, 位置/上下文决定作用域; 真实接线（非占位）

### 7.4 项目首页（Founder 要求设计）
```
顶栏: ◆ AI Factory │ 📁 项目 │ 生命周期状态 │ 开发者控制台
左栏: OS 层级树                    中央: 项目首页
  🏢 我的公司                       ① 全生命周期条 (11 段 + 进度 + 当前卡点)
  ├─ 📁 项目A                       ② 任务 Todo (列表 ⇄ 看板泳道 可切换)
  └─ 📁 项目B                       ③ 运维/监控 (执行/质量分/成本/失败)
                                    ④ 项目内对话 (底部 Composer, 针对本项目)
```

### 7.5 敏捷项目管理（统一方法）
- 方法: **Agile (Scrum/Kanban)** — backlog/sprint/milestone 对齐现有后端
- Todo 双视图: **列表**（默认, 筛选/批量）⇄ **看板泳道**（待办/进行中/已完成, 拖拽）
- **编辑**: 行内编辑（标题/描述/优先级 P0-P2/负责人）
- **归档**: 完成任务 → 归档区（可展开查看）; 后端需补归档接口
- **审计/溯源**: 点任务 → 该任务审计链（创建/变更/执行/完成, 接 K-4 trace）
- 原则: **简单 · 直接 · 高效 · 易用**（不堆功能）

- **会话状态**: ● 进行中 / ○ 已归档(可恢复)

#### 7.9.3 上下文管理（规划 · 压缩 · 切换）— 核心设计

**① 环境 = 作用域 (Context Scope)**

| 作用域 | 上下文内容 | 会话归属 |
|---|---|---|
| 🏢 公司 | 项目列表/全局待办/经验库/决策记忆/全局设置 | 公司级会话 |
| 📁 项目 | 生命周期/PRD/文档索引/todo/质量/成本/执行/参与 agent | 项目级会话 |
| 🎯 任务 | 任务详情/子任务/执行记录/质量分/依赖 (从项目会话派生) | 任务级会话 |
| (未来) 部门/行业 | — | — |

**② 上下文清单 (Context Plan — 规划)**

- 每个会话生成一份**上下文计划** JSON:
  `{scope, facts:{…}, docs:[…], retrieval_plan, budget, created_at}`
- **稳定事实卡** (常驻, ≤800 tokens): 项目名/生命周期阶段/当前卡点/关键文档列表
- **按需注入**: PRD 正文/文档内容/todo/质量分 — 不进系统提示, 会话中经 RAG (K-6)
  检索按需取, 引用带来源 (文件/片段/score)
- **任务绑定**: 会话创建时可绑定一个任务 → 自动注入任务上下文 (依赖/执行记录)
- **注入预算**: 默认 公司 4k / 项目 6k / 任务 4k tokens, 超 80% 触发压缩

**③ 压缩 (Compression)**

- **自动**: 会话 > 20 轮 或 tokens > 预算 80% → 旧轮次压成"会话摘要"
  (决策 + 待办 + 关键事实), 保留最近 10 轮原文
- **摘要落盘**: 存会话元数据; 恢复 = 摘要 + 最近 N 轮 (不载全量历史)
- **沉淀**: 已批准决策 → decision memory (K-3); 经验 → experience store (K-3);
  任务状态 → todo/backlog
- **手动**: 会话头 [压缩] 按钮; **可追溯**: 摘要链接原始轮次 (K-4 trace)

**④ 切换 (Switching) — 铁律: 数据隔离**

- 点 OS 树项目 → B 列工作区 + C 列会话**同步切换**到该项目, 各自历史保留
- 会话列表按作用域隔离; 切回项目 A → 恢复 A 的会话列表 + 当前会话 (摘要+最近轮)
- **不跨项目注入** (加载按作用域, 上下文零串扰)
- 项目间共享的只有: 公司级会话 / 经验库 / 决策记忆 (显式全局)
