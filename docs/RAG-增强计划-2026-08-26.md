## 1. K-6 现状评估（诚实）

**逻辑对（K-6 验收达标）**: 复用 board 扫描入库 · 三级分档(raw/summary/knowledge) · 零污染独立索引
(workspace/.factory_rag) · 增量(mtime/size) · CJK 二元子词词频检索(确定性可解释, 带引用源) ·
外部源接口+Mock · E-5 trace。

**局限（作为"真 RAG"）**:
1. 纯词频 = 字面检索, 非语义检索 (同义/改写/语义相关不命中)
2. 无 LLM 答案生成 (返回片段+引用源, 是"检索"不是"问答")
3. bigram 噪声 ("支付系统"→"付系" 可能命中无关)
4. 无 IDF/长度归一化 (长文档偏)
5. 无重排序

## 3. 两步增强路线

### 第一步：零约束增强（推荐先做, 无向量库/无网络/无重依赖）
- jieba 中文分词（替代 bigram, 更准召回）
- 同义词/别名表（记账=账本=财务流水, 语义改写命中）
- BM25 打分（纯 Python 实现, 替代纯 TF, IDF 归一化）
- 符合"纯规则零依赖"纪律

### 第二步：embedding 语义检索（有约束但环境就绪, 可选）
- ollama 本地 embedding（nomic-embed-text, 离线）→ 真语义检索
- 内存向量索引（纯 Python 余弦, 几千条够用, 不需要向量库）
- 注入点 `query(scorer=)` 已留, 接上即可
