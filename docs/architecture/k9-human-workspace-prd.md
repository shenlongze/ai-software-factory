## 1. 产品定位

**一句话**: AI Factory OS 是一个「和公司说话」的 AI 工作系统——用户用自然语言驱动 AI 员工完成真实工作,并随时看到公司正在做什么。

**目标用户分层**:
| 用户 | 看到的入口 | 需求 |
|------|-----------|------|
| 普通用户 | 对话 / 工作 / 项目 | 说人话驱动, 不接触 Agent/Plugin/Task 术语 |
| 专业用户 | + 运行 / 团队 / 治理 | 观察执行细节、审批、追踪 Evidence |
| 运营/管理员 | + Control Tower | 全局状态、钻取、异常处理 |

**非目标**: 不做 ERP/多租户/商业化; 不暴露 Agent/Plugin/Runtime 等内部术语给普通用户。

---

## 2. 用户故事 (10 个真实场景)

1. **开场**: 用户打开 OS, 看到"和公司说话", 输入"我想做一个台球记分 App"
2. **需求讨论**: AI 先确认"目标用户是谁? 核心功能?" 不立即创建项目 (讨论 ≠ 执行)
3. **决策形成**: 用户确认"个人用户, MVP 先做计分", AI 总结需求 → 用户确认
4. **创建 Work**: "好, 开始做吧" → Project + Sprint + Task Tree 自动创建, 右栏显示任务树
5. **真实执行**: Agent 开始工作, 用户看到"工程 Agent 正在实现计分模块" + 右栏 Code/Diff 实时变化
6. **状态查询**: "现在做到哪了?" → 真实投影回答 (完成/运行中/等待/失败)
7. **失败诊断**: "登录功能报错了" → 右栏 Incident → 诊断 → 修复建议, AI 说明原因
8. **审批**: 高风险操作 → 消息内嵌审批卡 [批准][拒绝], 批准后继续
9. **改需求**: "记分规则改成 3 局制" → Replan, 任务树更新, 受影响任务标注
10. **看结果**: "打开看看" → 右栏 Preview 实时展示 Web App

## 3. 三栏信息架构

### 3.1 左栏 Context (不是传统菜单)

```
AI Factory
💬 对话
   ├── 当前工作
   ├── 最近会话
   └── 收藏
我的工作
   ├── 进行中
   └── 已完成
项目
   ├── 台球计分
   └── ScorePocket
团队            (专业用户)
   ├── 开发/产品/QA
运行中          (专业用户)
   🟢 3 个 Agent 在工作
审批            (专业用户)
   🔴 1 个待审批
```

**动态规则**: 普通用户 = 对话/我的工作/项目; 专业用户 = +团队/运行中/审批/治理。

### 3.2 中栏 Conversation (人机协作空间)

**消息类型**:
| 类型 | 示例 | 交互 |
|------|------|------|
| 纯文本 | AI 回复/澄清/解释 | 无按钮 |
| 需求分析卡 | 分析结果 (目标用户/流程/待确认) | [查看分析] [继续讨论] |
| PRD 卡 | 需求文档摘要 | [查看 PRD] [确认需求] |
| 任务树卡 | Sprint/Task 状态 | [查看任务] [开始执行] |
| 执行状态卡 | Agent 进度 | [查看详情] |
| 失败诊断卡 | 失败原因 + 建议 | [查看诊断] [修复] [忽略] |
| 审批卡 | 高风险操作请求 | [批准] [拒绝] [查看方案] |

**输入区**: 文本输入 + 附件入口; 发送后等待真实回复 (不伪造)。

### 3.3 右栏 Workspace (AI 工作现场)

**Tab 集合**:
| Tab | 内容 | 数据源 |
|-----|------|--------|
| Preview | Web App 实时预览 | 真实产物 |
| Code | 代码文件查看 | /api/artifacts/content |
| Files | 项目文件树 | /api/artifacts |
| Terminal | 执行输出 | production_run logs |
| Diff | 代码变更对比 | artifacts diff |
| Task | 任务树/状态 | /api/task-trees + projects-os |
| Evidence | 验证证据 | /api/evidence |

**多 Tab + 分屏**: `Preview | Code` 并排 (IDE/Browser 式), Tab 可关可开。

## 4. 消息卡片规范 (6 种)

### 4.1 需求分析卡
```
┌─ 📋 需求分析 ────────────────┐
│ ✓ 核心用户: 个人台球爱好者     │
│ ✓ 核心流程: 开新局→记分→结算   │
│ ⚠ 待确认: 是否需要联网对战     │
│                              │
│ [查看分析] [继续讨论]          │
└──────────────────────────────┘
```
字段: 确认项(✓)/待确认项(⚠)/建议; 按钮: 查看分析/继续讨论。

### 4.2 PRD 卡
```
┌─ 📄 Product Requirement ─────┐
│ 台球计分 App v1              │
│ 定位: 个人爱好者轻量记分工具   │
│ 范围: MVP (计分/结算/历史)     │
│                              │
│ [查看 PRD] [确认需求]          │
└──────────────────────────────┘
```
字段: 标题/定位/范围; 按钮: 查看 PRD/确认需求(→ 触发 Work 创建)。

### 4.3 任务树卡
```
┌─ 📊 Task Tree ───────────────┐
│ Sprint 1: MVP                │
│  T001 产品分析  ✅            │
│  T002 计分模块  🟢 运行中      │
│  T003 界面     ⏳ 等待         │
│                              │
│ [查看任务] [暂停] [继续]        │
└──────────────────────────────┘
```
字段: Sprint/Task/状态; 按钮: 查看任务(→ 右栏 Task Tab)。

### 4.4 执行状态卡
```
┌─ ⚙️ 执行中 ──────────────────┐
│ 工程 Agent → T002 计分模块     │
│ 进度 45% · 已运行 2m          │
│ 最近: 生成 API 路由            │
│                              │
│ [查看详情]                     │
└──────────────────────────────┘
```
字段: Agent/Task/进度/最近事件; 按钮: 查看详情(→ 右栏 Code/Terminal)。

### 4.5 失败诊断卡
```
┌─ 🐛 执行遇到问题 ─────────────┐
│ 任务: T005 登录模块 FAILED    │
│ 原因: 测试未通过 (JWT 校验)    │
│ 建议: 修复 JWT 过期处理        │
│                              │
│ [查看诊断] [修复] [忽略]        │
└──────────────────────────────┘
```
字段: 任务/原因(evidence-backed)/建议; 按钮: 查看诊断/修复(触发 Self-Healing)/忽略。

### 4.6 审批卡
```
┌─ 🔐 需要你的批准 ─────────────┐
│ 操作: 部署到生产环境           │
│ 风险: HIGH                   │
│ 请求方: DevOps Agent          │
│                              │
│ [批准] [拒绝] [查看方案]        │
└──────────────────────────────┘
```
字段: 操作/风险/请求方; 按钮: 批准(→ Governance 通过)/拒绝(→ 停止)。

## 5. Workspace 联动规则表 (Intent → Work → Artifact → Tab)

| # | 用户意图/消息 | 当前 Work | 右栏自动切换 |
|---|-------------|-----------|-------------|
| 1 | 分析产品需求 | 讨论中 | 📋 需求分析 |
| 2 | 写 PRD / 确认需求 | Requirement 已建 | 📄 PRD.md |
| 3 | 开始开发 / 执行 | Project/Sprint 已建 | 📊 Task Tree |
| 4 | 任务进行中 (Agent 工作) | Task RUNNING | ⚙️ Code + Terminal |
| 5 | 查看产物 / 打开看看 | Artifact 已产生 | 🌐 Preview |
| 6 | 代码变更 | 有 diff | 📝 Diff |
| 7 | 查看文件 | Artifact 列表 | 📁 Files |
| 8 | 测试结果 / 验证 | Verification 完成 | ✅ Evidence |
| 9 | 失败了 / 报错 | Task FAILED | 🐛 诊断 |
| 10 | 审批请求 | Approval PENDING | 🔐 审批详情 |
| 11 | 改需求 / Replan | Requirement v2 | 📊 任务树 (受影响标注) |
| 12 | 现在什么状态 | 任意 | 📊 任务树 (实时投影) |

**规则**: 中栏消息 → 解析 Intent + 关联 Work/Artifact → 设置右栏 Tab。右栏**被动跟随**, 用户可手动切 Tab, 但新消息会再次联动。

## 6. 用户旅程 (完整 12 步)

```
打开 OS → 左栏 Context + 中栏对话 (默认) + 右栏空
  ↓ 1. "我想做台球计分 App"
  ↓ 2. AI 澄清: 目标用户? 核心功能? (右栏: 需求分析卡)
  ↓ 3. 用户确认 → AI 总结 → 需求分析卡 ✓ (右栏: 📋 分析)
  ↓ 4. "确认, 开始做" → PRD 卡 → 右栏: 📄 PRD
  ↓ 5. "开始执行" → Project/Sprint/Task 创建 → 任务树卡 → 右栏: 📊 Task
  ↓ 6. Agent 执行 → 执行状态卡 → 右栏: ⚙️ Code
  ↓ 7. "现在到哪了?" → 任务树卡 (实时) → 右栏: 📊 Task
  ↓ 8. 失败 → 诊断卡 → 右栏: 🐛 诊断
  ↓ 9. "修复" → Self-Healing → 执行状态卡 → 右栏: 📝 Diff
  ↓ 10. 高风险操作 → 审批卡 → 右栏: 🔐 审批
  ↓ 11. 批准 → 继续执行 → 状态卡 → 右栏: ⚙️ Code
  ↓ 12. "打开看看" → 完成 → 右栏: 🌐 Preview
```

## 7. 验收标准 (普通用户视角)

1. 打开后看到"和公司说话", 不看到 Agent/Plugin/Task 术语
2. 输入"我想做 XX" → 自然讨论, 不立即建项目
3. 需求确认后 → 才创建 Work (讨论 ≠ 执行)
4. 执行中右栏自动显示对应工作现场 (Code/Preview/Task)
5. "现在到哪了?" → 真实状态, 不编造
6. 失败 → 说人话解释 + 修复建议
7. 审批 → 消息内卡片 [批准][拒绝], 批准前不执行
8. 改需求 → 任务树更新, 受影响任务标注
9. 全程无需理解任何内部对象名称
10. 刷新/重开 → 状态从 SSOT 恢复

## 8. MVP 范围

**必须有**:
- 三栏布局 (Context/Conversation/Workspace)
- 中栏: 文本消息 + 需求分析卡 + 任务树卡 + 执行状态卡 + 审批卡
- 右栏: Task Tree / Code / Preview / Diff / Evidence (5 个核心 Tab)
- 联动: 消息 → Tab 自动切换 (规则表 1-10)
- 真实数据: 全来自 OS API (conversations/projects-os/task-trees/ops)
- UI 零业务状态, polling 5s (SSE 后置)

**明确不做** (本版):
- 多工具分屏 (Code|Preview 并排) → v1.1
- Terminal 实时流 / 多 Tab 任意拖拽 → v1.1
- 用户身份分级动态导航 → v1.1 (先做统一导航)
- SSE 实时推送 → 后置 (polling 兜底)
- Control Tower 深度钻取 → 后置 (保留现有独立页)

## 9. 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 三栏重构破坏现有页面 (Work/Tower) | 高 | 保留路由, 中栏嵌入; 不删功能 |
| Workspace 联动过激 (Tab 乱跳) | 中 | 规则表白名单, 仅 12 条规则 |
| 消息卡片数据不足 (后端无对应字段) | 中 | 复用现有 API, 缺字段先降级为文本 |
| 右栏变"工具大杂烩" | 中 | 由 Work/Conversation 决定, 非用户自选 |
| 性能 (每消息轮询) | 低 | 仅右栏 polling, 中栏消息即时 |
| 用户感知"太多" | 中 | 普通用户默认只看 3 入口, 专业展开 |
