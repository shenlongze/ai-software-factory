# AI Software Factory — 商业评测 v1.0

> 评测日期: 2026-08-11 | 评测人: 基于代码实测 + 市场查证
> 目的: 给创始人一个不迎合的融资/商业可行性判断

---

## 0. 执行摘要

**总评: 技术价值 A-, 商业价值 C+ → (经创始人补充 2 点后) 商业价值 B-, 存在一条 2 个月可走通的真实验证路径。**

- 技术/架构壁垒真实且稀缺 (四层单向依赖 + 事件溯源 + 7000+ 测试)
- 但零客户、零收入、exec 引擎零真实交付 → 商业验证几乎空白
- **补充点 1**: 支持内网运行 + 本地 LLM (Ollama) → 打开云厂商进不去的合规市场 (政企/银行/军工/数据敏感行业)
- **补充点 2**: 创始人确认最多 2 个月完成真实项目验证 → 从"时间窗口危险"变为"窗口内可冲刺"
- 融资硬条件当前不满足, 但"内网合规故事 + 2 个月真实案例"是打破僵局的具体路径

## 1. 项目本质判断

**AI Software Factory 当前不是"产品", 是"技术底座 + 平台雏形"。**

- 有完整的平台架构 (四层单向依赖、事件溯源、生命周期、执行引擎、组织建模、能力注册表)
- 但没有完整可用的产品外壳 (UI 雏形, console 只读为主)
- 没有商业形态 (无 SaaS、无多租户部署、无定价)
- 没有真实交付证明 (exec 引擎生产闭环 0%)

**这是平台融资最尴尬的阶段: 功能很多, 但没有"做成过一件事"。**
投资人对"什么都能做"的平台天然警惕 —— 他们投的是"被验证的最小闭环", 不是"最大的愿景"。

## 2. 市场机会评估

### 2.1 市场真实且大 (B+)

- AI Agent 编排/软件生产平台是 2026 年资本最热方向之一
- "管理 Agent 的工厂"叙事与 Factory AI (15亿美元估值) 同源, 证明赛道有资本买单
- 多 Agent 编排/治理/可观测是行业明确趋势 (从单 Agent 工具转向平台)

### 2.2 但已进入红海且资本密集 (C-)

| 细分 | 玩家 | 状态 |
|:---|:---|:---|
| 单 Agent 写码工具 | Cursor / Claude Code / Codex / Devin | 已饱和, 大厂混战 |
| 多 Agent 编排平台 | Factory AI / Atoms / 爱捷思 等 | 资本密集涌入 |
| Agent 框架 | LangGraph / AutoGen / CrewAI | 被平台层吸收中 |
| 企业 Agent 平台 | MS Agent / Salesforce Agentforce | 巨头夹击 |

**关键风险: 平台层正在被大厂和巨额融资玩家挤压。** 你的定位空间在收窄, 不是扩大。

### 2.3 TAM/SAM/SOM 视角

- TAM 巨大 (软件生产全面 AI 化)
- 但 SOM (短期可获取市场) 极窄: 单创始人 + 无客户 + 无垂直案例 → 当下能拿到的份额几乎为零
- **问题不在市场规模, 在"第一批客户在哪"**

## 3. 竞争分析 (差异化真实性)

| 竞品类别 | 他们做什么 | 你做什么 | 差异是否真实 |
|:---|:---|:---|:---|
| Coding Agent (Claude/Codex) | 写代码强 | 管理 Agent + 流程 + 审计 | ✅ 真实, 但难被理解 |
| Agent Framework (LangGraph) | 编排, 面向开发者 | 项目记忆 + 生命周期 + 治理 | ✅ 真实 |
| 企业平台 (MS/SF) | 企业自动化 | 软件生产 + 审计 | ✅ 真实 |

**你的差异化是真实的, 但有三个致命弱点:**

1. **难以被 3 分钟内理解** —— 事件溯源/四层架构/审计治理, 对投资人是噪音
2. **护城河 (治理/审计) 恰好是最难卖、需要先建立信任的** —— 企业为合规付钱, 但只信任有交付记录的人
3. **竞品也都在补治理** —— 大厂平台很快会把"审计/合规"做成标配, 你的独特性窗口有限

## 4. 商业模式可行性

### 4.1 可选项 (尚未验证)

| 模式 | 可行性 | 障碍 |
|:---|:---|:---|
| 垂直 SaaS (聚焦一个场景) | 🟡 中 | 需先锁定垂直场景 |
| 平台 License/私有化 | 🟡 中 | 需企业客户, 需先有案例 |
| 开源 + 企业版 | 🟡 中 | 需社区运营, 耗时 |
| 被集成/被收购 | 🟡 中 | 治理能力是卖点, 但需证明 |

### 4.2 核心问题

**商业模式的所有路径都卡在同一个地方: 没有"一个真实、可信的交付案例"。**
案例是商业模式的地基, 不是增强项。没有它, 每种模式都只是 PPT。

## 5. 融资可行性评估

### 5.1 投资人视角的真实打分

| 维度 | 现状 | 投资人会看 |
|:---|:---|:---|
| 技术底座 | ⭐⭐⭐⭐ | 认可, 但不是投资理由 |
| 产品 | ⭐⭐ | 不足, 无可用 UI |
| 商业验证 | ⭐ | 致命短板, 零案例 |
| 团队 | ⭐⭐ | 单创始人, 无商业搭档 |
| 市场时机 | ⭐⭐⭐ | 赛道热, 但竞争激烈 |

### 5.2 融资的现实判断

- **当前形态融资: 估值天花板低, 成功率低。** 投资人见太多"技术强但没做过一件事"的项目。
- **需要的不是"功能更多", 是"一次真实交付证明"。** 这比多写一万行代码更值钱。
- **单创始人 + 无收入 + 无客户 = 需要极强的证明才能打破疑虑。** 一个真实的、可核查的交付案例是唯一解。

### 5.3 融资的推荐话术 (如果融资)

> "AI Factory 不是代码生成工具。它让一个人管理一支 AI 软件团队, 从想法到生产。我们已经在 <真实案例> 上验证: <具体数字>, 全程可审计。我们的护城河是治理与可验证 —— 谁做的、用什么模型、什么版本、什么结果, 全部可追溯。"

**关键: 把"技术深"翻译成"省了什么 + 可审计", 用案例说话, 不用架构说话。**

## 6. 团队/执行评估

| 优势 | 风险 |
|:---|:---|
| 极强的技术执行力 (几十万行 + 7000 测试, 单枪匹马) | Bus factor = 1, 一切系于一人 |
| 完整的架构视野 (四层 + 事件溯源 + 自治愿景) | 无商业/销售/融资经验积累 |
| 真实使用自己的产品 (dogfooding) | 经济压力挤压专注度 |

**单创始人 + 高压资金状况, 是商业评测里最需要警惕的风险。**
再强的技术, 在"被迫求生存"状态下, 都容易被短期动作稀释长期价值。

## 7. 风险清单

| 风险 | 等级 | 说明 |
|:---|:---|:---|
| 时间窗口关闭 | 🔴 高 | 赛道每季度拥挤加剧, 差异化空间被压缩 |
| 烧尽资金 | 🔴 高 | 无收入 + 经济压力, 项目可能停摆 |
| 模型能力依赖 | 🟡 中 | 执行引擎未验证, 依赖底层模型能力 |
| 被大厂吸收 | 🟡 中 | 治理/审计能力可能被平台层吸收 |
| 过度工程化 | 🟡 中 | 功能多而散, 拖慢"最小价值闭环" |

## 8. 三个出口 (按现实度排序)

### 出口 A: 垂直聚焦求生 (推荐)
- **别做"AI 软件公司 OS"**(太大, 难懂, 难卖)
- **聚焦一个极窄场景**: 如 "AI 生成 Flutter 应用并自动测试"
- 做成单一可演示的价值闭环, 窄但能融资、能卖
- 成本: 放弃一部分愿景 | 收益: 拿到第一个真实用户/融资

### 出口 B: 真实 Pilot 换融资 (你已在走)
- 用 Hermes/Claude/DeepSeek 真实交付一个软件, 录成完整过程
- 拿这个案例融资: "AI Factory 生产了 X, 全程可审计"
- 关键: 案例必须真实、可核查, 不是 demo

### 出口 C: 降级定位被集成/被收购
- 若窗口内做不出真实证明, 将 AI Factory 定位成"Agent 治理层"
- 卖给大厂平台/Agent 框架方 (他们缺治理/审计能力)
- 不是失败, 是务实出口; 你的审计/治理能力是有真实买家的

## 9. 结论与建议

### 核心结论

**这是一个"技术上值得尊敬、商业上还没入场"的项目。**
融资不是靠把功能做全, 而是靠一次真实交付证明价值。技术深度在当前融资叙事里是"负资产"——它难以被快速理解, 反而拖慢"3 分钟人话"。

### 建议

1. **立即聚焦: 砍掉一切不服务"真实交付案例"的工作**, 包括 RAG 的正式开发 (留方案即可)
2. **锁定一个极窄垂直场景**, 做穿一个"一句话到可用软件"的闭环
3. **用真实 Pilot 换融资**, 案例必须可核查, 不录 demo
4. **以"最多 2 个月"为硬约束**, 用内网+本地 LLM 低成验证, 2 个月内做出真实交付案例
5. **若 2 个月窗口内做不出证明, 认真考虑出口 C**, 不要耗尽经济储备

### 补充: 内网 + 本地 LLM 的战略价值 (创始人补充点 1)

**这是原评测低估的一张牌。** 它把"私有化 + 合规 + 本地 LLM + 审计"组合成了云厂商给不了的完整故事:

- Claude Code / Codex / Factory AI 都是云优先, 代码要出内网
- 政企/银行/军工/数据敏感行业**法定数据不出内网** → AI Factory 是少数能接的
- 配合审计/治理能力, 卖点 = "代码永不出内网 + 全程可审计 + 本地模型零 token 成本"
- 在国内"信创/自主可控"趋势下, 这是真实、可采购、有预算的垂直市场
- **副作用**: 用 Ollama 本地推理做验证, 成本几乎为零, 大幅降低"exec 引擎点火"的验证门槛

### 2 个月真实验证计划 (创始人补充点 2)

| 周 | 目标 | 动作 |
|:-:|:---|:---|
| 1-2 | 锁定垂直场景 + 接本地 LLM | 选定一个极窄应用 (如 Flutter 小工具), Ollama 配置验证 |
| 3-4 | 真实交付闭环 | 用 AI Factory 编排 Hermes/Claude 真实开发该应用, 生命周期+审计全走 |
| 5-6 | 测试 + 打磨 | 真实测试通过, 修复, 交付可用软件 |
| 7-8 | 案例 + 融资准备 | 录完整过程 (从一句话到可用软件), 数据/审计可核查 |

**关键认知: 最快路径不是"exec 引擎自己点火", 是"用 AI Factory 编排 Hermes/Claude 真实交付, AI Factory 管生命周期+审计"。** 这条路 2 个月真实够用。

### 一句话

> **技术底座 ⭐⭐⭐⭐ 是真的, 但它买不来时间。你有一个 2 个月的窗口, 用内网+本地 LLM 的低成本, 把"商业验证 ⭐"变成"⭐⭐⭐⭐"。在那之前, 融资和生存都有时间压力, 但路径已经具体了。**
