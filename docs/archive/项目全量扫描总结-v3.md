## 3. 重大进展: S10-016~020 五个 Sprint 落地

| Sprint | 内容 | 规模 | 状态 |

| **S10-019** | **Skill System (Registry/Permission)** | skill.py 420行 | ✅ |
| **S10-020** | **MCP Adapter (Client/Registry/ToolAdapter)** | mcp.py 18k行 | 🔄 开发中 |

**意义: "能力树 ⏳ 侧" (Agent Runtime/Executor/Tool/Skill/MCP) 正在逐个变 ✅。执行引擎从"空壳"变成"有骨架"。**

**架构亮点 (设计正确):**
- MCP 是 Tool Runtime 的外部扩展, 不绕过内部治理 (经 ToolRegistry/Permission)
- Skill 有最小权限 (permissions); Tool 默认全部禁止, 白名单开放
- 执行循环有明确状态机; 失败响亮 (不假装成功)
- Removal Isolation: 各模块只依赖 stdlib + pydantic + 本层 models

## 6. 核心判断 (更新)

**项目重心从"编排/管理"转向"真实执行"** — 正是 v1 命门方向。

**但"真实点火"仍未发生:** 这些是骨架 (有测试, 但 LLMPlanner 未接真实 Provider, MockActionExecutor 是 mock)。**代码从"空壳"变成"有骨架的执行系统", 但"用真实 LLM 跑真实软件"仍是下一步。**
