# S20.5 Production Integrity Hardening — Completion Report

> 日期: 2026-08-29 | HEAD: (S20.5 commit) | v1.1.327

## 1. GAP
S0-S20 Integrity Audit 发现 3 MAJOR: 并发锁缺口 / Recovery 不覆盖 VERIFYING / verification retry 缺失。

## 2. GAP-1: 并发保护 — REAL
- integrity_lock.py: fcntl.flock 跨进程锁 + 进程内 RLock + 线程本地重入计数(同线程重入跳过重复 flock)
- release/rollback/governance 的 mutation(_transition/create/approve/reject/request)全部包锁
- 与 atomic write(tmp+fsync+os.replace)组合 = 完整并发安全
- 测试证明: 并发 release execute × 4 → 全部 no-op(单次 apply);并发 approve × 4 → 恰好 1 次成功

## 3. GAP-2: Recovery VERIFYING — REAL
- release_service.recover_verifying: VERIFYING + PASS evidence → RELEASED;无 evidence → 重验(bounded);FAIL → 真实 FAILED
- rollback_service.recover_verifying: 同理 → ROLLED_BACK
- 不伪造成功: 重验失败保持 FAILED

## 4. GAP-3: Verification Retry — REAL
- retry_policy.py: MAX_VERIFICATION_ATTEMPTS=3(单一来源)+ is_retryable_verification 分类
  RETRYABLE: exit_code{-1,124,137,143} / timeout / command not found / killed
  NON_RETRYABLE: syntax / pytest assert / deterministic fail
- release/rollback execute 复用 _run_verification(bounded retry loop)
- verification_attempts append-only(lineage 保留: attempt1 FAIL → attempt2 PASS)
