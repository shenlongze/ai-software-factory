# 00 — S49 REPORT: Hermes 行为逆向 + AF 吸收候选 (2026-09-07, READ-ONLY)

## 核心结论
Hermes 的"自然"主要来自:
1. **完整上下文** (全历史 + 全部工具结果原文参与推理) — 系统
2. **运行时极简** (无互相竞争的中间判定层; 单 LLM 自决) — 系统
3. **工具结果即对话事实** (引用上轮结果 → 不重查) — 系统
4. **LLM intrinsic** (语言理解/推理/合成 — 与 AI Factory 同源同模型)
5. **无显式 Conversation State 组件** — 状态隐式在上下文 (跨轮可靠
   由大上下文保证, 非状态 JSON)
6. **停止 = LLM 自决** (问题答完即收; 无"继续查"压力)

## AI Factory 差异 (证据对照 02)
| 维度 | 差异 | 归因 |
|---|---|---|
| 上下文 | 4 轮扁平 vs 全量 → 丢已查事实 → 重查/猜 | 系统 (最大单项) |
| 提示组织 | 15-25 system 互竞争/稀释; 曾执行指令 vs 克制冲突 (E3.2) | 系统 |
| 工具面 | CORE 4/5=诊断; 引导偏继续查/执行 | 系统 |
| 回答合成 | 无"结论先行/禁空转"约束; FACT 分层未落地 | 系统+prompt |
| 状态 | 显式 (conv_state/gate) — 生产跨轮可靠 (强于 Hermes) | AF 需要 |

## LLM vs 系统
同一类模型: Hermes 自然 ≠ AF 不自然 = 模型差异;
= 上下文构造/提示组织/工具面/循环压力 的系统差异。
LLM intrinsic 部分两边相等 — 修复系统即可拉近。

## 吸收 (04)
A 必须: ① 已有结果即事实 (追问轮 0 工具综合) ② 完整上下文 (8 轮含
  工具结果) ③ 单执行指令贴 user + 引导降噪 ④ 结论先行/禁空转
  ⑤ 执行轮工具面收起诊断 (gate 保留 — AF 写生产 truth, 必需)
B 可吸收: FACT/推断标注 · "要结论/催促"语义 · 记忆纪律
C 不吸收: persona/语气 · 无 gate 自由 (AF 写生产) · 无成本截断
  · 工具完全自由 (AF 授权层必需)

## 终极回答
AF 缺的不是"一个更高层 Conversation Runtime 组件"。
缺的是把**已存在事实与指令以 Hermes 方式喂给同一个 LLM**:
更厚上下文 + 更少冲突提示 + 已查结果复用约束 + 结论先行的回答纪律。
这些是 context/prompt/loop 纪律, 不是新引擎。
(P0: 上下文完整性 · P1: 提示降噪/单指令 · P1: 追问综合约束 ·
 P2: 结论先行模板/FACT 标注)
