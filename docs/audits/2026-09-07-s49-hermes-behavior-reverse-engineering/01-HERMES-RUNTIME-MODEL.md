# 01 — HERMES RUNTIME MODEL (逆向还原)

## 真实处理链 (非套模板)
Hermes = 单 LLM + 自主工具循环。每轮 = 一次 LLM 推理, 输入
(完整对话历史 + 系统提示 + 最近工具结果), 输出 (工具调用或最终回答)。
无显式 Conversation State 组件、无 Planning 组件(计划仅 skill 可选)、
无独立 Intent Classifier、无 Stop Condition 代码。

真实循环:
  1. LLM 读全部上下文 (含所有历史用户/AI 消息 + 每步工具结果原文)
  2. 单次推理内完成: 理解用户句 → 定位到当前话题/目标 (从历史推断)
     → 判断"这轮要不要工具、要哪个" → 决定工具调用或直接回答
  3. 若调工具: 结果作为新消息进上下文 → 回 1 (LLM 自决继续或收尾)
  4. 停止 = LLM 判断"问题已回答"时输出纯回答 (无显式充分性代码)

## 关键: 状态在哪
- Active Work / 当前目标 / 已获事实: 全部隐式存在于上下文 (历史消息 +
  工具结果), 无独立 JSON state
- "上一轮查了什么": 工具结果文本就在历史里, LLM 直接引用
- 记忆 (memory/skills): 系统提示级注入的持久精简画像 + 程序化技能 —
  非会话状态, 是长期上下文
- 无 truncation/摘要组件: 上下文够大, 全量保留 (超长时才滚动)

## 工具决策 (真实现象)
- 何时调: 用户问事实且历史无此事实 → 调; 需要外部 (搜索/终端) → 调
- 何时不调: 历史已有事实 (直接引用上轮结果回答 — 不重查);
  纯讨论/观点/反馈 → 不调; 信息不足但可合理推断+标注 → 不调直接答
- 何时多调: 独立事实并行 → 一批调多个 (工具调用并行)
- 何时停查: 用户问题可答时立即收尾 — LLM 自决, 无强制继续引导
- 何时问: 仅真歧义且影响大; 大多数情况选择"按最合理理解 + 标注假设"

## 关键机制 = 无显式机制
Hermes 自然度主要来自: ① LLM 在完整上下文上的原生推理/合成能力
② 运行时极简 (不注入相互竞争的中间判定层, 不截断丢失已查事实)
③ 工具结果以"对话事实"形态参与推理 (引用而非重查)
→ 结论: 优势主要是 LLM intrinsic + 上下文完整性 + 系统简洁性,
非复杂会话运行时。
