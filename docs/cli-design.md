# CLI 会话界面规格（对齐 Hermes 的 CLI 设计）

> 来源：`~/.hermes/hermes-agent/hermes_cli/skin_engine.py`（Hermes 的皮肤/渲染规格）+ Founder 实测反馈。
> 本文是 **AI Factory OS 的 CLI 会话界面规格**：写清楚"有哪几个区、每个区长什么样、为什么"。
> 规则：**改界面先改本文，再改代码**（Founder 铁律：规则要落文档 + 挂"进入即读"入口）。

## 一、五个区（照 Hermes，一个都不能混）

| 区 | 作用 | 视觉（Hermes 的规格 → 我们的做法） |
|---|---|---|
| banner | 开场: 我是谁 + 你的数据 | 边框框住标题; 数据 1-2 行; 怎么用 1-2 行 |
| **输入区** | 你敲的那一行 | `input_rule` 横线 **上下夹住** + 提示符（Hermes `❯` → 我们 `factory>`）|
| **执行区** | 它跑了什么 | `tool_prefix「┊」` + 工具 emoji + 命令 + 耗时; 输出**原样缩进**在下面 |
| **回答区** | 助手的话 | `response_border` 框 + `response_label`（`⚕ AI Factory OS`）; **用量不写在标题里** |
| **状态栏** | 常驻信息 | 框/回答之后一行: `⚕ 模型 │ ↑in ↓out │ $成本 │ 耗时 │ 查了 N 次` |

**为什么这么分**（Founder 原话）: «输入单独的区域 · Hermes 的回答是单独的区域 · 执行也是独立的» ——
混在一起就"乱、没有分区" ✗。

## 二、四条硬规则（都是从实测的坑换来的）

1. **输入区不重打**: 横线夹住你敲的那一行即可，**不要**再把你说的话复述一遍 ✗（重复 = 噪音）。
2. **执行区不重画**: 工具输出**原样**给人看（模型重画表格会把列画散 ✗）；跑废/空的调用**不展示** ✗。
3. **回答区不堆料**: 回答 ≤3 行；模型/用量/成本/耗时**只出现在状态栏**，不塞进回答标题。
4. **少装饰**: 不要每条输出行都加 `│`、不要到处画分隔线（Hermes 的清晰来自**少装饰** ✓）。

## 三、颜色与开关

- 只在终端里上色（`tty` 判定）；`NO_COLOR=1` 或 `FACTORY_UI=plain` ⇒ 无框、无颜色、无状态栏色。
- 框宽上限 100 列（照 Hermes 通栏，但不超屏）。

## 四、可发现性（照 Hermes）

- **单独打 `/` 回车** ⇒ 出命令表（不用记）。
- **TAB 补全** `/命令`（会话命令 + factory 命令都补）。
- 命令**带不带 `/` 都行**（命令名开头且全 ASCII ⇒ 直接跑）。

## 五、守卫（改坏了就红）

`scripts/smoke_chain_links.py` 里的「三态可辨」「输出可读性」「斜杠可发现性」「Hermes 风格呈现」四组，
逐条锁住上面的规格（分区/框/状态栏/补全/表对齐/不要重画/不要跑废的）。
