## 1. 关键节点（★ 你点名要分析清楚的）

把串行循环里的**共享状态**逐个列出 —— 并行的安全性取决于它们每一个。

| # | 关键节点 | 现状（已取证 ✓） | 并行风险 | 处置 |
|---|---|---|---|---|
| **K1** | **工作区落点** | 所有 node 的 codex 在**同一个** `projects/<P>/workspace/` 干活 | ★★★ **并行必撞** ✗（多 agent 同时改同一批文件） | **每节点独立工作区** + 完成后合并 ✓ |
| **K2** | **跨进程锁** | `production_run._lock = threading.RLock()` —— **进程内** ✓，而执行器是**子进程** ✗ | ★★ 跨进程无保护 ✗ | 落盘级别防撞：临时名带 pid ✓（已有先例）+ 每节点独立文件 ✓ |
| **K3** | **运行记录写入** | `_record(root, run, ...)` + `_write(root, run)` 在 `with _lock` 内 ✓ | ★ 同进程串行化 ✓ 但**记录结构是"单 run 单文件、节点列表"** ✗ → 并发追加要原子 | 节点结果**各写各的文件** ✓ 由 run 汇总读 ✓（避免同文件多写方 ✓） |
| **K4** | **产物/实体存储** | `_SectionStore`/`store_entity` **有进程内锁** ✓；临时名已带 pid ✓（本轮修过 `_write_list` ✗） | ★ 同进程 ✓；跨进程需复核所有写点 | 复核所有 `os.replace` 的临时名 ✓ 统一加 pid ✓ |
| **K5** | **事件流** | SQLite **WAL** ✓ + 单连接 RLock ✓（`store.py:71`） | ✓ 已安全（WAL 多读单写 ✓） | 无需改 ✓（但**同一连接跨线程**要确认 ✓） |
| **K6** | **外部 agent 并发上限** | `max_concurrent: int = 1`（`contracts/organization`）✓ 调度器已用它判"成员已满" ✓ | ★★ 无上限会**打爆机器** ✗ | 显式配置上限 ✓（默认 2-3 ✓）+ 复用调度器既有机制 ✓ |
| **K7** | **依赖感知调度** | 串行遍历 `nodes`；`parallel_groups` 字段**恒为空** ✗ | ★ 不按 DAG 就是"全并行"✗ = 读未写完的文件 ✗ | **按 DAG 拓扑分层** ✓：同层内并行 ✓ 层间串行 ✓ |

### 1.1 关键节点的因果链（为什么 K7 必须先做 ✓）

```
同层并行 ✓                     全并行 ✗（若只把 for 换成线程池）
  依赖满足才跑 ✓                 下游任务在上游产物还没写完时开跑 ✗

```
**K7 是"并行正确性"的前提 ✗** —— 没有它，并行 = 把确定性失败换成随机失败 ✗。

## 6. 刀2 的隔离点地图（2026-09-14 追查完成 ✓）

### 6.1 唯一隔离点 = `project_dir` 的取值 ✓

外部执行器（codex/claude/hermes）的调用模板在
`external_executor/registry.py:30`：

```python

"--sandbox", "workspace-write", "{prompt}"
```

adapter 声明的入参名：`"project_dir": "flag:-C"`（codex）/ `"cwd"`（claude、hermes）。

⇒ **隔离点只有一个：`project_dir` 传给执行器的是什么目录。**

### 6.2 现状：所有节点共用同一个项目工作区 ✗

```

artifact_lifecycle.py:505 → ws = art.get("workspace")                  # 产物也带 workspace ✓
```

⇒ 17 个节点并行时会**全部在这个目录里跑 codex** ✗ → 互相覆盖 ✗

### 6.3 处置（刀2）

1. **节点级目录**：`projects/<P>/nodes/<node_id>/`（由 `project_dir` 指向它 ✓）
2. **执行完合并**：节点完成后把产物合并回 `projects/<P>/workspace/` ✓
   - **冲突必须可见** ✗（同名文件被两个节点改 → 记录冲突 ✓ 不静默覆盖 ✗）
3. **产物链路不变** ✓：`art["workspace"]` 仍指向项目工作区（对外语义不变 ✓）
4. **负例必测** ✓：两个节点同时改同一文件 → 必须**留下冲突记录** ✓ 而不是随机取胜 ✗

### 6.4 为什么不能"只改 project_dir"就完事 ✗

只改目录 → 各节点产出散在 `nodes/<id>/` ✗ 项目工作区**看不到成果** ✗
⇒ **必须同时做合并** ✓ 否则等于"跑完了但东西不见了"✗（比串行更糟 ✗）
