# Community Growth Strategy — AI Factory

> 位置: docs/product/community-growth.md | Sprint: S10-045 | GitHub 开源增长策略

---

## 1. 目标受众分层

| 受众 | 特征 | 价值主张 | 渠道 |
|---|---|---|---|
| **开发者** | 用 AI 编码, 想控制成本 | 多模型 + 成本透明 + 审计 | GitHub / 技术博客 / Hacker News |
| **Agent 开发者** | 用 SDK/框架构建 Agent | 治理底座 + 开箱审计 + Router | GitHub / 框架社区 / Discord |
| **AI 工程师** | 企业平台团队 | 多 Provider 管理 + 治理基础 | 技术分享 / 企业博客 |

## 2. 增长策略(洋葱式开源落地)

### 阶段 1: 种子吸引(当前, 0-100 star)

| 动作 | 说明 | 优先级 |
|---|---|---|
| **仓库转公开** | 首要前提 | P0(用户决策) |
| README 首屏优化 | 已完成(定位/痛点/能力) | ✅ |
| 发布技术博客 | "为什么 AI 需要操作系统" 系列 | P1 |
| 5 分钟演示视频 | 真实 demo run 录屏 | P1 |
| 种子用户 5-10 名 | 反馈 + 口碑 | P1 |
| GitHub Topics | ai-agents/llm-router/software-factory | P2 |

### 阶段 2: 社区启动(100-1000 star)

| 动作 | 说明 | 优先级 |
|---|---|---|
| 洋葱式开源外层 | providers → router 独立开源(知名度) | P1 |
| Contribution 指南优化 | 已有 CONTRIBUTING, 加 good-first-issue | P1 |
| 案例展示 | 种子用户使用案例(use-cases) | P1 |
| 双周更新日志 | CHANGELOG 保持活跃 | P2 |
| 参与 AI 工具榜单 | GitHub Trending / awesome-ai-agents | P2 |

### 阶段 3: 生态成长(1000+ star)

| 动作 | 说明 |
|---|---|
| Agent Marketplace(v0.3+) | 社区 Agent 生态 |
| Plugin 架构开放 | Extension 接口公开 |
| 企业案例 | Enterprise 客户背书 |

## 3. 差异化内容(获客弹药)

| 内容 | 目标受众 | 卖点 |
|---|---|---|
| "Devin 替你干活, AI Factory 管理你的 AI 员工" | 开发者 | 组织隐喻 |
| "多模型成本优化实测"(Router 对比数据) | 开发者/工程师 | 数据驱动 |
| "AI 治理: 为什么审计是护城河" | AI 工程师 | 思想领导力 |
| "真实执行 vs 一问一答"(对比表) | 开发者 | 差异化 |

## 4. 衡量指标

| 指标 | 目标(3 个月) |
|---|---|
| GitHub star | 100+ |
| 种子用户 | 10+ 反馈 |
| Issue 活跃 | 每周 2+ |
| 首次任务成功率 | 80%+(种子用户实测) |
| 复购意愿 | 60%+ 愿继续使用 |

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 大厂内置治理 | 快速建立社区 + 中立定位 |
| 开源了没人用 | 种子用户优先(先验证再扩) |
| 被当"又一个 Agent 框架" | 坚持 OS/治理叙事 |

## 6. 结论

**增长路径: 转公开 → 种子用户 + 博客/视频 → 洋葱式开源外层 → 社区生态。**

- 首要: 转公开(用户决策)+ 种子用户验证
- 内容弹药: 差异化叙事(治理/成本/组织)
- 指标: 3 个月 100 star + 10 种子用户 + 80% 首任务成功率
