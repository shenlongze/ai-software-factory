# AI 变更审计与证据链（AI Change Audit & Evidence Chain）— 可立项产品规格

> 版本: 0.1 (可立项) | 日期: 2026-08-24 | 状态: 审计链+证据包已实现
> 来源: AI Factory 方案书 §5 审计与可观测 · §5.6 可追溯回放 · §5.9 审计报告 · §2.9.1（P0）

---

## 1. 产品概述

**一句话**: 每次 AI 变更的完整证据链（diff+测试+决策+审计事件，hash 防篡改）——"看完证据敢签字，出事能追到根"。

**给谁**: 审计 / 合规 / 研发管理 / 监管部门

**解决什么**:
- AI 改了什么说不清（黑盒变更）
- 出事无证据（AI 背锅 vs 人工背锅各执一词）
- 合规要求（变更可追溯、可回放、可审计）

**价值主张**: "AI 每次变更 = 一份防篡改证据包 + 一条可回放审计链——企业敢让 AI 进生产的基础"。

## 2. 背景与机会

- **痛点**: AI 编码工具改代码**没有证据链**——diff 在，但"为什么这么改/谁批准的/测没测/花多少钱"全无
- **机会**: 审计/合规是最刚需的付费场景（法规要求 AI 变更可追溯），且**与治理平台互补**（治理管审批，证据链管追溯）
- **竞品对照**: 通用 coding agent 无证据链；审计工具（Splunk 等）不认 AI 变更；本产品差异 = **AI 变更专属证据模型**
- **战略地位**: P0——治理平台的"证据底座"，可独立卖（审计场景）

## 3. 目标用户与场景

| 用户 | 场景 | 价值 |
|---|---|---|
| 审计师 | "上季度所有 AI 变更合规吗" | 审计报告 + 全链查询 |
| 研发管理 | "这个事故是哪次 AI 变更引起的" | trace 回溯 + 回放 |
| 合规官 | "AI 改生产前有审批吗" | 审批事件 + 证据关联 |

## 4. 功能范围

### MVP（已实现 ✅）
- [x] **审计事件链**: 52 事件 + sha256 hash 防篡改（append-only, 脱敏）
- [x] **证据包**（EvidenceBundle）: diff + 测试 + 决策 + 日志 + 变更文件
- [x] **血缘追溯**: 资产 parent_artifact / parent_event_id 互引
- [x] **审计查询**（8+ 函数）: events / trace / chain / task / agent / decisions / explain / cost
- [x] **可追溯**（§5.6.1）: 事件全链路可查

### P1（待做）
- [ ] **回放引擎**（§5.6.2-5.6.3）: dry-run / re-exec / 对比报告（L3/L4）
- [ ] **审计报告**（§5.9）: factory audit report --from/--to → md/pdf
- [ ] **审计 API 对外**（audit_* 10 能力补 API, §22.4.1）
- [ ] 审计视图（§5.4: 用户可查看的审计界面）

### P2（远期）
- [ ] WORM 外部存储（防篡改升级, §20.7）
- [ ] 定时报告 + 消息推送（§9.5 渠道）
- [ ] 合规认证对接（SOC2 审计证据输出）

### 明确不做
- 不做执行（只审计/追溯, 与治理平台同铁律）
- 不做监控告警（那是可观测 §5.8, 分离边界 §5.9）

## 5. 端到端用户流程

```
1. AI 变更发生 → 自动落审计事件（谁/何时/哪个模型/多少钱）+ 证据包
2. 审计师: 查询（按项目/Agent/时间/成本）
3. 事故场景: trace 回溯 → 找到问题变更 → 看证据包（diff+测试+决策）
4. 回放（P1）: dry-run 重演该变更 → 对比报告（两次执行 diff）
5. 报告: 按需/定时生成审计报告（变更量/成本/审批率/风险）
6. 防篡改: 审计链 hash 校验（证明"没改过"）
```

## 6. 技术架构（复用 AI Factory，不重造）

```
AI 变更审计与证据链
  ├─ 审计事件（audit/audit_event.py: 52 事件 + sha256 链 ✅）
  ├─ 审计存储（audit_store.py: append-only + 原子落盘 ✅）
  ├─ 证据包（evidence.py: diff+test+决策+日志 ✅）
  ├─ 血缘（handoff_bus parent_artifact ✅）
  ├─ 查询（api/audit.py: 8+ 函数 ✅）
  ├─ 回放引擎（§5.6.3 设计 📐 → P1）
  └─ 报告（§5.9 设计 📐 → P1）
统一契约: audit 事件注册表 · 血缘字段 · E4xx 错误码
```

## 7. 验收标准（可立项门槛）

```
1. 一次 AI 变更 → 审计事件 + 证据包完整（diff+测试+决策可断言）
2. hash 链校验通过（篡改检测: 改一个事件 → 校验失败）
3. trace 回溯: 从事件 → 证据包 → 决策链 可达
4. 审计查询按 项目/Agent/时间/成本 过滤
5. 全量回归 0 新增 + git clean
```

## 8. 商业模式与 Go-to-market

```
包装: "AI 变更证据链 — 每次 AI 改动都有防篡改证据，出事能追到根"
```
