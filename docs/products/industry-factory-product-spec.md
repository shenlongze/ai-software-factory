# 行业工厂产品线（Industry Factory Product Line）— 可立项产品规格

> 版本: 0.1 (可立项) | 日期: 2026-08-24 | 状态: IT 工厂实现中, FactorySpec 设计
> 来源: AI Factory 方案书 §10 行业工厂 · §2.9.1（P1+, 每行业一条产品线）

---

## 1. 产品概述

**一句话**: 同一底座复制的行业 AI 工厂——IT/运维/电商/自媒体/数据分析/办公自动化，每行业一条产品线，开箱即用。

**给谁**: 行业客户（各行业想用 AI 建"自己的智能团队"的组织）

**解决什么**:
- AI Factory 内核通用但行业不懂（每个行业有专属技能/知识/流程）
- 每行业从零搭 AI 团队成本高
- 行业最佳实践不沉淀

**价值主张**: "每个行业一份开箱即用的 AI 工厂——Skill + 知识 + 流程 + 评价 + 学习全配好"。

## 2. 背景与机会

- **痛点**: 通用 AI 平台"什么都能干但什么都不精"；行业客户要的是"懂我行业的 AI 团队"
- **机会**: 行业复制 = AI Factory 的规模化路径（同一内核，N 个行业 = N 条产品线）
- **竞品对照**: 通用 Agent 平台（无行业深度）· 行业软件（无 AI 内核）· 本产品差异 = **行业专属 FactorySpec（Skill+MCP+Knowledge+Workflow+Evaluation+Learning）**
- **战略地位**: P1+——规模化层（内核做透后，行业复制证明可扩展）

## 3. 目标用户与场景

| 用户 | 场景 | 价值 |
|---|---|---|
| IT 团队 | "让 AI 帮我管代码/清积压/做 PRD" | IT 工厂（当前专注） |
| 运维团队 | "让 AI 监控/诊断/修复" | 运维工厂 |
| 电商运营 | "让 AI 做选品/文案/客服" | 电商运营工厂 |

## 4. 功能范围

### MVP（IT 工厂实现中 ✅/🚧）
- [x] **软件开发工厂**（§10.5 软件工厂专项细化）: 需求→PRD→工程→任务→执行→交付 全流程
- [x] **IT 工厂闭环**（create_product/pipeline/repo_mode）
- [ ] **FactorySpec 声明式规格**（employees/capabilities/workflows/governance/assets, 📐）
- [ ] **FactorySpec 自举**（从 IT 提取 spec 可重新实例化, M5）

### P1（待做）
- [ ] **第二行业最小闭环**（M6）: 数据分析或办公自动化工厂跑通
- [ ] 行业知识库（T4: 各行业专属知识）
- [ ] 行业 Evaluation 标准（质量评分/指标）

### P2（远期）
- [ ] 运维/电商/自媒体工厂
- [ ] 行业工厂模板市场（分享/安装）
- [ ] 行业定制服务（客户定制 FactorySpec）

### 明确不做
- 不做"万能行业引擎"（每行业 = 专属 FactorySpec, 不是通用模板套壳）
- 第二行业前不做更多行业（先证明可复制, 再批量）

## 5. 端到端用户流程

```
1. 用户选行业工厂（如"数据分析工厂"）
2. 系统: 加载 FactorySpec（该行业 Skill/MCP/Knowledge/Workflow/Evaluation/Learning）
3. 用户: 描述需求（"这个季度销售数据清洗后生成运营报表"）
4. 系统: 该行业 Agent 团队干活（拆解→调度→执行→证据→审批）
5. 沉淀: 行业经验回流该工厂知识库（越用越懂行业）
6. 复制: 验证后可实例化下一个行业工厂
```

## 6. 技术架构（复用 AI Factory，不重造）

```
行业工厂产品线
  ├─ FactorySpec（声明式规格: employees/capabilities/workflows/governance/assets, 📐）
  ├─ 软件开发工厂（§10.5 专项, ✅ 实现中）
  ├─ 行业场景（§10.2: 软件开发/运维/电商/自媒体/数据分析/办公自动化 ✅ 设计）
  ├─ 工厂扩展机制（§10.3: 模板定制/插件扩展/学习扩展/市场扩展 ✅ 设计）
  ├─ 行业知识（T4 领域知识库, 📐）
  └─ 自举验证（从 IT 提取 spec 重新实例化, M5）
统一契约: FactorySpec schema · 行业命名空间 · 统一内核（§2.10）
```

## 7. 验收标准（可立项门槛）

```
1. 第二行业（数据分析/办公自动化）最小闭环跑通（M6）
2. FactorySpec 从 IT 提取 → 可重新实例化（自举）
3. 行业经验回流（该工厂知识库积累）
4. 统一内核不变（行业 = 配置, 不改内核）
5. 全量回归 0 新增 + git clean
```

## 8. 商业模式与 Go-to-market

```
定价: 按行业订阅/定制（每行业一条产品线）
GTM: 先 IT 工厂做透（当前）→ 第二行业验证可复制（数据分析/办公自动化）→ 批量铺行业
包装: "每行业一份 AI 工厂 — 开箱即用, 越用越懂行业"
```

## 9. 里程碑

| 阶段 | 内容 | 状态 |
|---|---|---|
| M0 IT 工厂 | 软件开发工厂专项（§10.5, 当前） | ✅/🚧 实现中 |
| M1 可复制 | FactorySpec + 自举验证（M5） | 📐 |
| M2 第二行业 | 数据分析/办公自动化最小闭环（M6） | 📐 |
| M3 批量 | 运维/电商/自媒体 + 模板市场 | 远期 |

## 10. 风险与依赖

| 风险 | 缓解 |
|---|---|
| 行业复制 = 套壳 | 每行业专属 FactorySpec（Skill/知识/流程/评价全配） |
| 内核被行业需求拉偏 | 行业 = 配置不改内核（§2.10 统一设计） |
| 行业知识积累慢 | T4 领域知识库 + 行业经验回流 |
| 依赖 | IT 工厂 ✅ · FactorySpec/自举/第二行业 📐 M5/M6 |

## 11. 团队需求

```
2 后端（FactorySpec + 自举 + 第二行业实例化）
1 行业专家（首个第二行业的需求/知识/评价标准）
1 产品/GTM（行业选型 + 复制验证）—— 最大增量 = FactorySpec 自举 + 第二行业
```

---

**结论**: 行业工厂产品线 = **IT 工厂实现中 + 6 类行业场景设计 + FactorySpec 设计** 的规模化产品。
最大增量是 M5（FactorySpec + 自举验证）→ M6（第二行业最小闭环）——**证明"同一底座可复制"后，
AI Factory 从"一个行业的工具"变成"可规模化到所有行业的平台"**。
这是 8 个产品里唯一承载"规模化"使命的产品线。
