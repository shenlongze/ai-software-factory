# 企业知识库（Enterprise Knowledge Base）— 可立项产品规格

> 版本: 0.1 (可立项) | 日期: 2026-08-24 | 状态: 经验检索已实现, 三级 RAG/知识图谱设计
> 来源: AI Factory 方案书 §8 RAG 知识检索 · §19 知识图谱 · §7.2.1 经验标签 · §2.9.1（P1）

---

## 1. 产品概述

**一句话**: 企业知识管理与检索平台——经验 + 文档 + 知识图谱三级知识，让 AI 和人都能"问到答案、用上沉淀"。

**给谁**: 知识密集企业（研发/运营/客服/咨询）

**解决什么**:
- 知识散落（文档/经验/聊天记录各自为政）
- 经验不沉淀（做过的坑下次还踩）
- AI 检索不可信（无来源标注/跨项目混淆）

**价值主张**: "把企业的隐性经验变成可检索、有来源、防幻觉的知识资产"。

## 2. 背景与机会

- **痛点**: 企业知识 80% 是隐性经验（没文档化）；通用 RAG 检索无来源标注（AI 幻觉）
- **机会**: RAG 是企业 AI 落地最刚需的底座；"经验级知识 + 来源标注"是差异化
- **竞品对照**: LlamaIndex（文档 RAG 强, 无经验/治理）· Notion AI（知识库弱 RAG）· 本产品差异 = **经验五维标签 + 跨项目共享不混淆 + 三级知识（经验/文档/图谱）**
- **战略地位**: P1——记忆底座（AI Factory 的学习层 + 独立企业知识库双形态）

## 3. 目标用户与场景

| 用户 | 场景 | 价值 |
|---|---|---|
| 研发团队 | "这个报错之前怎么解决的" | 经验检索（来源标注） |
| 运营/客服 | "客户常见问题的标准答案" | 文档 RAG |
| 知识管理 | "公司知识资产在哪/质量如何" | 知识图谱 + 统计 |

## 5. 端到端用户流程

```
1. 知识入库: 经验自动沉淀（任务完成→提取→五维标签）· 文档上传切分
2. 检索: 用户/AI 提问 → 按标签上下文匹配 → 来源标注（哪个项目/哪份文档）
3. 防幻觉: 事实区（本项目）+ 参考区（跨项目, 标注来源）分离
4. 升级: 数据体量上来 → 档1(纯) → 档2(+DB) → 档3(+RAG) → 档4(RAG+DB) 无痛
5. 图谱（P2）: 知识关系可视化 + 规则库
```

## 6. 技术架构（复用 AI Factory，不重造）

```
企业知识库
  ├─ ExperienceStore（experience_store.py ✅）
  ├─ 检索（retrieval.py: search/similar_projects ✅）
  ├─ 五维标签（§7.2.1 设计 📐 → P1 实现）
  ├─ 文档 RAG（§8 设计 📐 → P1）
  ├─ 四档配置（§8.5 设计 📐 → P1）
  ├─ 知识图谱（§19 设计 📐 → P2）
  └─ 所有权: 自建（AI Factory 存储）vs 外挂（企业 BYO, §8.5.6）
统一契约: 经验记录 schema · 标签枚举 · 来源字段 · E4xx
```

## 7. 验收标准（可立项门槛）

```
1. 一条经验入库 → 检索命中（按项目/类型过滤）
2. 跨项目检索 → 来源标注（哪个项目）+ 事实/参考分离
3. 四档升级: 档1→档4 数据不迁移（§8.5.4 无痛升级断言）
4. 外挂接入: 企业 Postgres/向量库 BYO 可用
5. 全量回归 0 新增 + git clean
```
