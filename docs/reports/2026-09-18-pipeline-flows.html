4跨环依赖（谁挡住谁）

这一层决定"改一环会不会牵动别环"。
环依赖谁被谁依赖断链风险
① 会话—②（消息是理解输入）低
② 需求① · LLM 口③（事实→PRD）中（LLM 口断则降级 CLARIFY）

④ 架构③ 的 PRD 语义 · LLM ×3 · org 存储⑤（design.task_breakdown 是种子）高（双输入缺失则无法生成）
⑤ 拆解④ 的 design 产物⑥（叶任务 + 拓扑序）高（无 design 则拒绝）
⑥ 执行⑤ 的任务 · 真实仓库 · LLM⑦⑧（执行记录是数据源）中（缺仓库则报错, 不静默）
⑦ 监控⑥ 的执行记录 + 事件—低（无数据则显示 0, 诚实标注）
⑧ 运维数据根—低

学到的标准
  • 资源做名词：tool · mcp · skills · agents
  • 操作做动词：list / show / run / scan / test
  • help 每行说清"能干什么"（不重复名字）
  • 常用给别名（rm/ls）· 顶层一句总述
本仓落地（实测输出）

  • factory mcp {scan,list,test} → 扫到 2 个 MCP
  • factory discover [all|ai-clis|mcp|projects] → 扫到 6 项
  • help 形如：list 列出工具 (可按阶段过滤)
本轮修的一个隐蔽断链：plugins/tools/adapters.py 有 7 处 import 指向已删模块 （plugins/session/* ×5 · plugins/backup.py · plugins/monitor.py）， 导致 7 个工具里 6 个一调用就 ModuleNotFoundError —— 也就是 agent 的工具面是坏的。
