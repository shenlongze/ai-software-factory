## 二、发现的问题（按严重度）

### [F1 · 严重] 新根里「招人 ≠ 进调度池」⇒ 任务树永远跑不动 ✗
- 现象：`confirm` 之后 `run` 恒为「就绪叶为空: unresolved」，**不说原因** ✗
- 真因（读代码 + 复现）：
  - 调度器的候选池 = **`<root>/agents/agents.json`**（或 `org/agents.json`）
    （`bootstrap/scheduler_wiring.py:187`），匹配依据 = 成员的 `role`/`skills`
  - 而 `factory org employee hire` 写的是 **org 数据空间的 employees**（另一个文件 ✗）
  - ⇒ 新根里 `agents.json` 不存在 ⇒ 候选 0 人 ⇒ 每个叶都判 `unresolved`
    （`scheduler_wiring.py:251`：`status="resolved" if matches else "unresolved"`）
- 影响：**冷启动用户按提示招了人，树照样不动** ✗ —— 这是产品自身的链路断点，不是场景问题
- 待你定（两种修法，涉及两套账本 ⇒ 我不自己拍 ✗）：
  1) 调度器的候选池**同时读** org 员工（桥接 ✓ 改动小 ✓ 但两处来源要定谁是权威）
  2) `hire` 同时把成员写进 `agents.json`（口径统一 ✓ 但要定 agents.json 是否退役）

### [F2 · 严重] 招某些角色直接崩 ✗
- 复现：`factory org employee hire --company <C> --role devops --capabilities devops`
  ⇒ `error: AttributeError: 'builtin_function_or_method' object has no attribute 'roles'`
- 实测：`developer` / `tester` ✓ 成功；**`devops` / `architect` / `writer` ✗ 全崩**
- 影响：树里有 devops 4 / architect 1 / writer 1 个叶 ⇒ 这些叶**永远没人能干** ✗

### [F3 · 中] chain 结尾给了个**假地址** ✗
- 现象：跑完提示「浏览器: http://127.0.0.1:8787/」—— **没有任何服务在监听 8787** ✗
- 影响：用户会去点，然后以为产品坏了 ✗（你现在要的观感是"能看"，那就该指向真能开的东西 ✓）

### [F4 · 低] 「定位」那行文案含糊 ✗
- 现象：先打「· ① 定位 未给 --conversation（定位落在会话上, 无会话则跳过）」紧接着又
  「✔ ① 定位 新项目（补做）」⇒ 同一环出现"跳过"和"补做"两条，读者不知道到底做了没

### [F5 · 提示] 粒度判据在工作 ✓
- 4/70 个叶被标「可能没拆到位」（验收分 2 段）⇒ 这是**好的**（判据 + 人可改的路径都给了 ✓）

### [F6 · 低] 登记表里有不存在的命令 ✗
- `factory doctor` 报「没有这个命令」，但 CLI 注册表（`apps/cli/registry.py`）把它登记在 platform 域
- ⇒ 登记表与现实不符（R23 只查了"命令必须登记"，没查"登记必须存在" ⇒ 可加一条 ✓）
