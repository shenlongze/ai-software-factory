# v0.2 Feedback Loop

> 位置: docs/roadmap/v0.2-feedback-loop.md | Sprint: S10-046 | 用户反馈 → 迭代闭环
> 目标: 让种子用户反馈直接驱动 v0.2 优先级

---

## 1. 闭环流程

```
用户反馈 (Issue/问卷/访谈)
    ↓
Issue 收集 (GitHub Issues + label)
    ↓
优先级评估 (每周, 基于影响×频率)
    ↓
Sprint 排期 (v0.2 backlog)
    ↓
实现 + 回归
    ↓
发布 + 反馈确认 (是否解决?)
    ↓
(回到顶部 — 持续迭代)
```

## 2. 反馈入口

| 入口 | 用途 | 链接 |
|---|---|---|
| GitHub Issue: bug | 缺陷报告 | templates/bug_report.md |
| GitHub Issue: question | 使用疑问 | templates/question.md |
| GitHub Issue: feature | 功能建议 | templates/feature_request.md |
| 结构化问卷 | seed-user-feedback 模板 | docs/community/seed-user-feedback.md |
| 访谈 | 深访 3-5 名种子用户 | 手动 |

## 3. Issue 标签体系

| 标签 | 含义 | 处理 |
|---|---|---|
| bug | 缺陷 | P1 修复(影响使用者) |
| question | 疑问 | 文档/支持 |
| feature | 功能 | 进 backlog |
| feedback | 体验反馈 | 进优先级评估 |
| good-first-issue | 新手任务 | 社区贡献 |

## 4. 优先级评估模型

```
优先级 = 影响(受影响的用户数) × 频率(遇到次数) × 价值(对产品定位)

P0: 阻塞使用 (不修没人用)
P1: 核心价值 (修了更多人用)
P2: 体验优化 (用了更爽)
P3: 远期 (先记录)
```

## 5. 每周节奏

| 日 | 动作 |
|---|---|
| 周一 | 收集上周 Issue, 更新 backlog |
| 周三 | 优先级评估 + v0.2 Sprint 排期 |
| 周五 | 发布进展 + 回复反馈者 |

## 6. 反馈 → 行动示例

| 反馈信号 | 行动 |
|---|---|
| "安装失败" | 修 setup.sh / 文档 |
| "失败看不懂" | 错误信息优化(已做) |
| "想要 diff 预览" | v0.2 CLI 增强 |
| "想要 UI" | v0.2 UI Console |
| "想要团队协作" | 组织域增强 |
| "愿意付费" | Enterprise 方向 |

## 7. 指标

```
反馈响应时间: < 48h
Issue 关闭率: 每周 > 50%
反馈 → 实现: 80% 的 P1 反馈在 2 个 Sprint 内实现
种子用户留存: 60%+ 愿意继续用
```
