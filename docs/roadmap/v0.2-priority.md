| 优先 | 项 | 理由 |

## 4. 排序逻辑

```
发布前提(P0): 转公开 + PyPI — 决定"能不能被用"
价值增强(P1): CLI diff + UI + Evaluation — 决定"用起来爽不爽"
远期(P2): RAG + Governance + Marketplace — 决定"能做多大"
```

**原则: 先让 100 个用户用起来(前提), 再让他们爽(CLI/UI), 再扩能力(RAG/治理)。**

## 5. v0.2 建议 Scope

```
v0.2 聚焦:
  1. PyPI 发布 (前提)
  2. CLI: diff 预览 + run --wait + run --json (F)
  3. UI Console 基础: 执行触发 + 结果查看 (A 起步)
  4. 种子用户验证 + 反馈闭环

v0.3 承接:
  Project RAG (B) + Evaluation 深化 (E) + Memory
```

## 6. 结论

**v0.2 优先级: P0 发布前提(转公开/PyPI) > P1 CLI diff/UI/Evaluation > P2 RAG/Governance/Marketplace。**

- 核心: 让用户"用起来 + 用得爽"(CLI/UI), 再扩能力(RAG/治理)
- 验证驱动: 每个 P1 项都以种子用户反馈为验收
