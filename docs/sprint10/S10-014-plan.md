# 1. Sprint Goal

## 1.1 为什么现在进入 Frontend Foundation

```
问题: 后端能力存在 (Idea→Lifecycle→Discovery→PRD→Backlog→Sprint→Task→Scheduler→
      Workflow Instance→Capability Binding→Runtime→Audit 全链路已可运行),
      但用户不可见 — 只有 CLI + Human Console (专家只读控制台)。

目标: 建立 AI Factory 产品前端基础框架 — 让普通用户 (CEO/产品负责人) 打开浏览器
      就能看到"我的 AI 软件团队正在帮我生产软件"。

本 Sprint 不开发完整业务功能, 只打地基:
  ✅ 前端工程基座 (路由/状态/API 层/设计系统/Shell)
  ✅ 两级信息架构 (Workspace Shell + Project Shell)
  ✅ P0 页面的基础骨架 (可渲染, 数据走 Mock/聚合)
  ❌ 完整业务交互 (进入 S10-015+)
```

## 1.2 定位差异 (对比现状)

```
现状 Human Console (S9, 保留):     目标 AI Factory Operating Interface (S10-014+):
  ├ 专家/只读控制台                   ├ CEO/产品负责人操作台
  ├ 术语密集 (Workflow/Artifact/      ├ 人话 (员工/进度/风险/下一步)
  │  Gate/Decision)                  │
  ├ 技术监控视角                      ├ 产品生产视角
  └ 保留为 Expert 模式入口            └ 新 Shell 为默认入口 (普通用户)

不删除现有 console — 新 Shell 独立演进, Expert 模式保留 (ModeToggle 已有)
```

## 1.3 Sprint 成功标准

```
1. 前端项目可启动 (npm run dev, 5173)
```

## 2.4 状态管理

```
分层:
  UI 状态   (AppState Context): 当前路由/选中项目/侧栏折叠/主题模式 (已有, 演进)
  服务端状态 (useAsync + api):  每页面独立加载, loading/error/data 三态 (已有模式)
  域状态    (Domain Store):     project 上下文 (当前项目 id → 各页共享) (新增轻量 Context)

原则:
  - 不引入 Redux/MobX (状态量小, Context + hook 足够)
  - 页面数据全部走 API/Mock 层, 组件不直接 fetch (单一数据源)
  - 只读投影 (S10-013 §8 / dashboard-design 原则): 页面不伪造状态
```

## 2.5 API Layer + Domain Adapter

```
API Layer (已有 api/client.ts): 薄 HTTP 封装 (fetch + JSON + 错误归一)
  → 扩展: 封装全部 59 路由 (按域分组: projects/tasks/workflow/runtime/capability)

Domain Adapter (新增 api/domain.ts): 后端 JSON → Frontend Domain Model 转换
  职责:
    - 字段映射 (后端 snake_case → 前端 domain 字段)
    - 派生计算 (完成度/状态人话/耗时/风险)
    - 聚合 (Todo Tree 从 backlog+runtime 投影)
    - 降级 (后端字段缺失 → 默认值, 不崩溃)

数据流:
  Component → Domain Hook (useTodoTree) → Domain Adapter → API Layer → FastAPI (8011)
                              ← Domain Model ← 转换 ← JSON
```

## 2.6 Component Architecture

```
层级 (自下而上):
  ds/ (Design System): 无业务知识的通用组件 (Button/Card/StatusBadge/Timeline)
    ↑
  af/ (AI Factory 组件): 有业务语义的组合组件 (AgentCard/TodoTree/WorkflowPipeline)
    ↑
  pages/ (页面): 组合 af 组件 + 数据 hook
    ↑
  shell/ (壳): 布局 + 导航 (WorkspaceShell/ProjectShell)

原则:
  - ds 组件不 import api/models (纯 UI)
  - af 组件可 import models (domain types), 不直接 fetch
  - pages 负责数据获取 (useAsync + domain hook)
  - 组件 props 用 domain model 而非后端原始 JSON
```

## 4.2 设计令牌 (Design Tokens)

```
颜色 (深色主):
  背景:   深空 #0F1115 / 面板 #161A22 / 卡片 #1D232E
  主色:   科技蓝 #4C8DFF (动作/链接/焦点)
  成功:   青绿 #22C55E

其他: 间距 4/8/12/16/24/32 (8pt) | 圆角 卡片12/按钮8/标签6 | 字号 20/16/14/12
```

## 4.4 动效与反馈

```
- 状态变化: 颜色过渡 150ms (不闪烁)
- 执行中: 呼吸动画 (透明度 0.6→1, 1.2s)
- 完成: 轻量勾选动画 200ms
- 错误: 红描边 + 轻震 (仅错误)
- 实时更新: SSE 增量, 不整页刷新
- 无障碍: 对比度 ≥4.5:1; 状态不只靠颜色 (色点+图标+文字); 键盘导航
```

# 5. MVP 页面拆解

## 5.1 Dashboard (Workspace 首页)

```
区块:
  我的项目      项目卡片网格: 名称/生命周期徽标/完成度进度条/待审数/风险数
  项目状态      生命周期阶段徽标 (草稿/探索/定义/开发/发布/维护)
  当前 AI 员工  正在执行的 Agent + 任务 + 耗时 [查看]
  最近活动      事件流 (最新 N 条): 时间/执行者/动作/结果
  待确认事项    审批门待办列表 (PRD/设计/发布) [去审核]
  风险提醒      延迟/阻塞/失败列表 ⚠ [查看]
MVP 范围: 数据走 /api/dashboard + /api/projects 真实接口; 空态引导 (无项目 → 想法输入框)
```

## 5.2 Todo Tree ⭐ (最高优先级)

```
结构 (S10-013 §4.2):
  Project → Phase (阶段) → Module (模块) → Task (任务)
  例: ScorePocket → 开发阶段 → Backend/用户系统 → API 开发

Task 展示 (每叶子节点 + Context Panel):
  状态 / Agent (AI 员工) / 当前负责人 / 开始时间 / 完成时间 / 下一步 / 阻塞原因

MVP 范围:
  ✅ 树渲染 (阶段→模块→任务, 状态色点 + 完成度%)
  ✅ 展开/折叠
  ✅ 状态过滤 ([全部][执行中][阻塞][待审核][失败])
  ✅ 节点点击 → Context Panel (任务详情字段)
  ✅ 完成度聚合 (节点 = 子节点加权)
  ⏳ 完整交互 (手动执行/暂停/重试/拖拽) → S10-015
  ⏳ 实时 SSE 刷新 → S10-015 (MVP 轮询或静态)

数据: Domain Adapter 聚合 (backlog + runtime + workflow 状态) — 后端无专用 todo-tree API 时
     前端 Adapter 从既有接口投影 (映射: backlog/epic→阶段, feature→模块, task→任务,
     runtime 状态→状态色, workflow stage→Agent)
```

## 5.3 Workflow Viewer

```
展示 (S10-013 §5.1):
  需求分析 → 产品经理 Agent → 架构 Agent → 开发 Agent → 测试 Agent → 发布 Agent
```

```
                     status, statusLabel, progress, agent?, owner?, startedAt?, completedAt?,
                     nextAction?, blockedReason?, children: [] }
  WorkflowPipeline:  { templateId, templateName, stages: [WorkflowStage] }

  RuntimeActivity:   { time, actor, action, result, projectName? }
  TaskDetail:        { id, title, status, statusLabel, agent?, owner?, startedAt?, completedAt?,
                     nextAction?, blockedReason?, history: [Activity], artifacts: [] }
  AgentSummary:      { id, name, role, status, skills: [], version, successRate?, avgDuration? }
```

## 6.2 映射表 (后端 API → Frontend Domain)

| Frontend Domain | 后端 API (已有, 不改) | 转换 (Adapter) |
|---|---|---|
| WorkspaceProject | GET /api/projects + GET /api/dashboard | lifecycle_stage → label; progress; pending_approvals |
| Project Detail | GET /api/projects/{id} + /lifecycle + /run-status | 状态聚合 → Overview |
| TodoTree | GET /api/projects/{id}/backlog + /workflow + /timeline | epic→phase, feature→module, task→task; runtime 状态→色; 完成度聚合 |
| WorkflowPipeline | GET /api/projects/{id}/workflow + /api/workflows/{id}/stages | stage + status + agent |
| TaskDetail | GET /api/projects/{id}/backlog/task/{task_id} + timeline | task 字段 + history 投影 |
| RuntimeActivity | GET /api/projects/{id}/timeline + /api/events/stream | 事件 → 活动条目 |
| AgentSummary | GET /api/workflows (agents 引用) + registry 门面 (S10-012) | agent 实体 → 卡片 |
| CapabilityList | S10-012 六 Registry 门面 (get_capability/list_capabilities) | 实体 → 员工/技能/工具/流程/模型 |
| AuditEntries | audit list API (S10-011) | 审计条目 → 列表 |
| Providers/Settings | GET /api/providers | LLM 配置列表 |

## 6.3 映射原则

```
1. 不改后端: 前端 Adapter 只读消费已有 59 路由 + Registry 门面
2. 缺失降级: 后端字段缺失/接口未就绪 → domain 默认值 (空列表/None/未知), 不崩溃
3. 聚合在前端: Todo Tree / Dashboard 聚合由 Domain Adapter 完成 (后端不新增聚合 API)
4. Mock 先行: 开发期用 mock/projects.ts 提供示例数据 (结构=domain model), 后端可用后切换
```
