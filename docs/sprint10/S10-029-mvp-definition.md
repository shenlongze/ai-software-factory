# S10-029 Task 3 — MVP 产品定义

> 日期:2026-08-14 | Sprint: S10-029 Product Validation | 产品决策,未修改代码
> 问题:如果只能做一个月,必须保留什么?删除什么?

---

## 1. 决策框架

一个月 = 4 周,单人(当前现实)。目标:交付一个**可对外演示、可让陌生用户跑通、能验证核心价值**的 MVP。

原则:
- 保留 = 支撑核心价值闭环 + 发布必需
- 删除 = 锦上添花 / 需要大量工作 / 非验证必需

## 2. 必须保留(核心价值闭环)

### 2.1 核心闭环(第 1 周)

| 保留 | 理由 | 现状 |
|---|---|---|
| LLM 真实执行链 | **产品灵魂** — "AI 真的在写软件" | ✅ 已实现(S10-023) |
| Router 五层决策 | 多模型优化价值 | ✅ 已实现(S10-024) |
| ControlPlane/ModelCatalog | 配置/模型管理基础 | ✅ 已实现 |
| 审批门 | 治理差异化,企业卖点 | ✅ 已实现 |

### 2.2 发布必需(第 2 周)

| 保留 | 理由 | 现状 |
|---|---|---|
| CLI 入口(init/doctor/config/start) | 用户唯一入口 | ✅ 已实现(S10-026) |
| setup.sh 安装 | 可安装 | ✅ 已实现 |
| **发布分发**(PyPI/tarball) | **陌生人能装** — 当前最大缺口 | ❌ 需做 |
| README 四步指引 | 用户能上手 | ⚠️ 需更新 |
| 示例项目 demo | 演示价值 | ✅ 已实现(demo workspace) |

### 2.3 验证必需(第 3 周)

| 保留 | 理由 | 现状 |
|---|---|---|
| 3 个可演示场景 | 一句话建产品 / 自动开发 / 成本优化 | ✅ 已实现 |
| 3 分钟演示视频 | 获客/融资素材 | ❌ 需制作 |
| 技术博客(治理为何重要) | 内容获客 | ❌ 需撰写 |

## 3. 必须删除(不做)

| 删除 | 理由 |
|---|---|
| 前端 UI 增强(执行触发/配置页) | CLI 已够用;UI 是大工作量,非 MVP 必需 |
| RAG Engine | 未实现,远期;1 个月做不完 |
| Evaluation Platform 独立化 | 散落功能够用;独立化非 MVP 必需 |
| Multi Agent 协作 | 编排未实现;单 Agent 已演示核心 |
| Governance 策略引擎 | 硬编码权限够 MVP;策略引擎是产品化后置 |
| Marketplace/插件系统 | 远期 |
| 智能路由(Phase 5) | Router 五层已够;usage 学习是增强 |
| Docker/企业部署 | 企业版后置;MVP 面向开发者/创业团队 |
| API 认证 | 单机 MVP 可接受 localhost(记录风险)|
| 桌面安装器/Cloud | 远期 |

## 4. MVP 一个月排期

```
Week 1 (核心闭环): 验证现有 5 场景可演示 + 修复阻塞
  - 全量回归 8116 保持绿
  - 修复已知 P1 (如 config exit code 文档化)
  - 端到端冒烟: init → start → 执行真实任务

Week 2 (发布): 打通分发
  - PyPI 打包 (console scripts + 前端 dist) 或 release tarball
  - README 四步指引 + LLM key 配置说明
  - factory version 命令
  - 仓库公开或 release 发布

Week 3 (验证): 内容 + 反馈
  - 3 分钟演示视频
  - 技术博客 2 篇 (治理/真实执行)
  - 邀请 5-10 名种子用户试用 (开发者/创业团队)
  - 收集反馈 → 验证场景 1/3/4

Week 4 (打磨): 反馈迭代
  - 修种子用户反馈的阻塞
  - demo 体验打磨
  - 发布 v0.2 (第一个公开版本)
```

## 5. MVP 成功标准(可验证)

| 指标 | 目标 |
|---|---|
| 陌生用户安装成功 | ≥ 80%(10 名种子用户中 8 名能装能跑) |
| 核心场景演示成功 | 3/3(一句话建产品/自动开发/成本优化) |
| 种子用户反馈 | ≥ 5 名明确表示"想继续用" |
| 测试基线 | 8116 保持全绿(发布前) |
| 发布 | v0.2 公开(PyPI 或 release) |

## 6. MVP 定位一句话

**AI Software Factory MVP = 治理驱动的 AI 软件生产 CLI:让开发者/创业团队用可审计、可验证、多模型优化的人工智能员工开发软件。**

## 7. MVP 边界(明确不做)

```
✅ IN:    CLI + 真实执行 + Router + 审批 + 安装分发 + 演示
❌ OUT:   UI 增强 / RAG / MultiAgent / 智能路由 / 策略引擎 / Docker / 认证 / 市场
```

**判断:现有 80% 已完成;MVP = 补分发 + 验证 + 内容,而非新开发。**
