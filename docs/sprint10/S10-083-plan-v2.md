# S10-083 Real Execution & Observability Foundation — 重新规划

> 日期: 2026-08-19 | 待确认 | 目标: 透明、可审计、可控制的软件生产系统

---

## 1. 当前真实能力总结

**数据层已有(复用基础)**:
- AuditEvent: 20+ 字段 (trace/actor/event_type/action/timestamp/decision/evidence/approval/parent_event/artifact_reference)
- exec events: record_execution_started/completed/failed (agent_id/duration/artifact_count)
- ExecutionResult.usage: input_tokens/output_tokens/estimated_cost + artifacts + duration
- 33+ 审计事件类型 + 决策链查询 (S10-069)

**缺的**:
- 用户可见执行历史/timeline (CLI/API 查询层)
- 进行中进度展示 (黑屏)
- patch → 项目落地 (Delivery)
- 事件 ↔ 资产血缘 (Lineage 预留)

## 2. S10-083 重新定位

**Real Execution & Observability Foundation**:
一次真实用户操作,从输入到执行到结果,**全过程可见、可追踪、可验证**。

## 4. P0/P1/P2 拆分

| P | 项 | 交付 |
|---|---|---|
| **P0** | Patch Delivery | patch 白名单过滤 → apply 回项目 → 真实文件 → 0 文件 FAILED |
| **P0** | Execution Timeline | CLI `factory exec history` + 进行中状态; API timeline |
| **P1** | Project Status View | 阶段/Agent/事件/资产/测试摘要 (CLI + API) |
| **P1** | Artifact Lineage 预留 | 事件 → artifact_reference + parent_event 完善 (模型已支持) |
| **P2** | 快照/回滚 | (预留, S10-085) |

## 5. 架构设计

```
任务执行 (orchestrator):
  Task → execute_task → LLM → patch
  → ArtifactBoundary 过滤 (剥离状态文件)
  → patch apply 回项目目录 (approval.apply 接线)
  → 合并后真实 pytest
  → 0 代码文件 → FAILED
  → 每步 emit Execution Event

Observability:
  已有事件 (audit + exec) → TimelineService 聚合
  → CLI: factory exec history / factory project status
  → API: GET /api/projects/{id}/timeline
```

## 6. 数据模型设计

- 复用 AuditEvent (20+ 字段已覆盖); 新增 event_type: PATCH_APPLIED/CODE_VALIDATED/DELIVERY_COMPLETED
- ExecutionResult.usage 已有 token/cost → Timeline 直接读
- execution_state.json task 增加: applied(bool) + code_files(list)
- Lineage 预留: artifact_reference + parent_event_id 已有字段, S10-084 多角色资产接上即可

## 7. CLI/API 设计

| 能力 | CLI | API |
|---|---|---|

| 项目状态 | `factory project status [--project X]` | GET /api/projects/{id}/status |
| 当前执行进度 | `factory exec status` | GET /api/execution/current |
| Delivery | 内部 (继续开发 闭环) | 内部 |
