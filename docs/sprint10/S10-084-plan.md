## 3. S10-084 定位

**Product Intelligence Pipeline**：用户想法进入后，由一组专业角色（Agent Team）依次真实产出
**版本化 Artifact**，每个产出同时落 **Audit Event**（血缘自动接上 S10-083），关键节点走
**审批门**，最终交付可确认的 PRD 与工程入口。

```
用户想法
  ↓
Discovery（现有）→ ProductIntent
  ↓
ProductPipeline（新增 orchestrator）
  ├── PM Agent        → product.md          (产品定位/用户价值/功能范围/非目标/商业模式)
  ├── Market Agent    → market_analysis.md   (市场规模/趋势/机会 —— 复用 MarketAnalysis)
  ├── Competitive     → competitive_analysis.md (直接/间接/替代 + 机会点 —— 复用 CompetitorAnalysis)
  ├── UX Agent        → ux_flow.md           (用户流程/信息架构/页面结构)
  ├── Architect       → architecture.md      (技术选型/系统设计/数据模型/风险)
  ├── QA Agent        → test_plan.md         (单元/集成/安全/性能测试方案)
  └── Senior PM       → PRD.md               (LLM 深度 PRD，替代模板拼接)
  ↓
每角色产出 = Artifact（版本化）+ Event（血缘）
  ↓
审批门：Discovery ✅ → PRD ✅ → Architecture（recommended）
  ↓
用户确认 → create_product（现有）→ prepare_project（现有）→ 执行（S10-083 底座）
```

## 4. 需求变更与渐进明细（核心闭环）

> 用户点: PRD 形成后执行中需求可能变更，需要应对机制；需求获取/开发中存在渐进明细过程。
> 现状: 任务级重规划已有（S10-060 ReplanningEngine 8 决策 + plan_version），
> **需求级回流没有** —— 变更不写回需求资产，只在任务图打补丁（悄悄改）。

### 4.1 原则

需求不是一次成型。三个阶段都会「越聊越细」，且变化必须**受控回流**到需求资产：

```
渐进明细 (Progressive Elaboration):
  Discovery 明细化: 想法 → 问题/用户/场景 → 初步需求/风险 (discovery.md v1..n)
  PRD 明细化:     discovery → 用户故事 → 功能需求(优先级) → 验收标准 (prd.md v1..n)
  执行明细化:     任务执行发现歧义/缺口 → 澄清写回需求资产 (prd.md v+1) → 任务重规划

变更回流 (Change Control):
  变更来源 → 影响分析 → 审批 → 资产版本+1 + 任务图更新 → 继续执行 (血缘链完整)
```

### 4.2 变更来源（触发）

| 来源 | 示例 | 复用检测 |
|---|---|---|
| 用户反馈 | "加个导出功能" | Feedback Artifact（Operating Model Phase 15）+ ReviewGate |
| 执行缺口 | QA 发现 "缺持久化" | GapAnalyzer（S10-060） |
| 任务失败歧义 | 验收标准不清导致 FAILED | quality/repair + ReplanningEngine |
| 计划批判 | PlanCritic 指出范围不合理 | plan_critic（已有） |

### 4.3 变更流（Requirement Change Loop）

```
ChangeProposal {source, what, why, affected_artifacts, affected_tasks}
  ↓ 影响分析 (Impact): 哪些资产版本受影响 / 插入或修改哪些任务 / 成本风险
  ↓ 审批门 (ReviewGate, 用户): approved / rejected
  ↓ Apply:
      artifact_registry → 需求资产 version+1 (discovery/prd 等, content_ref 指向新版本)
      ReplanningEngine → INSERT_TASK / MODIFY_TASK + plan_version+1 (S10-060 复用)
      AuditEvent → parent_event_id 链: 变更提议 → 批准 → 资产 v+1 → 重规划 → 继续执行
  ↓ 继续执行 (S10-083 底座)
```

### 4.4 与 S10-084 / S10-085 的关系

- **前提是 S10-084 的版本化资产 + 血缘**: 没有 artifact v+n 与 parent_event 链，
  变更就是"悄悄改"（当前真实状态）。
- S10-084 P0 交付资产版本化；**P1 增加需求变更回流**（ChangeProposal + 影响分析 +
  审批 + 资产 v+1 + ReplanningEngine）。
- 完整闭环（含快照/回滚）归 **S10-085**：PRD 深度化 + 变更审批门 + 快照/回滚。

## 5. 架构设计

```
session/pipeline_runner.py（新增，编排层，零业务复制）
  ProductPipeline:
    run(product_intent, workspace, provider) -> PipelineReport
      roles = [pm, market, competitive, ux, architect, qa, prd]
      每个 role:
        RoleRunner(role, prompt_builder, artifact_writer, event_emitter)
        → LLM 调用（复用 S10-062 ReasoningProvider；失败 → deterministic 兜底）
        → artifact.md + artifact.json（版本化 v1..n）
        → AuditEvent（event_type=PIPELINE_*，artifact_reference + parent_event_id）
    save / load / to_markdown（同 ProductIntelligenceEngine 模式）

session/artifact_registry.py（新增，资产版本化）
  artifacts/<slug>/<type>/v<n>/artifact.md + artifact.json
  {id, type, version, source(conversation_id/idea_id), created_by(role+model),
   status(draft|confirmed), content_ref, event_id, parent_event_id}

复用：
  - ProductIntent / DiscoverySession / conversation.py（入口与状态机）
  - ProductIntelligenceEngine.analyze_market / analyze_competitor（Market/Competitive 角色）
  - pipeline.py ProductDocument（PRD 结构骨架；内容由 LLM 深度化）
  - audit（AuditEmitter）+ S10-083 artifact_reference/parent_event 字段
  - api/artifacts.py（只读资产清单，已存在）
```

## 8. P0 / P1 / P2 拆分

| P | 项 | 交付 |
|---|---|---|
| **P0** | Pipeline 编排（7 角色 Runner + LLM/deterministic 双模式） | 一条命令跑通 Idea→PRD 全链 |
| **P0** | Artifact 版本化落盘（artifact_registry） | 每角色产出 md + json，版本递增 |
| **P0** | 事件血缘接入（PIPELINE_* + artifact_reference/parent_event） | 时间线/项目状态可见角色产出 |
| **P0** | discovery.md 落盘（需求整理 → Artifact） | "整理需求" 不再只停留在聊天 |
| **P1** | LLM 深度 PRD（替代模板拼接） | PRD.md 含用户故事/功能需求(P0..)/验收标准/非功能 |
| **P1** | 审批门（Discovery/PRD mandatory，Architecture recommended） | 关键节点用户确认后推进 |
| **P1** | 需求变更回流（ChangeProposal → 影响分析 → 审批 → 资产 v+1 → ReplanningEngine） | 执行中需求变更受控写回 PRD/discovery，任务图同步 |
| **P1** | CLI/API 全链路 + 会话意图 | factory product pipeline / artifact / approve |
| **P2** | 逐句 diff 编辑（LLM 辅助修改资产） | 用户改资产 → 版本 +1（衔接 Test 5 编辑能力） |
| **P2** | 快照/回滚（衔接 S10-085） | 变更前快照，回滚到上一资产版本 |
| **P2** | 真实市场/竞品数据源（预留） | 非实时爬虫，LLM 知识 + 规则模板 |
