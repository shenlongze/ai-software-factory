# AI Factory — 下一阶段产品规划

**一份 CEO + CPO 视角的战略判断**

---

## 0. 一句话开场判断（先立结论）

**你造的是一个引擎，引擎不是产品。**

过去阶段完成的东西——Agent Runtime、Workflow、Task System、Execution Kernel、LLM Router、Real Execution、Repair Loop、Observability——本质上是一台**已经造好的发动机**。但没有人会为发动机买单，人们为「把你从 A 地送到 B 地的车」买单。

下一阶段的核心任务不是继续造引擎，而是回答一个问题：**这台引擎，能替谁、把哪件具体的活干完，并且干得让企业敢签字、能审计、越用越好。**

如果继续往下堆引擎能力，你会成为「又一个 Agent 框架」——在一个已经拥挤、且被大厂免费能力挤压的赛道里被淹没。如果往上一层做产品，你才有机会成为一个品类。

---

## 1. 市场机会

**「AI 能写代码」这件事已经商品化了，但「企业敢不敢让 AI 写、写完敢不敢上线」这件事，几乎没人做。**

- **供给已经过剩**：写代码、补全、生成的能力，Copilot / Cursor / Claude Code / 各类 Agent 已经铺满。单点「代码生成」没有溢价空间。
- **交付仍然稀缺**：从「AI 生成了一段代码」到「这段代码通过审批、有证据、可审计地进入了生产环境」，中间隔着一整套**治理、信任、责任**的空白。这才是企业真正愿意付钱的地方。
- **存量市场的浪费**：企业里大量**没人干的活**——积压的 bug、依赖升级、安全补丁、遗留系统维护、测试覆盖回填、文档——这些是 AI 当前能力恰好匹配、但现有工具（面向单人开发者）覆盖不到的「无聊但必须做」的工作。
- **监管与合规的强制力**：金融、医疗、保险、政务等领域，AI 落地不是「好不好用」而是「敢不敢用」。谁能提供审计证据链，谁就拿到入场券——而这块门槛高、付费意愿强、竞争少。

**一句话市场机会**：把「AI 生成代码」升级为「**有治理、有证据、可审计的 AI 软件交付**」，切的是企业里「没被做的存量工作」+「不敢做的合规工作」这两块没人碰的市场。

## 2. 用户痛点（按角色拆）

| 角色 | 痛点 |
|---|---|
| **CTO / VP Engineering**（付钱的人） | 董事会要求「上 AI」，但买了工具测不出 ROI；开发者各自在用黑盒 AI，团队失控；不敢把 AI 放进核心代码库 |
| **技术负责人 / Platform Lead**（推动的人） | 想把 AI 用在真实仓库，但现有工具只服务单人键盘输入，没有「团队级、可审批、可追溯」的工作流 |
| **资深工程师**（被说服的人） | 不信 AI 的输出（没有证据）；怕 AI 制造技术债；审批要花更多时间，不如自己写 |
| **合规 / 安全负责人**（一票否决的人） | AI 是否碰了敏感数据？变更是否可审计？谁为 AI 的代码负责？现有工具给不出答案 |
| **企业经营者** | 开发者流失 + AI 工具 = **组织知识持续蒸发**，新人接不住老系统 |

**贯穿所有角色的元痛点**：**AI 是个黑盒。** 它要么太快（不可控），要么太慢（鸡肋）。企业要的不是「更聪明的 AI」，而是「**能把 AI 当一名可管理、可问责、越用越懂自家系统的员工来用的机制**」。

## 3. 竞争产品（诚实盘点）

| 类别 | 代表 | 它们的打法 | 我们的空隙 |
|---|---|---|---|
| **代码助手（单人）** | GitHub Copilot、Cursor | 键盘级提效，按人头收费 | 它们服务「个人敲代码」，不服务「团队交付」 |
| **自主工程师 Agent** | Devin (Cognition)、Factory 等 | 追求「全自动」，主打「AI 员工」叙事 | 全自动 = 无治理，企业不敢用；且信任问题未解决 |
| **大厂 Agentic Coding** | Claude Code、Gemini Code Assist、Codex | 免费/低价铺量，绑定自家模型生态 | 它们是「能力」，不是「操作系统」；不做治理与记忆 |
| **企业 DevOps 平台** | GitHub、GitLab、Jira 生态 | 已经占据工作流入口 | 它们缺「AI 员工」这一层；我们做**插件进它们**，而不是对抗 |
| **Agent 框架/平台** | LangGraph、各类编排工具 | 给开发者搭积木 | 框架卖给「想造引擎的人」，不卖给「想要结果的企业」 |

**关键判断**：正面和 Copilot/Cursor/Devin 打「谁更会写代码」是死路。我们要打的仗是**「谁能让企业敢把 AI 放进生产、并证明它值得」**——这是治理与信任层，目前是真空地带。同时，**不要试图取代 GitHub/Jira，要做进它们的生态里**，成为「AI 员工」这一层。

## 4. AI Factory 差异化优势

你们已有的四大原则，恰好精准命中上述真空，这是别人抄不动的组合：

1. **Human in the Loop** —— 不是「缺陷」，是**卖点**。企业要的就是人说了算。把「人在环」做成产品（审批流、角色、门槛），而不是把它当作「AI 还不够好」的过渡。
2. **Evidence Driven** —— 最锋利的差异化。**每一个 AI 动作都产出人类可读的证据包**（diff + 测试 + 日志 + 依据引用），让「不信 AI 的资深工程师」和「一票否决的合规官」都能被说服。这是黑盒 Agent 给不了的。
3. **Experience Accumulation** —— 最深的护城河。AI 工具都是无状态的，用完即忘。让 AI 在每一次审批、每一次纠正中**积累你这家公司的知识**，它就在你的系统上越用越准——**客户越用越离不开，因为知识长在系统里**（且客户拥有并导出这些知识）。
4. **Safety Governance** —— 进入受监管行业的门票，也是别人懒得做的脏活。

**一句话差异化**：别人卖「更聪明的 AI 工人」，我们卖「**可管理、可问责、会积累、可审计的 AI 员工组织**」。

## 5. 下一阶段必须建设的能力（产品视角，不是代码视角）

按「先建立信任 → 再交付价值 → 再形成护城河」的顺序：

1. **证据包系统（Evidence Bundle）** —— 每个 AI 产出附带可读证据：改了什么、为什么、测试结果、日志、引用了哪条历史经验。**这是全产品的信任地基。**
2. **人工审批工作流** —— 按角色（开发者 → 技术负责人 → 合规官）、按爆炸半径（改动影响范围）分级的审批闸门 + 超时升级 + 一键否决。
3. **组织知识库（Org Memory）** —— 审批决策、纠正、代码约定、架构禁忌沉淀为可检索、可携带的记忆，成为「公司自己的 AI 大脑」。
4. **域工作负载包（Workload Packs）** —— 预置的、有证据模板的可售卖任务：积压 bug 清道夫、依赖升级、测试覆盖回填、安全补丁、遗留迁移、文档补齐。**这才是用户真正购买的东西。**
5. **深度集成层** —— GitHub/GitLab + Jira/Linear + CI + Slack，让 AI Factory **活在现有工具链里**，而不是再造一个入口。
6. **安全治理控制** —— 权限边界、密钥/PII 防护、变更策略、按爆炸半径定审批阈值、全局急停。
7. **ROI 与价值证明面板** —— 「AI 干了多少活、质量如何、人在哪里介入过」——**这是 CTO 拿去向董事会汇报、也是销售能不能续约的东西。**
8. **信任爬坡机制（Trust Ramp）** —— 默认「只提案不落地」（只开 PR），随信任积累逐步放开到半自动。**消除企业第一次上手的恐惧。**

## 6. 哪些功能没有商业价值，应该删除 / 降级

这是最需要 CPO 冷血的部分。**引擎能力不是产品，把引擎当产品卖 = 没有买家。**

| 已完成组件 | 裁决 | 理由 |
|---|---|---|
| **Agent Runtime** | **保留为隐形基建** | 必需但不可售卖，永不对外暴露 |
| **Workflow（空白画布）** | **删除通用画布，改造为「域工作负载包」** | 没人买「通用流程编排」；有人买「升级依赖的标准流程」 |
| **Task System** | **降级为隐形基建**，并入工作队列 | 独立的任务系统没有买家 |
| **Execution Kernel** | **保留为隐形基建** | 同 Runtime |
| **LLM Router** | **降级为成本优化基建，删除其产品面** | 「模型路由」是省钱手段不是卖点，客户不关心你用哪个模型 |
| **Real Execution** | **保留，这是真正的价值** | 真实干活（真 PR、真 CI）是一切的前提，也是和 Demo 的分界线 |
| **Repair Loop** | **保留并强化，纳入证据包** | 自纠错 + 留证据是差异化，不是鸡肋 |
| **Observability（作为产品）** | **降级为内部基建；对外只卖「审计/证据/ROI 报告」** | 客户不为「观测你的 Agent」付费，客户为「审计报告」付费 |
| **Project Production Pilot** | **转化为 2–3 个具名参考案例** | 试点本身不值钱，案例是销售弹药 |

**核心原则：凡是「引擎 / 平台 / 框架」语义的功能，一律隐形；凡是「证据 / 审批 / 记忆 / 报告 / 可售卖任务」语义的功能，才是产品面。**

## 7. 用户完整体验流程

以典型客户「某 2000 人金融科技公司」为例：

1. **接入（10 分钟）**：连接 GitHub + Jira + CI，AI Factory 读取代码库与 issue 历史，建立**组织知识基线**。
2. **选择工作负载**：技术负责人勾选「积压清道夫」包，指向积压队列。
3. **AI 员工上岗**：Planner / Implementer / Reviewer / QA 四个角色自动接单。
4. **产出证据包**：每张 ticket 交付的不是「一堆代码」，而是 **diff + 测试结果 + 日志 + 决策依据** 的可读证据包。
5. **人工在环审批**：进入审批队列；低风险自动推荐、高风险强制多人签；批准 / 否决 / 修改。
6. **决策回流记忆**：每一次批准与纠正，写回组织知识库——**这是飞轮的一环**。
7. **走现有 CI 上线**：AI Factory 不碰部署，产出交给客户自己的流水线，结果可观测。
8. **领导层看报告**：CTO 看到「AI 交付量、质量、人工介入率、成本」的 ROI 面板；合规官看到完整审计链。
9. **信任爬坡**：数月后，低风险工作自动派发，人工只盯高风险。

**体验的核心感受**：不是「我用了个 AI 工具」，而是「**我多了一个团队，这个团队每次交活都带证据、等审批、还越干越懂我的系统**」。

## 8. 产品战略（一句话 + 三条支柱）

**定位**：AI Factory = **有治理的 AI 软件交付操作系统**（Governed AI Software Delivery OS）——让企业把「没人干的和不敢干的」软件工作，交给一群可管理、可问责、可审计、会积累的 AI 员工完成。

**三条战略支柱**：

- **信任优先（Land）**：先用「证据 + 审批」赢得一个团队、一个仓库的信任，而不是先吹「全自动」。
- **单点切入（Expand）**：不卖「平台」，卖**一个具体的可交付工作负载**（积压清道夫），干完一件看得见的活。
- **记忆筑城（Moat）**：让每一次交付都沉淀为组织知识，让「越用越准、越用越离不开」成为不可复制的护城河。

**战略纪律**：**不碰**「通用 AI 助手」「通用 Agent 聊天框」「通用流程画布」——这些没有差异化、没有买家。

**决策链上的关键否决者**：安全 / 合规负责人 —— 必须被「证据 + 审计 + 权限」说服。

**显性排除**：个人开发者、10 人以内极早期创业团队（他们要速度不要治理，且付不起企业价）。

## 13. Sprint 优先级

遵循「先可信 → 再交付 → 再筑城」的节奏：

| Sprint | 内容 | 为什么这个顺序 |
|---|---|---|
| **1–2** | E1 证据包 MVP | 地基。没有证据，后面全是空谈 |
| **3–4** | E2 审批工作流 | 把「人在环」产品化，这是第一个卖点 |
| **5–6** | E3 积压清道夫 + E4 最小集成 | 第一次「真实交付一个具体活」+「进真实工具链」 |
| **7–8** | E5 经验累积 v1 | 开始积累护城河，让飞轮转起来 |
| **9–10** | E6 安全治理 + E7 ROI 面板 | 解锁合规客户 + 拿到续约/成交依据 |
| **全程并行** | E8 参考案例打磨 | 边做边沉淀销售弹药，不单独占 sprint |

**核心原则：任何 sprint 内，产品面（证据/审批/记忆/报告/负载包）优先级永远高于引擎面。**

## 14. MVP 商业闭环

**目标客户**：从 Production Pilot 里选 1–2 个**受监管 / 复杂遗留系统**的中型企业，签首个付费合同。

**卖什么**：
- **一个工作负载**（「积压清道夫」：bug 分诊 + 修复 + 测试 + 证据包）
- **一套治理**（证据 + 审批 + 审计）
- **定价按「完成的 AI 工作量 / 容量」**，不按人头——因为买的是「干完的活」，不是「座位」。

**闭环怎么转起来**：
```
连接仓库 → AI 接单干活 → 产出证据包 → 人工审批 → 走 CI 合并
     ↑                                                    │
     └── 组织记忆增强 ← 纠正回流 ← 审批决策 ───────────────┘
                          ↓
        更多低风险工作被自动派发 → ROI 面板可见 → 续费 / 扩团队
```

**验证指标（决定生死的那几个）**：
- **采纳率**：积压队列里多少 ticket 真的被 AI 接走
- **证据通过率 / 人工介入率**：审批一次通过的比例，以及随时间是否下降（信任在爬坡）
- **交付速度与成本**：同样工作，AI 团队 vs 人力的对比
- **续约与扩容**：首个合同之后，是否扩到更多团队/仓库/负载包

**收入里程碑**：第一个付费客户 → 首个年度合同 → 2–3 个具名参考案例 → 用「证据 + ROI + 案例」复制到同行业下一个客户。

## 15. 给 CEO 的三句决策

1. **别再投资引擎，投资信任。** 下一阶段每一分钱都应花在「让企业敢用、能审、越用越准」，而不是花在更聪明的执行内核上。
2. **不卖平台，卖一件干完的活。** 用「积压清道夫」这一个可交付工作负载验证有人付钱，再谈「操作系统」的宏大叙事。
3. **护城河是记忆，不是模型。** 模型人人可用，组织知识长在客户系统里——这才是别人抄不走、客户离不开的东西。
