## 1. 真实 LLM 验收实录（唯一真相）

```
用户: 开始做个记账App
系统: 你希望这个记账App首先解决什么问题，比如手动记账、自动同步银行流水，还是提供预算管理？
      (为什么还问: 用户未说明要解决的痛点。)                    ← 智能追问带理由, 非机械首问
用户: 记账麻烦, 手工记容易漏, 月底对不上账
系统: 主要给谁使用?                                            ← field_answer → 既有字段逻辑 (与 conversation 同)
用户: 给个人和小商户用
系统: 核心功能有哪些? (用逗号或顿号分隔)
用户: 快速记账、分类统计、月度报表
系统: 主要在哪些场景使用?
用户: 日常消费随手记, 月底看报表
系统: 第一版范围是什么? (可不填, 默认全量)
用户: 先做记账和分类统计
系统: 有什么性能/安全/兼容性要求? (可不填)
用户: 数据本地保存, 打开快
系统(READY):
  我理解你要做一个记账App，但具体目标用户和核心功能尚未明确，需要进一步细化。   ← 理解摘要首行
  产品: 轻账本 | 问题: 记账麻烦... | 目标用户: 给个人和小商户用 | 核心功能: 快速记账,分类统计,月度报表
  使用场景: 日常消费随手记, 月底看报表 | MVP 范围: 先做记账和分类统计 | 非功能要求: 数据本地保存, 打开快
  建议名称: 轻账本
    1. 轻账本  2. 笔笔清  3. 简记流                                    ← LLM 命名候选
  主动建议: 平台=主流平台（iOS/Android/Web），建议优先移动端。· 竞品=随手记、鲨鱼记账、Money Wiz等。
           · 范围=建议MVP聚焦核心记账功能。· 备注=可考虑多端同步、自动分类、报表导出等。
  请确认产品需求 — 输入 y 确认创建 / n 重新描述 (或 /cancel 取消)
```

## 4. 诚实记录（工程资产）

- **中间字段追问是机械模板**（"主要给谁使用?"等）: 与 conversation 路径行为一致 — field_answer 分类 → 并入既有字段逻辑 → 机械模板下一问; 智能追问发生在初始理解轮和缺失检测轮。这是"两路径对齐"的设计行为, 非缺陷。若后续要求全程智能话术, 是独立增强项。
- 我的首个验收脚本断言错对象 (查 summary 而非 message) — 修正后 8/8; 教训: READY 的 LLM 增强在响应 message, 字段摘要 to_text 不含。
- Codex 沙箱 8 个环境性失败 (team_decision ~/.factory 权限 / cli_doctor socket / s10_074 wheel 网络 / m3e flaky) 在我的环境全部通过 — 环境敏感, 非代码回归。
