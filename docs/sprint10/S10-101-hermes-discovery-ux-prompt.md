【AI Factory Sprint 规格 — 产品发现引导体验（Founder 实测反馈）】

## 角色
Hermes = CTO + 架构委员会。产出可执行 Sprint 规格，不写实现代码。

## 背景（Founder 实测 v1.1.21 暴露 3 个体验缺陷）
Founder 实测 "做个记账App" 流程:
1. 首轮 LLM 智能追问 ✅（"解决什么痛点? (为什么还问: ...)"）
2. **但中间字段机械** — 用户答痛点后, "目标用户是谁? (缺失字段: user)" / "核心功能有哪些? (缺失字段: core_features)" 纯模板, 无 LLM、无"为什么还问"
3. **无进度提示** — 用户不知道在产品发现第几步/还剩几步/软件生命周期概念
4. **求助未响应** — 用户说 "简单好用, 给我点建议" / "我没有想法, 给些意见" → 系统仍机械收下/继续问, 没提供建议

## Sprint 目标（3 项）
1. **进度提示**: 每轮追问带进度（"产品定义 2/3: 问题✅ 用户✅ 核心功能待填"）
   + 生命周期引导（发现→确认→创建→PRD→工程→开发, 让用户有概念）
2. **中间字段 LLM 化**: field_answer 也走 LLM（理解回答 + 智能追问带理由）, 不只第一轮
3. **求助响应**: "给些建议/没有想法" → LLM 识别求助意图 → 提供建议（如核心功能默认推荐
   "记账/统计/导出"）→ 用户确认后填入（不是机械收下/继续问）

## 必须包含（6 项）
1. **进度模型**: 发现流程总步数（3 必填 + 增强?）+ 每轮进度展示格式 + 生命周期引导文案
2. **中间字段 LLM 化**: field_answer 路径的 analyzer 调用（含 system_question 多轮合并,
   复用 S10-099/v1.1.19 模式）+ 智能追问带理由
3. **求助意图**: LLM 分类 "ask_for_advice"（"给些建议"/"没有想法"/"你看着办"）→ 提供
   默认建议 + 用户确认填入; 规则兜底（关键词: 建议/意见/没有想法/你定）
4. **进度展示与求助响应** 的对话格式（示例: "📋 产品定义 2/3 ..." + 建议列表）
5. **无 LLM 兜底**: 现有机械追问保留（诚实降级）+ 进度提示仍加（确定性, 不依赖 LLM）
6. **向后兼容**: 既有测试零破坏（进度提示是追加, 不改变字段收集语义）

## 规格必须包含（8 项）
1. 进度/生命周期引导设计（文案/格式/步数定义）
2. 中间字段 LLM 化方案（复用 analyzer + system_question, 最小改动）
3. 求助响应设计（识别/建议内容/确认填入）
4. conversation.py + discovery.py 集成点（两路径同步: 都是 S10-100 对齐的）
5. 无 LLM 兜底（进度提示确定性 + 机械追问保留）
6. 契约测试要点: 进度显示/求助响应建议填入/中间字段智能/无LLM回退/两路径一致/向后兼容
7. Codex 写 scope
8. 边界: 不改确认门/命名/主动分析（已有）· 不做多语言

## 验收标准（Codex 完成后，你独立验证）
- "做个记账App" 全流程: 首轮智能 → 进度显示(2/3...) → 中间字段智能/带理由
- "我没有想法, 给些意见" → 系统提供核心功能建议 → 确认填入
- 无 LLM → 进度提示仍在 + 机械追问（零变化）
- 两路径（conversation + DiscoverySession）行为一致
- 全量回归 0 新增 + git clean
- 版本: 本 Sprint 完成后 bump v1.1.22

## 关键纪律
1. 代码存在 ≠ 能力；自报告 ≠ 事实 — 独立验证（真实 LLM "做个记账App" 全流程）
2. 禁止 stub/fake；无 LLM 诚实降级（进度提示确定性, 机械追问保留）
3. 复用 analyzer / system_question 模式 — 不重造
4. 向后兼容: 无 LLM 时行为零变化（除进度提示）
5. 版本: v1.1.21 → v1.1.22（patch+1）
