## 审查维度（逐项给判断 + 证据 + 建议）

1. **产品价值**: 这些功能对用户价值几何？哪些是"用户会为它付钱"的？哪些是自嗨？
2. **UX**: 产品发现/CLI/监控面板的体验——用户实测踩的坑（确认被当改名/命令被当字段/
   多轮分不清/删除不灵）是否从产品视角真解决？还有哪些 UX 硬伤？
3. **商业闭环**: SDK 化/商业化路线的进展与风险——8 个产品规格哪个最该先卖？
4. **主线 vs 周边**: 最近 20 个版本是否偏离主线（IT 工厂做透）？哪些是周边做多了？
5. **问题与风险**: 从产品视角看到的技术/体验/商业风险（诚实, 不吹捧）
6. **下一步方向**: 你认为接下来 3 个 Sprint 最该做什么（产品视角, 不是技术视角）

## 输出
- 价值评估报告（每个维度: 判断 ✅/⚠️/❌ + 证据 + 建议）
- 一句话结论: "敢不敢演示 / 值不值得继续投入 / 该往哪走"
- 建议的下一步（3 个 Sprint 优先级）

## 纪律
- 不吹捧: 基于真实交付判断, 用户实测踩的坑是最好证据
- 用户视角: 你是"敢不敢给客户演示"的判官, 不是工程赞美者
- 产品 > 技术: 关注用户价值/商业闭环/体验, 不陷入技术细节
