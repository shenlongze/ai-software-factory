## T1 完整流程 (有 LLM) — happy path

**步骤**:
1. `factory`
2. 输入: `我想做个markdown编辑器，要typora和notepad++的优点，适配手机`
3. 按追问回答 problem/user（如: `解决手机上写作排版麻烦` → `给普通用户用`）
4. 确认门显示: 理解摘要 + 产品名 + 建议名称候选 + 主动建议
5. 输入 `y` 或 `可以`

**预期**:
- [ ] 首问为 LLM 智能追问（带 "为什么还问" 理由），非机械模板
- [ ] 确认门: "我理解你要做…" 理解摘要 + AI 命名 + 主动建议
- [ ] 输出 `Product Created: <名> — Ready for Engineering.`
- [ ] 引导 "是否生成工程计划? 输入 '准备开发'"

**实测**: （记录实际输出差异）

## T2 确认+动作短语: "可以，先出prd文档"

**步骤**: T1 到确认门后，输入 `可以，先出prd文档`（不是 y）

**预期**:
- [ ] 产品创建成功（`Product Created`）
- [ ] 名称**不被覆盖**（不会变成 "可以，先出prd文档"）
- [ ] 自动生成 PRD: `已生成 PRD: .../PRD.md`
- [ ] PRD.md 落盘到**新建项目**目录（不是旧项目）

**实测**: （v1.1.47 实测 ✅ 生成到 P-e023a04c 新项目）

## T3 无 LLM 兜底

**步骤**: `env -u DEEPSEEK_API_KEY factory` → `我想做个记账App`

- [ ] 逐字段追问（problem → user → core_features）
- [ ] 无 "我理解你要做…" 摘要（诚实降级）
- [ ] 无 LLM 时全流程仍可走通（规则兜底）

## T4 字段不完整 + 确认短语 → 提示缺失

**步骤**: 只填 1 个字段，然后输入 `可以，先出prd文档` 或 `先出PRD`

**预期**:
- [ ] 输出: "产品定义还不完整，还缺 目标用户、核心功能 — 补齐后才能生成PRD文档"

- [ ] 仍在发现流程，继续问缺失字段

**实测**: （v1.1.47 修复 ✅）

## T9 ⚠️ 答非所问字段错位（已知 bug, v1.1.47 实测复现）

**步骤**: 首问问"痛点"时，用户答的是"目标用户"（如 `给大学生用`）

**实际输出** (v1.1.47 复现):
```
问题: 给大学生用          ← ❌ 应是"目标用户"
目标用户: 支持扫码记账和月度报表  ← ❌ 应是"核心功能"
核心功能: 可以            ← ❌ "可以"被当字段值
```

**预期** (正确行为):
- [ ] "给大学生用" → 目标用户
- [ ] "支持扫码记账和月度报表" → 核心功能
- [ ] "可以" → 确认词（或至少不污染字段）

**状态**: ❌ **稳定复现** — LLM field_answer 对"答非所问"不做语义校验, 按当前待填字段强填
**建议**: 需求分析 Sprint 修复（LLM 分流时对回答做"内容匹配"校验, 答非所问 → 智能归类或追问澄清）
