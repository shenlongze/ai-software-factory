## 1. 架构决策

### 1.1 改造原则（每个写点）

1. 改走 `set_artifact(root=workspace, project_id=slug, type=<类型>, data=<对象>|raw_text=<全文>,
   producer=<引擎标识>, trace_id=<contextvar 读, 无上下文 → None>, file=<保持现状文件名>)`
2. **内容语义零变化**: JSON 用 data 传对象 (set_artifact 序列化, 允许合法缩进差异);
   markdown 用 raw_text 传全文 — 与改造前逐字节一致
3. **追加写场景** (change_control PRD v2): 先读现有全文 → 合并新内容 → 整体 set_artifact
   (归档旧版=历史不丢); 禁止绕过契约直接 append
4. **读路径不动**: 只改写动作; 读 (service/retriever/board/intent) 保持原样
5. **失败安全**: set_artifact 包 try/except — 异常 → log + 继续主流程 (契约尽力而为,
   不阻断引擎); 默认路径必须成功 (测试断言)。**不写直写回退** (保持 grep 直写归零)
6. **契约自身**: artifact_contract.py 只 import 不改; 能力缺口 (如 PRD.quality.json 名 vs
   schema quality.json) → 记录给集成方 Codex, 本任务不扩契约

### 1.2 trace_id 来源

- `from factory_console.trace_context import get_trace_id` (K-4) — 无上下文 → "" → 传 None

### 1.3 测试

每个写点改造后断言 (tests/console/test_s10_125_c2_contract_wiring.py):
- 写后 manifest 有该类型条目 + 版本 +1
- producer/trace_id 正确 (trace 上下文内写 → trace_id 落 manifest)
- history 归档 (第二次写 → history/<名>.v<N> 存在)
- 内容读取一致 (文件内容与预期一致)
- 失败安全: set_artifact 异常 (mock) → 引擎不中断
- 直写归零: grep 标准文件名无残留直写 (源码断言)
