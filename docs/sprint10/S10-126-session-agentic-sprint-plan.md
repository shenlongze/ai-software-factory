## 0. 为什么这是重要 Sprint

会话单点能力已对齐前沿（agentic 循环 + Reflection + 话题账本 + 外部委派），但**三个痛点未解决**：

1. **问题总是用户发现的** —— 每轮 intent/tool/耗时无审计、无指标（可观测缺失）
2. **数据真不真靠自觉** —— 回答无强制证据链、无回答后自检（验证缺失）
3. **新会话断链** —— 跨会话记忆、项目知识（RAG）未接会话（记忆缺失）
4. **不说人话** —— 固定模板（【结论】【数据】【建议】）+ 无情绪回应 + 详略不分（对话风格层缺失）
5. **不做人事** —— 会话只会"答"，不会"办"：出计划/建任务/委派/验证/交付没串成执行状态机

**Sprint 目标：会话从"能用"→"自检自证、可度量、跨会话连续、像人说话、真把事办了"。**

成功标准（验收总纲）：
- ✅ 会话回答**每句结论可溯源**（能追溯到工具证据 / 事实卡一致性）
- ✅ 会话质量**可度量**（意图准确率 / 工具成功率 / 耗时进监控页趋势）
- ✅ 新会话说"继续上次"**能接上**（摘要 + 锚定任务）
- ✅ **真把事办了**：说"把 X 做完" → 出计划 → 审批 → 会话逐任务执行（委派+验证）→ 交付汇报，全程进度可查
- ✅ **盲测像人**：10 条真实会话盲测，≥7 条"像人说的"（非报表/非模板）

## 1. 史诗拆解（6 个史诗，按优先级）

### S-6 对话自然度（P0 · 最高优先 · 用户第一感知）

**目标**: 会话"像人说话"——风格适配、情绪回应、详略分级、模板解放。

| 任务 | 内容 | 验收标准 |
|---|---|---|
| S-6.1 风格分级 | 对话类型 → 输出风格：闲聊简短 / 查询清晰带数字 / 分析深入 / 不满质疑先共情 | 4 类风格单测（prompt 分支可注入） |
| S-6.2 模板解放 | 查询类保留必要数字但取消【结论】【数据】【数据来源】硬标签 → 自然段落（信息齐全但像人写） | 旧路由 STANDARD_OUTPUT 改自然段落；信息无丢失断言 |
| S-6.3 情绪回应 | 检测不满/质疑/感谢/闲聊 → 语气前置（"你说得对，我重新查证…"） | 质疑场景回答以共情/承认开头 |
| S-6.4 详略分级 | 按意图+上下文长度控篇幅：默认 ≤3 句，复杂才展开 | 闲聊回答 ≤3 句；分析可展开 |

**依赖**: 无 | **风险**: 过度"人味"丢信息 → 信息完整性单测兜底（关键数字必现）

---

### S-5 会话执行状态机（P0 · 做人事 · 与 S-6/S-1 并行）

**目标**: 会话真把事办了——"把 X 做完"在会话内闭环：计划→审批→逐任务执行→验证→交付。

| 任务 | 内容 | 验收标准 |
|---|---|---|
| S-5.1 执行状态机 | `session_exec_state.json`：plan/status/tasks/current/progress（审批后持久化） | 状态机单测：approve→running→verifying→done 流转合法 |
| S-5.2 逐任务推进 | `chain_start`/`chain_next`：委派执行（内部/外部 AI）→ M7 验证 → 回写任务状态 | 端到端单测：stub 委派 + stub 验证 → 任务 done + 回写 |
| S-5.3 交付汇报 | 全部完成 → 产出物/测试结果/证据 → 结构汇报 + 任务勾选 done | 汇报含 做了什么/结果/证据/下一步 |
| S-5.4 进度可查 | `chain_status`：会话内实时查询执行链进度（当前任务/完成数） | 会话问"进度"返回真实状态 |

**依赖**: M7 验证钩子（已有）+ execute_plan（已有）| **风险**: 外部委派耗时长 → 异步 + 进度可查，不阻塞会话

### S-1 会话可观测（P0 · 与 S-6 并行）

**目标**: 每轮会话落审计，指标进监控页，让"问题"从用户发现变为指标发现。

| 任务 | 内容 | 验收标准 |
|---|---|---|
| S-1.1 会话审计记录 | AgentLoop 每轮落 `session_audit.jsonl`：ts / session_id / question / intent(软参考) / tools[] / total_calls / 耗时ms / answer_len / 收敛方式(自主\|reflection\|硬收敛) | 每轮会话 1 条；字段齐全；trace_id 贯穿 |
| S-1.2 会话指标聚合 | 按天/按会话聚合：意图分布、工具成功率、平均轮数、平均耗时、硬收敛率（3-loop 触发占比） | `factory eval` 只读可查；JSON 落地 |
| S-1.3 监控页会话面板 | WebUI 监控页新增"会话"tab：意图分布/工具成功率/硬收敛率趋势 + 最近 N 条会话详情 | 页面可看趋势；无数据不崩 |

**依赖**: 无 | **风险**: 审计文件增长（jsonl 滚动上限 5000 条/天）

---

### S-2 回答验证闭环（P0）

**目标**: 回答不自说自话——关键数据可复核、无证据不结论、答完自检。

| 任务 | 内容 | 验收标准 |
|---|---|---|
| S-2.1 事实卡一致性校验器 | 回答中的关键数字（进度/任务数/版本）与实时查询结果**确定性比对**（数字提取 → 对账），不一致 → 标记 + 提示修正 | 校验器单测 5 用例（对/错/缺/小数/百分比） |
| S-2.2 无证据不结论 | 查询/分析类最终回答：若本轮未调任何工具且问题需实时数据 → 强制回退"先查再说"（拒绝空答） | 模拟"项目进度"不调工具直接答 → 被拦截提示 |
| S-2.3 回答后自评 | Reflection 加强：最终答案生成后追加一条 system 让模型自检"结论是否都有工具证据支持"，有疑 → 补充/修正 | 自检轮注入可见；单测覆盖 |

**依赖**: S-1.1（审计可查校验记录） | **风险**: 数字提取误判（中文数字/单位）→ 校验器只标记不阻断

---

### S-3 会话质量评估（P0）

**目标**: 会话质量可量化（eval 数据集 + LLM-judge），进发布门。

| 任务 | 内容 | 验收标准 |
|---|---|---|
| S-3.1 真实会话数据集 | 把 `test_real_conversation` 扩展为标注集：`session_eval_cases.json`（问题 + 期望意图/工具/回答要点），≥30 条，覆盖 8 类意图 + 5 类已知坑 | 数据集可加载；每条有期望断言 |
| S-3.2 LLM-judge 评分器 | 对回答质量评分：准确性(0-1)/证据充分(0-1)/格式合规(0-1) → 总分；LLM 判分 + 规则兜底（有工具证据=1） | judge 单测 5 用例；无 LLM 可降级 |
| S-3.3 eval 接入发布门 | `factory eval --gate` 增加会话维度：数据集通过率 ≥ 90% 才放行 | 门可跑；失败 → rc 阻断（只读 --check 不阻断） |

**依赖**: S-2.2（证据约束使 judge 有据可评） | **风险**: LLM-judge 主观 → 双 judge 或规则锚定

---

### S-4 跨会话记忆 + 项目知识（P1）

**目标**: 新会话能接上次；项目知识进上下文。

| 任务 | 内容 | 验收标准 |
|---|---|---|
| S-4.1 记忆存储 | 会话收尾（或每 10 轮）把话题摘要/结论/决策写入项目级 `project_memory.json`（带 ts/来源/可审计） | 记忆文件结构定稿；来源可追溯 |
| S-4.2 跨会话恢复 | 新会话"继续上次/接着做 XX" → 定位上次会话摘要 + 锚定任务 → 注入上下文 | 新会话上下文含上次摘要 + 任务锚点 |
| S-4.3 RAG 接会话 | agent 循环增加知识检索（复用 `rag_query`）：项目文档检索结果作为上下文注入（检索命中才注入，不命中不编造） | 会话上下文可含检索片段 + 引用源 |

**依赖**: TopicLedger（已有） | **风险**: 记忆污染 → 只追加不删除，可审计回滚

## 4. 风险与边界

| 风险 | 缓解 |
|---|---|
| DeepSeek 自评/反思深度有限 | 机制先建（S-2.3），模型可换；规则兜底（S-2.1 确定性校验）保底 |
| 审计/记忆数据增长 | jsonl 滚动上限 + 记忆只追加可审计 |
| LLM-judge 主观 | 双锚定：确定性规则（有工具证据=1）+ LLM 判分取并集 |
| RAG 无向量库 | 复用现有 `rag_query`（确定性片段 + 引用源），不引新依赖 |

**不做（边界）**: MCP 全量标准化 · 多模型分层路由 · 工具级 RBAC · 移动端 —— 放后续 Sprint（P2）。
