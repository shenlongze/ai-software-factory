# 会话系统整体设计 v2（评审稿）

> 日期: 2026-08-27 | 前置: v1.1.206 · v1 设计评审（Founder: 不够强/不正确）
> 状态: **评审稿** — 待 Founder 确认后定稿排期
> 核心（Founder 2026-08-27）: **无论用户提问/质疑/聊天/分派任务, 会话都必须先 get 到真实意图, 再让专业的人干专业的事。**

---

## 0. 为什么 v1 不对（自省）

v1 把会话做成「意图→工具/状态机」的**路由表**，再叠加 agent 循环——本质还是「猜意图 + 调工具」。
Founder 一句话点破：**用户是千变万化的（提问/质疑/闲聊/派活/骂系统），会话第一步必须是"真的听懂他在干什么"，然后交给专业能力。**
不是"会调工具的聊天"，是**先懂人、再调度**。

---

## 1. 核心架构：三句话

```
① 懂人（IntentCore）: LLM 深度理解 — 用户在做什么?
   意图(提问/质疑/聊天/派活/开发/操作…) × 对象(项目/任务/文档/系统/外部AI) × 情绪(不满/确认/追问)
② 调度（Router）: 按真实意图 → 专业能力 ("专业的人干专业的事")
   查询→数据工具 · 质疑→验证自查 · 聊天→自然对话(带上下文) · 派活/开发→自主执行链
   外部专业→外部 AI agent (架构/安全/UX 审查…) · 操作→动作工具(确认后执行)
③ 执行（Executor）: 多步自主执行 — 调工具/外部AI, 带证据, 关键决策点才问人
```

**铁律：意图理解不靠关键词; 调度按意图不按词; 执行可多步、可追溯、可确认。**

---

## 2. IntentCore — 真实意图理解（最强的一层）

### 2.1 意图维度（LLM 输出结构化）

```jsonc
{
  "intent": "question|challenge|chat|delegate|develop|operate|clarify",
  "target": {"type": "project|task|doc|system|external|general", "id?"},
  "need": "info|action|verification|correction|creation|execution",
  "emotion": "neutral|satisfied|dissatisfied|urgent|skeptical",
  "summary": "一句话用户到底要什么",
  "followup": "是否需要追问/确认 (和缺什么)"
}
```

- 输入: 当前消息 + **完整会话上下文**（历史/任务锚点/项目事实/上次结论）
- 模型: LLM 语义理解为主（prompt 规范 + 示例），命令类走快路径兜底
- 关键: **质疑/不满/纠错**也要识别（"这回答不负责"、"上次不对吧"）→ 触发自查/验证/诚实修正，不是继续瞎答

### 2.2 意图 → 专业能力（Router）

| 真实意图 | 例 | 交给谁 |
|---|---|---|
| 提问/查询 | "项目进度?" "这是什么?" | 数据工具 (scan/status/docs) + 证据 |
| 质疑/纠错 | "这回答不负责吧" "上次说的不对" | 自查: 重查数据 → 承认/修正 (诚实) |
| 聊天/沟通 | "你好" "聊聊想法" | 自然对话 (带上下文+记忆) |
| 分派任务 | "把登录功能做完" | 自主执行链 (开发) |
| 操作 | "把 P0 任务开始 2 个" "推送到 github" | 动作工具 (确认后执行) |
| 外部专业 | "审查一下这个架构" "做安全评估" | 外部 AI agent (route→delegate) |
| 澄清 | 意图不明 | 追问, 不瞎猜 |

## 3. Executor — 自主执行链（"把活干完"）

对"分派任务/开发/操作"类意图，进入执行链：

```
计划(拆任务/定顺序) → 建任务进 backlog → 逐任务执行(内部工具/外部AI) 
→ 验证(测试/审查) → 修(回修) → 审查(交叉) → 交付(产出/文档/git) → 汇报
```

- 多步自主: 可连续调工具/外部 AI 数轮, 不需要每条消息都等人
- 检查点: 关键决策（验证码走短信还是邮件/上不上生产）→ 停下问人
- 证据: 每步 {tool/external, input, output, ts, trace_id} 落 Message.evidence
- 全部动作: 真实执行 + 可审计; 敏感动作（建任务/执行/git push）确认

---

## 4. 会话 Agent（持久状态）

- Session = Agent 的一次连续上下文（历史 + 计划 + 进度 + 任务锚点 + 项目事实 + 记忆）
- 跨消息有状态: 执行中的计划/任务不丢（T-3 基础 + 新增 plan 状态）
- 跨会话: 新会话"继续上次的架构重构" → 恢复上次会话摘要 + 任务锚点
- 输出规范: 结论/证据/数据/建议 + 跳转; 无依据明确说"未查询到/需人工"

---

## 5. 上下文与记忆

- 每轮上下文: 历史(预算+压缩摘要) + 任务块(T-2) + 项目事实(实时) + 证据 + 记忆(K-7f)
- 记忆: 项目级（常问事实/关键决策）+ 用户级（偏好/历史想法）— 带来源/时间戳, 可审计
- 质疑/纠错的结果也要进记忆（避免重复犯同样的错）

---

## 6. 安全 / 诚实

- 敏感动作确认（已有 SENSITIVE_TOOLS）
- 质疑 → 必须先验证再回应（不嘴硬、不糊弄）; 查不到 → 诚实"未查询到"
- 外部 AI 委派: probe 验证可用才委派; 黑盒如实标注

---

## 7. 可观测

- trace_id 贯穿; 每轮 intent/route/execution 落审计
- 会话指标: 意图识别准确率/工具调用成功率/执行链完成率 → 监控页

## 8. 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **I1 IntentCore** | LLM 结构化意图(含质疑/聊天/派活/开发分类) + 上下文注入 + 命令快路径兜底 | 提问/质疑/聊天/派活/开发 五类都能正确分类; 质疑触发自查 |
| **I2 Router+Executor** | 意图→专业路由; 执行链: 计划→任务→执行(内部/外部)→验证→审查→交付 | "把登录做完" 一条消息跑完整条链(计划+任务+代码+测试+审查+汇报) |
| **I3 持久会话+记忆** | 跨消息计划/进度; 跨会话恢复; 项目/用户记忆 | "继续上次"恢复; 质疑纠错进记忆 |
| **I4 全工具面+原生FC** | 真实注册表(39+) + 外部执行器统一; 原生 function calling | 工具面全量; 非伪 JSON 协议 |

依赖: I1 → I2 → I3 → I4; 全程复用 T/S/U/M 底座。
