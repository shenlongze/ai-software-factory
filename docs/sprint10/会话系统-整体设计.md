# 会话系统整体设计 v0.1（评审稿）

> 日期: 2026-08-27 | 前置: v1.1.206 (T 系列 ✅ · 语义门 ✅ · 外部执行器 M1-M7 ✅)
> 状态: **评审稿** — 待 Founder 确认后定稿排期
> 动机: Founder「这会话功能太low了」— 从补丁式修会话 → 整体设计

---

## 0. 现状盘点（为什么 low）

用户会话层是**碎片拼的**，多处各搞一套：

| 能力 | 现状 | 问题 |
|---|---|---|
| 会话存储 | WebUI=`console_sessions.py`；CLI=`session/session.py` 内存态 | **两套模型, 互不相通**; CLI 无跨会话持久 |
| 上下文 | WebUI=事实卡+task_id 注入(T-2)；CLI=ChatService 内存历史(刚补) | 各自为政, 无统一上下文管线/预算/压缩 |
| 意图 | query_engine 关键词+LLM(语义门刚加) | 命令/分析/闲聊混在一层, 边界靠补丁 |
| 工具 | 39 工具注册表(U-1) + analysis_tools + project_scan + code_scan | **会话没有统一"工具面"**; 各意图各自调, 无证据规范 |
| 流程 | conversation.py 产品发现状态机 | 仅产品流程; 任务/审查/运维无会话状态机 |
| 记忆 | 无跨会话长期记忆(仅 trace 可追溯) | 新会话忘光 |
| 输出 | LLM 直接回 | 格式不一致; 无强制证据引用(刚给 deep_analyze 加) |

**用户感知的「low」= 上下文断、分析盲猜、工具不接、记忆没有、输出不统一。**
这些不是单个 bug，是缺一个**统一会话架构**。

---

## 1. 目标 / 非目标

### 目标
- G1 **统一会话**：WebUI / CLI / API 同一会话模型、同一上下文、同一意图/工具链
- G2 **上下文管线**：消息历史(预算)+任务上下文+项目事实+工具证据+记忆，压缩/摘要不掉链
- G3 **语义优先**：LLM 语义理解为主，命令快路径为辅（不再堆关键词）
- G4 **工具即能力**：会话能调用任意注册工具（39+外部执行器），统一证据块，可溯源
- G5 **记忆跨会话**：项目/用户级长期记忆，新会话「记得」
- G6 **输出规范**：诚实/结构化/引用证据/可跳转，全端一致

### 非目标
- 不做多模态（图片/语音）输入（后续）
- 不做自由 Agent 自主循环（会话是受控流程，不是放养 agent）
- 不重写现有 ~90 个 session 模块（只加统一层，复用现有能力）

## 2. 总体架构（统一会话层）

```
┌──────────────────────────────────────────────────────────────┐
│  端: WebUI 会话栏 · CLI REPL · API /chat /sessions            │
│  —— 全部走同一 HTTP/内部接口 (不再各端各自为政)                │
└───────────────┬──────────────────────────────────────────────┘
┌───────────────▼──────────────────────────────────────────────┐
│  统一会话层 (新)                                              │
│  · SessionManager: 统一会话存储 (WebUI/CLI/API 同一数据)       │
│  · ContextPipeline: 消息历史(预算/压缩/摘要) + 任务上下文       │
│      + 项目事实卡 + 工具证据 + 记忆注入                        │
│  · SemanticIntent: LLM 语义意图 + 语义门 + 命令快路径          │
│  · ToolGateway: 统一工具面 (39 内置 + 外部执行器 + 流程工具)    │
│    → 统一证据块 {tool, input, output, ts, trace_id}            │
│  · FlowState: 状态机 (产品发现 / 任务推进 / 审查 / 运维)        │
│  · Memory: 项目/用户长期记忆 (K-3/K-7f 底座)                   │
└───────────────┬──────────────────────────────────────────────┘
┌───────────────▼──────────────────────────────────────────────┐
│  能力层 (已有, 复用): tools/registry · analysis_tools ·       │
│  project_scan/code_scan · 外部执行器 · conversation · actions │
└──────────────────────────────────────────────────────────────┘
```

**铁律**：端只做渲染和输入采集；所有状态/上下文/意图/工具/记忆都在统一会话层。这消除「WebUI 记得、CLI 不记得」这类分裂。

## 3. 数据模型（统一）

```jsonc
// Session (统一, 兼容现有 console_sessions 字段)
{ "id", "scope": "company|project", "project_id", "feature_id", "task_id",
  "title", "status", "created_at", "updated_at",
  "summary": "压缩摘要",        // K-7f: 超预算后摘要落盘
  "memory_keys": ["project:ai-factory-self", "user:..."] }

// Message
{ "id", "session_id", "role": "user|assistant|system|tool",
  "content", "context_ref": "ctx-...",      // 该轮上下文快照 id (可追溯)
  "evidence": [ {tool, input_hash, output_snippet, ts, trace_id} ],
  "intent": "deep_analyze", "created_at" }

// Context (每轮上下文快照 — 可追溯/可审计)
{ "id", "history": [压缩后的最近N轮], "task_block", "project_facts",
  "tool_evidence", "memory", "budget": {tokens, used, action} }

// Memory (跨会话)
{ "key": "project:ai-factory-self", "facts": [...], "updated_at" }
```

## 4. 上下文管线（ContextPipeline）— 解决「上下文断」

```
输入 → ① 取会话(统一) → ② 组装上下文:
        - 历史: 最近 N 轮 (预算内) + 超预算 → 摘要 (K-7f, 自动)
        - 任务块: session.task_id → 任务状态/历史/下一步 (T-2 已有)
        - 项目事实卡: 项目级会话注入 (真实数据, 不再虚报)
        - 记忆: memory_keys 命中 → 注入相关事实
        → ③ LLM/工具执行 → ④ 结果+证据落 Message/Context → ⑤ 更新记忆/摘要
```

**预算与压缩**（K-7f 落地）: 每轮上下文 token 预算 (如 4k); 超 → 最旧轮压缩成摘要 (自动); 显式 `/context` 可看当前上下文清单 (现有压缩按钮)。

---

## 5. 语义意图层（SemanticIntent）— 解决「盲猜/堆关键词」

```
① LLM 语义理解 (统一 prompt: 意图 + 参数 + 语义边界) — 主路径
② 语义门 (分析/评估/命令语义信号) — 防劫持 (v1.1.206 已有, 扩展)
③ 命令快路径 (继续做/标记完成/创建任务 — 必须确定性, 不赌 LLM)
④ 未识别 → 明确问澄清 (不再瞎聊)
```

**工具绑定**: 意图 → 工具映射表 (意图级, 不是关键词级): deep_analyze→analysis_tools+scan;
project_status→事实卡; code_scan→scan_repo; task_action→PATCH... 一个意图稳定绑一组工具。

---

## 6. 工具面（ToolGateway）— 解决「工具不接/证据没有」

- 会话可调用**任意注册工具** (39 内置 + 外部执行器 + 扫描/文档/任务), 不再各意图硬编码
- 每次调用产生**统一证据块** {tool, output, ts, trace_id} 落 Message.evidence
- LLM 输出强制引用证据 (deep_analyze 已有 reply_extra, 推广到所有工具意图)
- 无工具/无证据 → 诚实「未查询到/需人工」, 不编造

---

## 7. 流程状态机（FlowState）

| 流程 | 状态 | 会话触发词示例 |
|---|---|---|
| 产品发现 | DISCOVERY→PRODUCT_CONFIRMATION→CREATED | 「我想做一个X」|
| 任务推进 | TASK_ANCHORED→EXECUTING→REVIEW→DONE | 「继续做X」「标记完成」|
| 深度分析 | ANALYZING→REPORT (deep_analyze) | 「分析利弊/扫描代码/评估」|
| 审查 | REVIEWING (外部 reviewer 交叉审查) | 「审查这个」|

状态机在统一层，端无关；中断/恢复 (T-3 已有基础)。

---

## 8. 记忆（Memory）— 解决「新会话忘光」

- 项目级记忆: 项目常问事实 (进度/结构/关键决策) — 会话启动注入
- 用户级记忆: 用户偏好/历史想法 (K-3 经验底座)
- 记忆有来源/时间戳, 可审计; 不自动编造, 只存真实执行沉淀

---

## 9. 输出规范（诚实/结构化）

- 工具意图 → 固定格式: 【结论】【数据(引用证据)】【数据来源】【建议】+ 跳转链接
- 分析意图 → 结论/分析过程(引用【工具】)/数据/建议
- 无依据 → 明确「未查询到/需人工」; 禁止编造
- 全端一致 (WebUI/CLI 同渲染规则)

---

## 10. 可观测（复用）

- trace_id 贯穿 (K-4 ✅); 会话/消息/证据落库可审计
- 会话指标: 每意图调用/成功率/上下文预算命中率 → 监控页 (M4 ✅)

---

## 11. 里程碑计划

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **C1 统一会话+上下文** | SessionManager 统一存储 (WebUI/CLI/API 同一); ContextPipeline 历史预算+压缩+任务/项目/证据注入 | 同一会话 WebUI/CLI 都能续聊; 超预算自动摘要; 上下文可 /context 查看 |
| **C2 语义意图+工具面** | SemanticIntent 全量接入 (所有意图走 LLM 语义+语义门+命令快路径); ToolGateway 统一证据块 | 任意措辞意图稳定; 所有工具调用有证据块; 输出强制引用 |
| **C3 流程状态机+记忆** | FlowState 任务/分析/审查统一; Memory 项目/用户记忆 | 「继续做X」跨会话记得上次; 新会话自动注入项目记忆 |
| **C4 输出规范+全端一致** | 输出模板全端统一; 会话指标进监控页 | WebUI/CLI 同渲染; 会话指标可视化 |

依赖: C1 (基础) → C2 → C3 → C4; 全程复用 T 系列/K-7f/U-1 底座。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 统一存储迁移破坏现有会话 | 兼容层: 统一 SessionManager 读旧格式, 增量迁移 |
| LLM 语义不稳定 | 命令快路径兜底 + 语义门 + 工具意图映射表 (语义只选意图, 工具绑定意图级) |
| 上下文预算误压缩丢关键 | 摘要保留任务块/证据引用; /context 可查 |
| 记忆污染 (陈旧事实) | 记忆带时间戳/来源, 更新才覆盖; 会话内以实时事实卡为准 |
