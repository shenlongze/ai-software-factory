## 0. 摘要（给决策者 30 秒）

当前 U-6 把 codex/claude/hermes 的发现与调用**硬编码在代码里**（`_SCAN_TARGETS` / `_RUN_TEMPLATES`）。
市场还有 OpenClaw、Pi Agent、Copilot、Cursor 等，每加一个都要改代码 —— 不可持续。

本设计把「外部 AI CLI」抽象为**声明式适配器（yaml）**：通用引擎负责
执行生命周期 / 执行记录 / 监控 / 路由 / 审计（产品无关），每个产品一个适配器
文件完整声明它的**独特能力**（怎么调、怎么挖内部 agents/skills、能干什么）。
**新增产品 = 写一个 yaml，零改代码；能力不因通用而损失（产品开放度决定能挖多深）。**

---

## 1. 目标 / 非目标

### 1.1 目标
- G1 **可扩展**：新增外部 AI CLI 只写声明式适配器，不改引擎代码
- G2 **能力完整**：每个产品的独特能力（agent 选择 / skills / 特殊参数 / 内部资产）在适配器里完整表达
- G3 **统一可观测**：所有执行器走同一执行记录 → 监控 / 审计 / 回滚 / 路由天然通用
- G4 **诚实**：probe 验证可用性；黑盒层不假装看到内部；效果靠产出验证衡量
- G5 **可路由**：按能力声明 + 历史效果分选择 agent/skill，成本最优，效果最佳

### 1.2 非目标（本期不做）
- 不实现产品内部的实时遥测（除非产品开放日志/API，且经 extensions 钩子接入）
- 不做跨产品统一 agent 语言（各产品 agent 定义保留原格式，导入时结构化）
- 不做外部产品的 GUI 操作（仅 CLI 非交互调用）
- 不做公网 MCP http/sse（沿用 U-3 诚实拒绝）

## 2. 术语

| 术语 | 定义 |
|---|---|
| **外部 AI CLI / 执行器** | 本机安装的 AI 命令行产品：codex / claude / hermes / openclaw / pi-agent… |
| **适配器（Adapter）** | 描述一个外部执行器的**声明式配置**（yaml），含发现/探测/调用/资产发现/能力声明 |
| **通用执行器（GenericExecutor）** | 按适配器声明执行 discover→probe→invoke→record 的引擎（产品无关） |
| **宿主资产（Host Assets）** | 执行器内部可导入的东西：agents（角色定义）、skills（SKILL.md）、plugins、persona |
| **借壳委派** | 把宿主内部 agent 注册为 AI 员工，用宿主 CLI + 指定 agent 参数真实调用 |
| **黑盒委派** | 直接调宿主 CLI，宿主内部用什么不可见，只记输入/输出/耗时/退出码 |
| **执行记录（EXR/EXS）** | 一次委派的完整生命周期记录（已有底座，本期扩展字段） |
| **能力声明（Capabilities）** | 适配器声明它能干什么（roles/agents/skills）→ 路由输入 |

## 3. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  WebUI（设置→外部能力 / AI 团队监控页）                       │
│  扫描/导入/试跑/监控指标/路由查看                             │
└───────────────┬─────────────────────────────────────────────┘
                │ REST
┌───────────────▼─────────────────────────────────────────────┐
│  AI Factory 引擎层（产品无关）                                │
│  · 适配器注册表 ExternalExecutorRegistry（读 yaml）           │
│  · 通用执行器 GenericExecutor（discover/probe/invoke）        │
│  · 资产发现 HostAssetScanner（agents/skills/plugins 解析）    │
│  · 路由 Router（能力匹配 + 历史加权 + 成本分级 + 用户显式）    │
│  · 执行记录 ExecutionRecord（EXR/EXS + verify/rework 扩展）   │
│  · 监控指标 Metrics（效率/效果/完成率/回修/验证）              │
└───────────────┬─────────────────────────────────────────────┘
                │ 按适配器声明调用（subprocess，统一契约）
┌───────────────▼─────────────────────────────────────────────┐
│  外部执行器（每产品一个适配器 yaml）                          │
│  codex / claude / hermes / openclaw / pi-agent / …          │
│  各自: invocation 模板 · host_assets 规则 · capabilities     │
└─────────────────────────────────────────────────────────────┘
```

**依赖方向**：引擎层只依赖「适配器 Schema」，不依赖任何具体产品名。
监控/路由/审计只消费「执行记录」，不消费产品名。

## 4. 适配器 Schema（严谨定义）

每个外部执行器一个 yaml，位于 `<data_dir>/external-ais/<id>.yaml`。
内置 codex/claude/hermes 作为预装模板（与用户新增同构）。

### 4.1 字段定义

| 字段 | 类型 | 必填 | 语义 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识（`codex`/`claude`/`openclaw`），即 agent id 前缀 |
| `name` | string | ✅ | 人话名（本机 Codex） |
| `binary` | string | ✅ | 可执行文件名（用于 which/PATH） |
| `discovery` | list | ✅ | 查找顺序：`PATH` + 绝对/家目录路径（`~/.local/bin`）|
| `version_probe` | list[string] | 可选 | 版本探测参数（默认 `--version`）|
| `probe_help` | list[string] | 可选 | 可用性探测参数（默认 `--help`）|
| `invocation` | object | ✅ | 调用模板（见 4.2）|
| `host_assets` | object | 可选 | 内部资产发现规则（见 4.3）|
| `capabilities` | object | ✅ | 能力声明（见 4.4）|
| `extensions` | object | 可选 | L2 深度特化钩子（见 4.5）|

### 4.2 invocation（调用模板）

```yaml
invocation:
  non_interactive: ["exec", "-C", "{project_dir}", "--skip-git-repo-check",
                    "--sandbox", "workspace-write", "{prompt}"]
  project_dir: "flag:-C"        # 三选一: "cwd" | "flag:<参数名>" | "none"
  agent_flag: ["--agent", "{agent}"]      # 可选：借壳委派宿主内部 agent
  skills_flag: ["--skills", "{skills}"]   # 可选：指定宿主 skills（逗号分隔）
  extra: ["--json"]                       # 可选：附加固定参数
  timeout: 600                            # 可选：默认超时秒数
```

**占位符**（渲染时替换，值一律 shell 转义）：
- `{prompt}` — 委派的任务 prompt（必含）
- `{project_dir}` — 项目目录（`flag:` 模式插入该参数名；`cwd` 模式不插入，用进程 cwd）
- `{agent}` — 宿主内部 agent id（仅 `agent_flag` 声明时可用）
- `{skills}` — 宿主 skills 列表（仅 `skills_flag` 声明时可用）

**project_dir 三种定位模式**：
| 模式 | 语义 | 例 |
|---|---|---|
| `cwd` | 子进程 cwd=项目目录（claude/hermes） | claude -p / hermes -z |
| `flag:<NAME>` | 参数名插入（codex 用 `-C`） | codex exec -C <dir> |
| `none` | 不支持指定目录（honest：只能在自身 cwd 跑） | — |

**调用契约铁律**：
1. 渲染后命令必须含 `{prompt}` 展开（否则拒绝执行 —— 防止无输入调用）
2. 所有占位符值经 `shlex.quote` 转义（防注入）
3. 未知/缺字段 → 引擎报「适配器校验失败」，不猜测

### 4.3 host_assets（内部资产发现规则）

```yaml
host_assets:
  agents:
    dir: "~/.codex/agents"
    glob: "*.toml"                  # 文件匹配
    format: "toml"                  # toml | md-frontmatter | yaml | keyvalue
    fields: {name: name, description: description, prompt: developer_instructions}
  skills:
    dir: "~/.codex/skills"
    format: "skill-md"              # 复用 U-4 external_skills 解析（SKILL.md）
  plugins:
    dir: "~/.codex/plugins/cache"
    format: "dirs"                  # 只列目录名（catalog）
  persona:
    path: "~/.hermes/SOUL.md"       # 可选：人格文件 → 展示/注入
```

**支持格式与解析器**（新增格式 = 注册一个 parser，不写产品逻辑）：
| format | 解析 | 产出 |
|---|---|---|
| `toml` | 标准库 tomllib | {name, description, prompt…} |
| `md-frontmatter` | 复用 claude agent 解析（yaml frontmatter + body） | {name, description, tools, model, prompt} |
| `yaml` | 标准库（或宽松 key:value 行解析，零依赖兜底） | 同上 |
| `keyvalue` | 通用 `key: value` 行解析（宽松） | 同上 |
| `skill-md` | **复用 U-4 external_skills.parse_skill_md** | {id, name, description, instructions} |
| `dirs` | 列子目录 | {id: 目录名} |

**导入目标**：
- agents → AI 员工注册表（id=`<adapter_id>.<agent_name>`，role=能力推导，skills=tools/声明，metadata={host, agent_file, invocation_agent_flag}）
- skills → `skills.json`（复用 U-4 → SkillRegistry → 执行注入）
- plugins/persona → 目录化展示（catalog，不注册为可执行）

### 4.4 capabilities（能力声明 → 路由输入）

```yaml
capabilities:
  roles: ["developer", "reviewer", "architect", "agent-runner"]
  agents: true          # 支持宿主内部 agent（可借壳）
  skills: true          # 支持宿主 skills（可注入）
  models: ["default"]   # 可选：已知模型
  cost_tier: "medium"   # low | medium | high（路由成本分级用）
```

### 4.5 extensions（L2 深度特化钩子 — 可选，按产品开放度追加）

```yaml
extensions:
  # 可选：深度遥测 —— 产品开放日志/接口时接入；不配 = 黑盒（诚实标注）
  # event_tail: {command: ["tail", "-f", "~/.codex/logs/agent.log"], parse: "jsonl"}
  # verify_hook: {command: ["openclaw", "verify", "{result_id}"], parse: "json"}
```

**原则**：extensions 是**可选增强**，不是必需；缺省时引擎走黑盒 + 产出验证，能力完整度不依赖 extensions。

## 5. 通用执行器流程（GenericExecutor）

```
discover(adapter) → probe(adapter) → invoke(adapter, task) → record(exec)
```

1. **discover**：按 `discovery` 顺序定位二进制（which + 路径）；找不到 → 标 `not_found`，不注册
2. **probe**：跑 `version_probe`/`probe_help`，退出 0 → `verified=true` + usage 首行落记录；失败 → `verified=false`，**可注册展示但不可委派**（诚实）
3. **invoke**：按 invocation 渲染命令 → subprocess（统一 {exit_code, output, error, command}）
   - 每次委派前**强制 probe**（若上次 probe 距现在 > 5 分钟，重探 —— 防产品更新/失效）
   - 失败路径：CLI 不存在 / 超时 / 非 0 退出 → 诚实错误，不假装成功
4. **record**：写统一执行记录（§7），无论成败

## 6. 委派模型（黑盒 / 借壳 + 分层观测）

### 6.1 两种委派
| 模式 | 触发 | 可见性 |
|---|---|---|
| 黑盒 | 无 agent 指定 | AI Factory 记输入/输出/耗时/成本/退出码；宿主内部不可见 |
| 借壳 | 指定宿主内部 agent（`codex.architecture-examiner`） | 同上 + 知道「派了哪个专业 agent」；内部思考仍黑盒 |

### 6.2 分层观测（能见多少标多少）
```
L1 委派层（引擎）      —— 全可见：适配器/agent/prompt/输入输出/耗时/成本/退出码
L2 宿主执行层          —— extensions.event_tail 可选接入；否则黑盒（UI 标「黑盒」）
L3 产出验证层          —— 全可见、客观：验证结果（测试/审查/验收）回写执行记录
```
**效果衡量不依赖 L2**：由 L3 验证结果定义（§8 指标）。

## 7. 统一执行记录模型（EXR/EXS 扩展）

现有底座：`exec/requests.json`（EXR）、`exec/execution_records.json`（EXS）、
`exec/checkpoints.json`（T-6）、runtime-sessions 事件链、K-4 trace_id、T-9 执行溯源。

本期扩展字段（新增，向后兼容）：

```jsonc
// EXR（委派请求）新增
{
  "executor_id": "codex",              // 适配器 id
  "mode": "blackbox|borrowed-shell",
  "host_agent": "architecture-examiner", // 借壳时
  "host_skills": ["..."]                // 借壳时
}
// EXS（执行结果）新增
{
  "duration_ms": 123456,               // 效率
  "cost_usd": 0.42,                    // 成本（产品报告或估算，诚实标 source）
  "first_pass": true,                  // 首次通过（无回修）
  "verify": {"method": "pytest|reviewer|manual", "result": "pass|fail|unknown", "score": 0.9},
  "rework": {"count": 0, "reasons": []},
  "visibility": "L1|L2"                // 观测层级（L2 需 extensions 接入）
}
```

**记录闭环**：委派(EXR) → 启动(checkpoint) → 事件 → 结果(EXS) → 验证(verify 回写) →
回修(redo 计数) → 交付 → 归档。全部带 trace_id（K-4），可回溯审计。

## 8. 监控指标模型（回答「监控什么」）

| 指标 | 定义 | 聚合维度 |
|---|---|---|
| 执行效率 | 委派→完成耗时 / 启动→首事件 / 输出大小 | 按 executor / agent / 项目 |
| 执行效果 | 首次通过率 = 无回修数 / 总数；验证通过率 = verify.pass / verify.total | 同上 |
| 完成率 | done 任务数 / 总任务数 | 按 executor / agent / 项目 |
| 回修 | 回修次数 / 回修原因分布 | 同上 |
| 验证 | 验证方式分布 / 验证通过率 / 未验证数（诚实标注） | 同上 |
| 成本 | 每次委派成本 / 每任务累计 | 同上 |
| 告警 | running 超时无事件(卡死) / 连续失败≥3 / provider 故障 / 不可用适配器 | 全局 |

**UI（AI 团队监控页）**：概览卡（4）+ agent 列表（含外部 agent，带源标识）+ 执行流
时间线 + 告警区 + 单记录钻取（事件链/证据/验证/回修）。

## 9. 路由模型（回答「选谁 / 怎么用最好」）

```
① 任务分类：意图 → 工作类型（write-code/review/test/product/security/ux/docs…）
② 能力匹配：候选 = 适配器.capabilities + 导入 agent 的能力声明 匹配工作类型
③ 历史加权：score = w1*首次通过率 + w2*验证通过率 − w3*成本 − w4*耗时
            （权重可配置；连续失败降权 + 告警）
④ 成本分级：任务难度 → 选 cost_tier 匹配（简单任务不派 high tier）
⑤ 用户显式：用户指定 agent → 直接采用（仍 probe）
⑥ 兜底：无匹配 → 系统默认 + 明确标注「未匹配专业能力，已降级」
```

**效果反馈闭环**：委派 → L3 验证 → 效果分回写执行记录 → 路由权重更新（学习循环）。

## 10. 安全 / 成本 / 诚实边界

- **权限边界**：外部执行器在子进程跑，可配置是否允许（默认禁 `--yolo`/`--dangerously-*`；
  适配器可声明 `allow_dangerous: false` 由引擎强制过滤）
- **成本上限**：单次委派预算 / 每任务累计预算（超 → 拒绝 + 告警；复用预算模块）
- **诚实铁律**：
  1. probe 不通过 → 不可委派（标不可用）
  2. 黑盒层 → UI 标「黑盒」，不编造内部事件
  3. 成本无来源 → 标 unknown，不估算冒充
  4. 验证未跑 → 标 unknown（效果指标不计入通过率）
  5. 能跑 ≠ 一次任务真实成功；成功以 CLI 退出码 + 验证结果为准

## 12. 里程碑计划（M1→M5，每步可独立验收）

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| **M1 适配器层** | schema + registry + GenericExecutor；重构 U-6 硬编码 → 声明式；内置 codex/claude/hermes + openclaw/pi-agent 示例 | `factory external-ai scan` 列出全部；probe 通过/不通过如实；`run` 真实调用；**新增一个 yaml 无需改代码** |
| **M2 资产导入** | HostAssetScanner + parsers；agents→AI 员工、skills→U-4 复用、plugins/persona→catalog；统一执行记录扩展字段 | 导入 codex 19 agent / claude 19 agent / hermes 121 skill 可见；AI 员工列表出现外部 agent；EXR/EXS 带 executor/mode/host 字段 |
| **M3 委派+验证回路** | 借壳委派（agent_flag 声明驱动）；verify_hook 回写；rework 计数 | `run --agent codex.architecture-examiner` 用宿主 CLI 真实跑；验证结果回写 EXS；回修计数正确 |
| **M4 监控页** | /api/external-ai/{id}/monitor 聚合 + AI 团队监控页（概览/agent 列表/执行流/告警） | 监控页显示外部 agent 状态/指标/告警；黑盒层如实标注 |
| **M5 路由层** | 能力匹配 + 历史加权 + 成本分级 + 反馈学习 | 同能力多候选时按效果分排序；连续失败降权；用户显式优先 |

**依赖**：M1 无依赖（重构 U-6）；M2 依赖 M1 + U-4（skills 解析复用）；M3 依赖 M2；
M4 依赖 M3（指标有数据）；M5 依赖 M2/M3（效果分有数据）。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 产品 CLI 频繁变参数 | 每次委派前强制 probe（5 分钟缓存）；probe 失败 → 拒绝委派 + 告警，不硬调 |
| 适配器 schema 表达不了某产品独特能力 | extensions 钩子特化（按开放度追加），不阻塞通用层 |
| 黑盒导致效果无法评估 | 以 L3 产出验证为准（不依赖 L2）；验证未跑标 unknown |
| 外部执行成本失控 | 成本上限 + 预算熔断（复用 budget） |
