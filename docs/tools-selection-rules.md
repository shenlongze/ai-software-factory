# 工具选择规则（Tools Selection Rules）

> 版本: v1.1.166 设计稿 · 状态: U-1 验收基准 · Founder 2026-08-26
> 目的: 统一工具注册表 (U-1) 的"何时调用什么工具"规则, 贯穿 CLI/WebUI/会话/流程。

## 核心哲学
**确定性优先, LLM 兜底** — 规则能定的不给 LLM 猜, 防止脑补工具。
工具 ID 只能来自注册表 (工具清单 = 事实源), LLM 不允许发明工具名。

## 三层选择

### 第一层 · 发起方式决定候选
| 发起 | 选择方式 |
|---|---|
| 用户显式 (CLI 命令 / WebUI 按钮) | 直接绑定工具 (无选择) |
| 会话自然语言 | 意图规则 (确定性关键词优先, LLM 只补参数) |
| 流程自动 (pipeline 阶段) | 阶段绑定工具 (PRD→prd_generate 等) |

### 第二层 · 候选多个时按规则打分 (顺序即优先级)
1. **关键词匹配** (确定性): 问句/上下文关键词命中工具
2. **参数满足**: 工具所需参数是否齐 (缺参 → 引导补, 不算命中)
3. **阶段匹配**: 工具所属 设计/开发/测试/部署/运维 阶段对齐上下文
4. **权限**: Permission 校验 (无权限 → 拒绝, 不静默)
5. **LLM 兜底** (仅前 4 层未命中): LLM 从注册表选, 必须输出真实 tool_id

### 第三层 · 执行
Schema 校验 → Execute → 结果 + trace + 审计

## 工具元数据 (每个工具注册时必填)
```
{id, name, 阶段, 描述, 参数schema, trigger:{keywords[], stage, required_params[]},
 CLI入口, API端点, 会话意图, 执行函数}
```

## 示例
```
"把 语音记账 标记完成" → 关键词[标记完成] → task_action → PATCH 任务
"详细分析 P0 任务"    → 关键词[详细分析] → deep_analyze → scan+list_tasks(P0)+git
"推送到 github"       → 关键词[推送] → git_push → 确认后 git push
"给 旅行记账 加个导出" → 关键词[加个] → create_task
```
