# AI Software Factory — 30 分钟 Founder Demo 脚本

> 日期: 2026-08-07 | 场景: 面向独立创业者 (Solo Founder) 的首次产品体验
> 目标: 30 分钟内让 Founder 完成「提交真实任务 → AI 执行 → 审阅 → 采纳」全链路,
> 并量化价值 (时间/成本/替代率)。全程禁 mock / 禁预录 — 演示即真实执行。
> 两种模式: 模式 A (有 API key) 真实全链; 模式 B (无 key) 诚实演示就绪态 + BLOCKED 标注。

## 1. Founder 全链时间轴 (30 分钟)

| 时间 | 环节 | 演示动作 | 展示点 (Founder 应看到) | 模式 B (无 key) 替代动作 |
|---|---|---|---|---|
| 0:00 | 开场 | 一句话价值命题: "一个人拥有一个开发团队" | 产品定位清晰 | 同左 |
| 0:02 | 环境 | 展示 4678 tests 全绿 + benchmark 43 全绿 | 工程质量可信 | 同左 (真实测试输出) |
| 0:05 | 任务 | 打开样本列表 (9 个真实任务: 5 Bug + 3 Feature + 1 项目) | 任务真实来自生产项目 (markpad), 非玩具 | 同左 |
| 0:08 | 提交 | Founder 选 1 个 Bug 样本 (如: 表格 undo 样式丢失) | 自然语言任务 → 系统理解 | 展示样本 objective/requirement 纯自然语言, 无人工答案 |
| 0:10 | 预检 | runner --check | "✓ 就绪 / ✗ BLOCKED" 诚实输出 | 展示 BLOCKED 标注 + 解锁条件 (不假装) |
| 0:12 | 执行 | (模式 A) --run 真实调 LLM: 沙箱 → patch → verifier | 过程可见: 沙箱隔离、diff、验收判定 | 展示执行链代码路径 + 43 测试覆盖 (FakeProvider 仅测链路, 非能力证明) |
| 0:20 | 审阅 | 展示 patch diff + 执行报告 (7 指标) | Founder 审阅可读: 改了哪、为什么、成本 | 展示报告模板字段 (成本/耗时列标注"待真实数据") |
| 0:22 | 验收 | verifier 判定结果 (通过/失败 + 原因) | 客观验收, 不靠嘴说 | 展示 verifier 正反例测试 (不误杀/不误判) |
| 0:24 | 采纳 | Human Approval → 应用到沙箱副本 | 人工把关一键, 生产目录零修改 | 展示审批门设计 (沙箱铁律) |
| 0:26 | 量化 | 本任务: 耗时 / 成本 / 人工对比 (2-4h vs AI 分钟级) | ROI 公式代入首个真实数据点 | 展示 ROI 公式 (工时×费率×替代率−订阅), 数值标注待真实数据 |
| 0:28 | 扩展 | 展示 9 样本全列表 + 五维评分框架 | 能力范围真实 (能/不能边界) | 同左 |
| 0:30 | 收尾 | 总结: 就绪清单 + 唯一阻塞 (key) + 下一步 | Founder 明确: 价值 / 风险 / 决策点 | 同左 |

## 3. 成功标准 (本场 Demo 交付物)

```
1. Founder 完成 1 个真实任务全链 (模式 A) 或看到完整就绪+BLOCKED 证据 (模式 B)
2. 首个真实数据点回填 product-proof-report.md §4 (模式 A)
3. 阻塞点记录 ≥0 条真实条目 (模板留档)
4. 明确下一步: key 配置路径 + Benchmark 重跑命令 (一条命令)
```
