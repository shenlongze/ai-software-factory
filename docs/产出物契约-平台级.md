# 产出物契约（平台级）— Artifact Contract

> 日期: 2026-08-26 · 状态: Founder 确认开始 · 依据: "数据不同步/不能实时更新"——
> 根因是产出物无标准格式 + 无变更通知, 且是**全部项目**的平台级问题, 非单项目定制。

## 1. 问题定位（Founder 原话框架）

- "数据不同步" = **没有标准格式**（WebUI 按约定读, 但引擎没按约定写 → 读不到/读错）
- "不能实时更新" = **没有变更通知**（读到了也不刷新）
- 适用: **AI Factory OS 下全部被管理项目**（P-xxx / ai-factory-self / 未来新项目）, 统一生效, 无例外。

## 2. 平台承诺

> AI Factory OS 保证: 任何引擎写的**任何项目**产出物, 都符合统一标准、都可被 WebUI
> 可靠读取、变化都实时可见。漂移可被 `validate` 检出并显示在 board。

## 3. Manifest 注册表（权威清单）+ 固定文件名（默认约定）

**核心（Founder 2026-08-26 确认）**: 不能只留最新, **历史不能丢, 有历史有追溯**。
每个项目一份 `artifacts.manifest.json` —— "这个项目到底产出了什么"的**权威清单**:

```jsonc
{
  "schema_version": 1,
  "version": 3,                 // 项目产出物版本号 (每次写 bump — WebUI 轮询依据)
  "updated_at": "...",
  "artifacts": {
    "prd": {
      "type": "prd", "label": "需求文档", "kind": "md",
      "file": "PRD.md",          // 当前版本位置
      "version": 3,
      "producer": "product-pipeline",   // 谁写的 (追溯)
      "trace_id": "trace-...",          // K-4 链路追溯
      "created_at": "...", "updated_at": "...",
      "versions": [              // 历史链 — 不丢
        {"version": 1, "file": "history/PRD.v1.md", "created_at": "...", "trace_id": "..."},
        {"version": 2, "file": "history/PRD.v2.md", "created_at": "...", "trace_id": "..."},
        {"version": 3, "file": "PRD.md",            "created_at": "...", "trace_id": "..."}
      ]
    }
  }
}
```

- **历史保存**: `set_artifact` 更新前, 旧版归档到 `history/<名>.v<N>.<ext>` (git 友好可 diff)
- **追溯**: 每版带 producer / trace_id / created_at / updated_at
- **固定文件名 = 默认约定** (规范类型默认落 `PRD.md`/`product.json` 等), 但 **manifest 是权威**:
  路径可改、可多份、可版本化; WebUI 一律读 manifest 展示, 不靠文件名猜
- **代码**: 不进 manifest 逐文件 (代码归 git), 以 `deliverable` 类型指向仓库路径

### 规范类型默认文件名 (ARTIFACT_SCHEMA, 仅默认约定)

| type | 默认文件 | 说明 |
|---|---|---|
| product | `product.json` | 产品定义 |
| prd | `PRD.md` | 需求文档 |
| engineering | `engineering.json` | 工程计划 |
| plan | `plan.json` | 依赖计划 |
| tasks | `tasks.json` | 任务拆分 |
| execution_plan | `execution_plan.json` | 执行计划 |
| execution_state | `execution_state.json` | 执行状态 |
| validation | `validation_result.json` | 验证结果 |
| repair | `repair_task.json` | 修复任务 |
| quality | `quality.json` | 质量分 (可缺省) |

## 4. 统一写入口 `set_artifact(project_id, type, data, {producer, trace_id, file?})`

- 平台服务方法, **所有引擎**（产品管线/编排器/Codex/Hermes 执行链）写产出物只能走它
- 流程: 校验 type → **归档旧版到 history/** → 写当前文件 → **更新 manifest
  (版本链+producer+trace_id+时间戳)** → **bump 项目版本号** → 审计事件
- 禁止直接写产出物文件（存量/边界情况由 `validate` 暴露）

## 5. 变更信号（实时）

- 每次 `set_artifact` 成功 → `artifacts.meta.json` 的 `version+1`, `changed_at` 更新
- WebUI 打开任何项目 → 轮询 `GET /api/projects/{id}/artifacts`（manifest 视图,
  含 version/updated_at）; 版本变化 → 当前页自动刷新（项目首页已有 5/15/30/60s 刷新,
  推广到全部项目页）
- 版本内容: `GET /api/projects/{id}/artifacts/{type}/versions/{v}` (读历史, 可追溯查看)
- 可选增强: `artifact.updated` 事件进 SSE/审计流（K-4 trace 复用）

## 6. 校验（兜底, 扫全部）

- `factory artifacts list [<项目>]` — 项目产出物清单（存在/缺失/版本）
- `factory artifacts validate [--all]` — 遍历项目对照 schema 报: 缺失 / 漂移(文件在但
  非标准名) / 格式不兼容(schema_version) / 元数据缺版本
- board 开发者控制台展示"哪些项目符合标准、哪些漂移"

## 7. 存量迁移（不强制回写, 实事求是）

- 现有项目资产按契约视图读取（读不到 → 如实标缺失, 不伪造）
- `validate` 报漂移清单 → 逐项按优先级迁移到标准位置/格式（同 J-1 reconcile 模式）

## 8. 实施拆分

| 战役 | 内容 | 验收 |
|---|---|---|
| **C-1 契约地基**（本次） | schema 注册表 + set_artifact + version 信号 + GET /api/projects/{id}/artifacts + factory artifacts list/validate | 任意项目可读统一产出物状态; validate 报漂移; 版本变化可感知 |
| **C-2 引擎接线** | 产品管线/编排器/执行链改走 set_artifact（禁直接写） | 新产出全部带标准格式+版本; 审计事件 |
| **C-3 WebUI 实时** | 全部项目页轮询 version 变化自动刷新 + board 展示漂移 | 产出变化 30s 内可见; board 有契约健康视图 |

## 9. 验收标准（C-1）

- `factory artifacts list <项目>` 列出全部类型（存在/缺失/版本）
- `factory artifacts validate --all` 扫全部项目, 漂移如实列出, 0 崩溃
- `GET /api/projects/{id}/artifacts` 返回 {items, version, changed_at}（真实）
- set_artifact 落标准文件 + bump version（测试断言）
