# 会话系统综合诊断与解决方案

> 日期: 2026-08-28 | 版本基线: v1.1.224 | 依据: 三轮调研（Codex/Claude/Trae 架构对比 + 开源方案扫描 + 会话专项）
> 一句话结论: **会话架构方向已对（agentic 同款），不缺架构、缺工程部件。
> 四个根因：①弱模型天花板（不可改，只能缓解）②21 个静态工具全量塞给模型（可选错）
> ③跨会话无结构化交接（"继续做 XX"会断）④无会话生命周期 Hooks（压缩/结束不沉淀）。
> 解决方案按 P0/P1/P2 排，P0 三项做完，"新会话继续做 XX"就不再断。**

## 2. 问题根因分层（缺什么）

| 层 | 根因 | 症状（你遇到的） | 可改吗 |
|---|---|---|---|
| **模型层** | DeepSeek 语义/推理弱于 GPT-5.2/Claude，是天花板 | 所答非所问、get 不到意图、答非所问 | ❌ 不可复用，只能缓解 |
| **工具层** | **21 个静态工具每次全量塞给模型**，弱模型选择压力大 → 选错/漏选 | 明明有 read_code 却去读文档；扫代码返回文档数据 | ✅ 动态工具发现 |
| **上下文层** | 跨会话只有"最近 N 条记忆"注入，**无结构化交接**（没有 Spine/Resume Point/Closure） | "继续做 XX"找不到上次进展；上下文断裂 | ✅ 交接协议 |
| **生命周期层** | **无会话级 Hooks**（SessionStart/PreCompact/SessionEnd 无钩子） | 压缩前后不交接、会话结束不提取决策/教训 | ✅ 会话 Hooks |
| **记忆层** | 记忆无类型（decision/learning/error）、无权威分层 | AI 摘要被当成事实；错误反复踩 | ✅ 类型化+权威 |
| **交互层** | 执行过程只到"工具徽章"，非流式 | 看不到"正在干嘛" | ✅ 流式展示 |

## 5. 总体判断

1. **架构方向已对**：agentic 自主循环 + Reflection + 硬收敛，与 Codex/Claude 同款，不需要推翻。
2. **缺口是工程部件，不是架构**：全部有开源答案，按 P0 三项（动态工具 + 交接协议 + 会话 Hooks）做完，体感就会明显变化。
3. **模型是唯一硬约束**：以上所有缓解都建立在 DeepSeek 上；若换强模型，同样的机制收益会更大（机制已就位）。
4. **保持工厂定位**：不抄"单 agent 聊天框"，做"工厂控制台 + 员工池"——外部委派/审计/治理是差异化。

## 6. 建议验收口径（做完 P0 后）

- 新会话说"继续做 XX" → 自动定位任务 → 展示上次进展到哪 + 下一步（T-6/T-8）
- 说"扫代码/看代码逻辑" → 必调 read_code 真读代码（不再返回文档）（工具层）
- 说"扫描项目" → 必调 project_scan 带证据数字（不编造）
- 会话压缩后 → 回来还能接上（PreCompact 交接）
- 会话结束 → 决策/错误→解法自动沉淀，下个会话可用（SessionEnd 提取）
