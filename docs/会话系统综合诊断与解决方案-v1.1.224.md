# 会话系统综合诊断与解决方案

> 日期: 2026-08-28 (v2 修订) | 版本基线: v1.1.224 | 依据: 三轮调研（架构对比 + 开源扫描 + 会话专项）+ 模型接入代码审计
> 一句话结论: **会话架构方向已对（agentic 同款），不缺架构、缺工程部件。
> 根因五条：①会话链路硬编码 DeepSeek 且未接已有模型路由（模型是变量，不是天花板）
> ②21 个静态工具全量塞给弱模型（可选错）③跨会话无结构化交接（"继续做 XX"会断）
> ④无会话生命周期 Hooks（压缩/结束不沉淀）⑤prompt/harness 负担过重，没为弱模型优化。
> 解决方案按 P0/P1/P2 排；P0 四项（模型无关适配 + 动态工具 + 交接协议 + 会话 Hooks）做完，
> 换模型只改配置，"新会话继续做 XX"不再断。**

---

## 0. 模型层修正（重要）

**"模型是天花板改不了" — 表述错误，已修正。**

事实核查（代码审计 v1.1.224）：
- 会话链路 `agent_loop.call_with_tools` **硬编码 OpenAI 兼容 function calling 形状**，且只取 `providers.json` 第一个 enabled provider（默认 deepseek-chat），**没走已有的 `LLMRouter`（分层路由 L1-L5）和 `ModelCatalog`（能力注册/协商）**。
- 系统已有 `llm_router.py` + `model_catalog.py` + `api/providers.py`：已注册 deepseek / openai / anthropic(claude) 等多 provider，有 capabilities / context_window / 路由分层 —— **只是会话链路没接上**。

推论：
1. **DeepSeek 网页版好用 ≠ 我们"差"在模型**。网页版是纯对话、零工具面、零复杂指令；我们的"差"一半是 harness 侧可改的：21 工具全量塞、超长系统提示（铁律+Reflection+style+verify 堆叠）、无动态工具、上下文噪音。
2. **模型是变量，不是固定天花板**。换强模型收益更大；换弱模型也能靠 harness 缓解（动态工具/精简 prompt/更严收敛）。
3. **换其他模型怎么办 = 模型无关架构**（见 P0-1），不是重写。

## 5. 总体判断

1. **架构方向已对**：agentic 自主循环 + Reflection + 硬收敛，与 Codex/Claude 同款，不需要推翻。
2. **模型是变量，不是天花板**：换模型 = 改配置 + 适配层（P0-1）；弱模型可被 harness 缓解（动态工具/精简 prompt）。
3. **缺口是工程部件，不是架构**：全部有开源答案或已有基础（LLMRouter/ModelCatalog 现成，只差接线）。
4. **保持工厂定位**：不抄"单 agent 聊天框"，做"工厂控制台 + 员工池"。

## 6. 建议验收口径（做完 P0 后）

- 设置里切换模型（deepseek/openai/claude/gemini）→ 会话立即生效，不挂（P0-1）
- 新会话说"继续做 XX" → 定位任务 → 展示上次进展 + 下一步（P0-3）
- 说"扫代码/看代码逻辑" → 必调 read_code 真读代码（P0-2）
- 说"扫描项目" → 必调 project_scan 带证据数字（P0-2）
- 压缩后回来接得上；会话结束决策/教训自动沉淀（P0-4）
