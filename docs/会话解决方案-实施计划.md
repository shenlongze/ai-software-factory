## P0-1 模型无关适配（地基, 2-3 天）

**目标**: 设置里切换模型（deepseek/openai/claude/gemini/ollama）→ 会话立即生效, 不挂; 无 FC 能力模型自动降级。

**现状问题**:
- `agent_loop.call_with_tools` 硬编码 OpenAI 兼容形状 + 只取 providers.json 第一个 enabled provider
- 未走已有 `LLMRouter.route()`（L1-L5 五层决策）与 `ModelCatalog`（capabilities/context_window）

**改动点**:
1. 新建 `factory-console/session/llm_gateway.py`
   - 统一内部消息/工具形状（OpenAI 形状为内部标准）
   - Provider 适配器注册表: `openai_compat`（deepseek/openai/moonshot/kimi/ollama 兼容端点）/ `anthropic`（Messages API tool_use → 内部形状）/ `gemini`（functionCall → 内部形状）; 新 provider = 加一个适配器, 不改主循环
   - 能力协商: 读 `ModelCatalog.get_model(model_id).capabilities` → 支持 fc? tool_search? context_window? → 降级路径（无 fc → 现有 prompt 套 JSON 兜底）
2. 改 `agent_loop.call_with_tools` → 调 `llm_gateway.complete(messages, tools, *, model_choice, ...)`
   - `model_choice` 来自 `LLMRouter.route(explicit_provider, explicit_model, project_dir, required_capabilities=["fc"])`
   - explicit_provider/model 从会话上下文/设置传入（复用现有设置模型选择）
3. 保留 `_simple_llm` 兜底（网关异常 → 诚实 rejected 回退）

**验收**:
- providers.json 增加 anthropic provider + key → 会话用 claude 跑通 FC（工具调用正常）
- 设置切换模型 → 会话立即用新模型（deepseek↔openai↔anthropic）
- 无 FC 模型 → 不挂, 走 prompt 套 JSON 降级
- 回归: 现有 deepseek 会话测试 `test_real_conversation.py` 全过

## P0-2 BM25 动态工具发现（1-2 天）

**目标**: 21 个工具不再全量塞给模型; "扫代码/扫描项目"必调对工具。

**改动点**:
1. 新建 `factory-console/session/tool_search.py`
   - `catalog_summary()`: 工具名+一句话分组目录（~400 token）
   - `discover_tools(query, top_k=5)`: BM25 打分（零依赖纯 stdlib: camelCase/snake_case/下划线分词 + 词频评分, 参考 tool-search-oss MIT）
   - `tool_search(query, max_results)` 元工具 schema
2. 改 `agent_loop.tool_schemas()`:
   - 首轮只返回: catalog 提示 + 静态核心工具（read_code/project_scan 等少量）+ `tool_search` 元工具
   - 模型调用 tool_search 命中后 → 累积把命中工具加入可见列表（Eino"累积可见"模式）; 或简版: 按会话首轮意图 query 预检索 top-N
3. `dispatch()` 不变（按工具名执行）; 外部能力 delegate_external 也纳入可搜索范围

**验收**:
- 说"扫描项目" → 模型只看到 project_scan 相关 3-5 个工具, 必调 project_scan
- 说"查看架构设计" → 必调 read_code(目录)
- 工具 schema token 占用可测下降（会话 audit 里记 tool_catalog_bytes）

## P0-3 跨会话交接协议（2-3 天）

**目标**: 新会话"继续做 XX" → 定位任务 → 注入"上次进展到哪 + 下一步"; 直接落地 T-4/T-6/T-8。

**改动点**:
1. 新建 `factory-console/session/handoff.py`（对标 Project Continuity Spine, MIT 设计借鉴）
   - `ProjectSpine`: `current_goal` / `active_requirements` / `handoff_card`（交接面: 上次进展+下一步+阻塞）/ `resume_point`（引用 exec_state checkpoint）/ `closure_memory`（已归档任务的压缩记忆）/ `source_pointers`（证据文件路径）
   - **权威分层**: 每条状态带 `source` 等级 `user_intent > verified_state > repo_evidence > agent_claim > summary`; 读取按等级过滤, 低等级不作事实
   - 落盘 `<data_dir>/project_spine/<project_id>.json`; 项目扫描/任务变更时更新 verified_state
2. `project_memory.py` 升级: 记忆分 5 类（decision/learning/error/pattern/observation）+ source 等级 + 时间衰减（参考 passbaton）
3. `task_continue` 工具改造: 定位任务 → 读 Spine → 注入 handoff_card + resume_point
4. `run_agent` 首轮注入: 新会话带 Spine 视图（handoff_card + closure_memory 摘要）, closure-over-replay（不重放旧聊天）

**验收**:
- 会话 A 把任务做到一半（exec_state 有 checkpoint）→ 新会话 B 说"继续做 XX" → 能说出进展+下一步
- 归档任务的 Closure Memory 以摘要检索, 不占活跃上下文
- 低等级记忆（agent_claim/summary）明确标注, 不被当事实

## P0-4 会话级 Hooks 生命周期（2 天）

**目标**: 压缩前交接、会话结束沉淀; 与工具级 Hooks 合并成双层。

**改动点**:
1. 新建 `factory-console/session/session_hooks.py`
   - 事件: `SessionStart` / `UserPromptSubmit` / `PreToolUse` / `PostToolUse` / `PreCompact` / `SessionEnd`
   - hook 注册表: 每个 hook 为 Python 函数, 可返回 deny+reason 或注入内容（参考 Claude Hooks 事件模型 / passbaton 5 hooks）
2. 内置 hooks 接线:
   - `SessionStart` → 注入 Spine handoff_card + 最近 decision/error→solution
   - `PreCompact` → 生成结构化交接写入 Spine（当前任务/进展/阻塞/下一步）
   - `SessionEnd` → 从对话提取 decision / error→solution / rule → 写 project_memory（5 类）
   - `PreToolUse` → 敏感动作门（建任务/改任务/委派/推送需审批, 已有逻辑挂进来）+ 审计
3. 暴露到 `run_agent` 生命周期调用点

**验收**:
- 触发压缩前 → Spine.handoff_card 自动更新; 压缩后回来接得上
- 会话结束 → 决策/错误→解法自动沉淀, 下个会话 SessionStart 可用
- PreToolUse deny 生效（如"删除"类动作被拦）; 审计记录事件
