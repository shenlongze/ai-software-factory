## 背景（实事求是）

| 层 | 现状 |
|---|---|
| 角色定义 | ✅ 7 个（pm/market/competitive/ux/architect/qa/prd）— expert_factory.py ROLE_DEFINITIONS |
| Agent 实体 | ✅ 7 个（pm-agent/architect-agent/qa-agent/frontend-agent/backend-1/flutter-dev/tester-1）— agents.json |
| Skill 资产 | ⚠️ **仅 1 个**（flutter）— skills.json |
| 装配 | ⚠️ 缺 skill → 确定性兜底（模板级产出） |

**结论**: 角色和员工都有, 但"专业能力（skill）"几乎没配 — 这就是 ux/qa 还是占位模板、
pm/prd 是规则级的原因。M3-5（Hermes 已做）深化了角色产物, 但 skill 资产仍需补齐。

---

## 短期 A-1: 补齐 7 角色 Skill 资产（P1）

**目标**: 7 角色需要的 skill 定义补齐, 装配走真 skill 而非兜底。

| 角色 | 需要 skill（建议） |
|---|---|
| pm | product_management, market_research |
| market | market_research, industry_analysis |
| competitive | competitive_analysis |
| ux | ux_design, ui_design |
| architect | software_architecture, system_design |
| qa | software_testing, test_planning |
| prd | product_documentation, requirement_analysis |

**实现**: `factory skill add --id product_management --name ... --category ...` × N
（或批量脚本）→ skills.json 注册 → ExpertFactory.assemble 校验通过 → 真 skill 装配。

**验收**:
- [ ] skills.json 含 7 角色所需全部 skill（≥7 个）
- [ ] ExpertFactory.assemble(role) 不再报"缺 skill"（7 角色全可装配）
- [ ] 装配产物质量: ux/qa/prd 从模板 → 真产出（配合 M3-5）

---

## 中期 A-2: board "员工管理" tab（P1）

**目标**: board 加"员工管理"视图 — Agent/Skill 列表、角色定义、装配状态、skill 缺失提示。

**规格**（复用 v1.1.78 命令 + API）:
- Tab: board 导航加"👥 员工"（与 📋 AI主线 并列）
- 内容:
  - Agent 列表: id/name/role/skills/装配状态（✅可装配 / ⚠️缺skill: x）
  - Skill 列表: id/name/category/version（内置 + 注册）
  - 角色定义: 7 角色 × skills × 现状（真引擎/规则/占位 — §4.10.2）
  - skill 缺失提示: 每角色缺哪些 skill → 一键补全建议
- 数据源: agents.json + skills.json + ExpertFactory.assemble 校验
- API: GET /api/agents + GET /api/skills（已有）→ 前端渲染

**验收**:
- [ ] board 员工 tab 显示 7 Agent + N Skill + 角色装配状态
- [ ] skill 缺失可见（如 ux 缺 ux_design → 提示）
- [ ] 只读展示（管理动作走 CLI 命令, 面板不直接写）
