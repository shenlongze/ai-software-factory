# 开源方案调研 — 会话专项：连续性 / 记忆 / 多议题分段 / 压缩

> 日期: 2026-08-28 | 范围: 全网（GitHub/Gitee/论文）聚焦**会话本身**：
> 跨会话连续、会话记忆、话题分段、上下文压缩、会话生命周期 Hooks。
> 结论先行: **多议题分块（TopicLedger）我们已有同款；最缺的是"跨会话结构化交接协议 + 会话级 Hooks 生命周期 + 分层上下文加载"三块，均有开源答案可直接借鉴。**

---

## 0. 我们现状（v1.1.224）

| 已有 | 位置 | 说明 |
|---|---|---|
| 话题账本分块 | `topic_ledger.py` (v1.1.211) | LLM 延续判断 + 显式切换/切回 + running summary + 滚动压缩 |
| 跨会话记忆 | `project_memory.py` | MemoryStore: add/recent/inject_block（简单文本，无类型） |
| 执行状态机 | `exec_state.py` | chain_start/next/status（跨会话续跑的基础） |
| 会话审计 | `session_audit.py` | 会话级可观测 |

**缺口**（对应用户 T 系列 P0：跨会话恢复/任务↔会话追溯/继续意图）：
1. 跨会话"交接"没有结构化协议（现在只有最近 N 条记忆注入）
2. 无会话级 Hooks 生命周期（SessionStart/PreCompact/SessionEnd 无钩子）
3. 上下文是"摘要+最近2条"两级，无 L0/L1/L2 分层按需加载
4. 话题分段靠 LLM 二分类（慢/贵），无语义向量快路径
5. 记忆无类型（decision/learning/error/pattern），无权威分层

## 5. 会话生命周期 Hooks（与上一轮 Hooks 层合并）

- **passbaton 5 hooks**（SessionStart/UserPromptSubmit/PostToolUse/PreCompact/Stop）→ 定义我们会话级事件
- **Claude Hooks 事件模型**（PreToolUse/PostToolUse/Notification/Stop）→ 工具级事件（上轮已列）
- 两者合并即"会话级 + 工具级"双层 Hooks，直接支撑：压缩前交接、结束提取、错误→解法、开始注入

## 6. 落地建议（会话专项，按性价比）

| 优先级 | 做啥 | 依据 | 预估 |
|---|---|---|---|
| **P0** | **跨会话交接协议**（对标 Project Continuity）：Spine 结构（当前目标/有效需求/交接面/Resume Point/Closure Memory）+ 权威分层 + 新会话"继续 XX"走 Spine 注入 | 直接完成 T-4/T-6/T-8；权威分层解决"摘要当事实" | 2-3 天 |
| **P0** | **会话级 Hooks 生命周期**：SessionStart 注入 / PreCompact 交接 / SessionEnd 提取（决策/错误修复/规则） | passbaton 5 hooks 模型照抄；与上轮工具级 Hooks 合并 | 2 天 |
| **P1** | **TopicLedger 加语义快路径**：embedding split_by_topic，LLM 兜底 | semantic-router 思路 | 1 天 |
| **P1** | **记忆类型化 + 权威分层**：project_memory 分 5 类（decision/learning/error/pattern/observation）+ 来源分级（用户>验证>证据>claim>summary） | passbaton 分类 + Project Continuity 权威 | 1-2 天 |
| **P1** | **分层上下文加载 L0/L1/L2**：context_builder 按任务深度取摘要/概览/详情 | OpenViking 设计（AGPL 只借鉴不并入） | 2 天 |
| **P2** | 压缩哲学升级：保留 lesson/rule/relationship | mosaic-memory-compress | 1 天 |

## 7. 结论

- **多议题分块已有同款**（TopicLedger）；不必重造。
- **三个真缺口**：①跨会话结构化交接（Project Continuity 协议，MIT 可直接设计借鉴）；②会话级 Hooks 生命周期（passbaton 模型）；③分层上下文加载（OpenViking L0/L1/L2）。
- 与 T 系列 P0 完全对应：**跨会话交接协议 = T-4/T-6/T-8 的主干**；Hooks = 压缩交接/结束提取的载体。
- 建议先做 **P0 两项**（跨会话交接 + 会话级 Hooks），做完"新会话继续做 XX"就不再是断的。
