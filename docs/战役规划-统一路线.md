## 2. 战役详情

### K-1 能力路由 + 员工管理（P1, 起点）
- **价值**: 回答 Founder 核心问题"拥有同样技能的多个 skill / agent / mcp 如何分配调用"——
  建立任务→能力→资源的确定性匹配规则 + 管理入口。
- **构成**: B-1 skill 路由 · B-2 agent 路由 · B-3 mcp 路由 · B-4 统一能力路由层 ·
  A-2 board 员工 tab（Agent/Skill 列表/装配状态/缺失提示）· A-3 MCP 管理命令+API · F-4 提示词版本管理
- **依赖**: 无（A-1 skill 补齐 ✅ 已就绪）
- **验收**: 同技能多资源可解释选择（确定性规则 + 显式优先级）; 任务→能力→资源全链路可追踪;
  board 员工 tab 可见装配状态与缺失提示; MCP 管理 CLI + API 可用; 契约测试 ≥10
- **体验补充 (S10-118, v1.1.87 ✅)**: 发现对话上下文保持 (逃生挂起) + 委托/求助口语全覆盖
  (把控/给我一点建议) + LLM 失败响亮报错 (网络/超时/限流/5xx) — 归入 K-1

### K-2 执行质量分 + 优选（P1, 依赖 K-1）
- **价值**: 回答"选中 agent 执行任务但没通过质量评测怎么办"——打分、优选、失败策略。
- **构成**: C-2 执行质量分 · C-3 T5.3 优选启用 · B-5 执行质量评估闭环（复用 M5-1 重放基础 ✅）· B-6 PRD/计划质量评估
- **依赖**: K-1（路由能读取质量分）
- **验收**: 每次执行产出质量分; 优选规则按分排序可解释; 低分走失败/重试策略; 分数落盘可审计

### K-3 学习闭环（主线 M4, P1, 依赖 K-2）
- **价值**: "让 Agent 变强且可控"——第二次同类任务引用第一次经验。
- **构成**: M4-1 经验→画像→决策引用→评价回写 · M4-2 学习护栏（开关/样本可信度/预算上限/回滚）·
  M4-3 决策记忆回流 E5 · M4-4 成本自动告警闭环 · M4-5 画像优先分配 · B-7/E-1 经验回写 · D-6 成本可视化 · E-2 修复深化 · E-3 优化完善
- **依赖**: K-2（质量分是学习样本）
- **验收**: 同类任务第二次引用第一次经验（可断言）; 护栏: 低样本不主导/超预算阻断; 成本告警闭环;
  M4 主线 6/6 ✅

### K-4 trace_id 贯穿（P1, 成本低收益高）
- **价值**: 审计/评测/链路可视化的地基（实测 2408 条全空）。
- **构成**: I-1 trace_id 一次请求全程贯穿 · F-9 日志 trace 落盘
- **依赖**: 无
- **验收**: 一次请求全链路同 trace_id; 审计可按 trace_id 追踪; 契约测试断言非空

### K-5 评测体系（渐进, P1, 依赖 K-4）
- **价值**: 每完成一个战役就用评测背书, 回答"质量体系完整/可靠/可信吗"。
- **构成**: P0-1 七维评测 · P0-4 长跑+并发 · P0-5 发布门（patch=L0, minor=L0+L1）·
  C-1/C-4/C-5/C-6 · H-1 整体流程评测 · F-10 测试覆盖度 · M5-7 错误码表+契约测试整体落地
- **依赖**: K-4（信赖评测需要 trace）
- **验收**: 每版本按等级跑评测; 七维第一版可出分; 发布门自动化; 错误码表全量

### K-6 项目级 RAG（P1, 依赖文档管理 ✅）
- **价值**: 项目知识可检索、可复用（"问得深但不懂行业"→ 行业知识库的起点）。
- **构成**: M5-2 KnowledgeStore + 自建 DB/向量 + RAG 分档 · M5-3 外挂适配器（企业 Postgres/向量库/知识库）·
  B-8 项目级 RAG · F-11 项目知识沉淀 · E-5 检索回路
- **依赖**: board 文档管理（已就绪, 多目录+文件树+搜索）
- **验收**: 项目文档可检索问答; 分档命中可解释; 外挂适配器可配置

### K-7 Web 产品化（P2, 依赖内核稳定）
- **价值**: 把内核能力暴露给真人用（"现在只是 CLI/board, 不是产品"）。
- **构成**: M5-6 Web 入口打通（React 壳→内核）· G-1 Web 产品壳 · G-2 Web 发现对话 · G-3 Web 项目管理 ·
  G-4 Web 执行审批 · G-5 Web 员工管理（依赖 A-2）· G-6 与 board 统一
- **依赖**: 内核 API 稳定 + K-1（员工管理）
- **验收**: 创建项目→发现→PRD→工程→审批→执行全流程 Web 可用; 与 board 同数据源

### K-8 链路 / 审计 / 治理（P2, 依赖 K-4）
- **价值**: 回答"调用链路是否清晰可控""项目是否可控/审计/治理"。
- **构成**: I-2 链路可视化 · I-3 链路可控（暂停/拦截/重试/回退）· H-2 项目可控 · H-3 审计深度 · H-4 治理深度

## 3. 执行规则

1. **一次一个战役**: 每个战役 = 一个 Hermes Sprint 链（可拆多个 S10-xxx）, 独立验收, 通过才进下一个
2. **渐进评测**: K-5 不是最后才做——K-1 起每个战役交付时附带对应评测项（K-5 只做体系化收口）
3. **主线同步**: K-3 完成 = M4 主线 ✅; K-6 完成 = M5 大部分; board 主线进度随战役推进实时更新
4. **防遗漏**: 战役合并不删旧编号（待办清单 A~J/M 保留）; 写点/注册表改动受 P0-10/11 门禁保护
5. **实事求是**: 每个战役验收标准都是可断言结果, 不接受"做了但没法证明"
