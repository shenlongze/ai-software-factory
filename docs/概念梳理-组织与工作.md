## 一句话结论

**「组织」与「工作」是两套正交维度**，不是严格父子（`原文`：方案书 L235-238，2026-08-24 Founder 澄清）。
「工作空间」**不在这两棵树里** —— 它是**项目之上的一层分组视图**（另一套东西）。
「工作目录」**也不在这两棵树里** —— 它是**会话里选中的某一个项目**（2026-09-25 新做）。

---

## 一、两棵正交的树（`原文` L241-243）

```
 组织树（回答"归属谁"）              工作树（回答"做什么"）
 ────────────────────────            ────────────────────────
 集团 Group（可选, 预留 Phase 21+）   项目 Project
   │                                    │  ← 拆解（M3）
   └─ 公司 Company                      └─ 任务 Task
        │                                   │  ← 细拆
        └─ 部门 Department（可选）           └─ 叶（叶子任务 = 派活的最小单位）
                                            │  ← 执行
  ★ Solo 模式: 公司/部门都可无              └─ 执行 Execution（EXR-xxx）
    项目**不挂在部门下** ⇒ 直接建项目即可（`原文` L249）
```

**关联（谁负责）**（`原文` L243 · L256-262）

```
 Project.company_id      归属公司（可选）
 Project.department_ids  多对多（可选）⇒ 一个项目可多部门协作 · 一个部门可多项目
 ⇒ 实现核对 ✓: department_ids 是**列表** ✓（services/organization/project_adoption.py:264）⇒ 与原文一致 ✓
```

## 三、三条最容易混的边界（务必记牢）

```
 1) 工作空间 ≠ 工作目录（不同层级, 别混 ✗）
      工作空间 = 装**多个项目**的容器 + 跨项目运营视图（dashboard --workspace ✓）
      工作目录 = 会话里选**某一个项目**（/project 2 ✓）⇒ 之后的命令只针对它 ✓

 2) 组织树 ≠ 工作树的父子关系（是**正交 + 关联** ✓ `原文` L238）
      项目**不是**部门的子节点 ✗ ⇒ 项目可以没有公司/部门（Solo ✓）
      要"归属"是**加关联**（Project.company_id / department_ids ✓）不是搬位置 ✓

 3) 部门是**可选**的（Solo 扁平 ⇒ 零配置 ✓ `原文` L249-250）
      前期「我想做个记账 App」⇒ 直接建项目 ✓；
      后期「成立公司, 记账户归财务部」⇒ 建 Company + Department ⇒ **关联**过去，**数据不动** ✓
```
