# AI Factory OS 能力地图：能做什么 · 能查看什么 · 能控制什么

> Founder 2026-09-26 问：「我能使用 AI Factory OS 做什么，查看什么，控制什么？」
> 本文**全部来自实测**（命令名单取自 `_top_command_names()`，行为逐条真跑过 ✓）· 不凭记忆 ✗

---

## 〇、一句话

**一个入口（会话）· 三类动作**: ① 让它**做**（造东西 / 改状态）② **查看**（只读）③ **控制**（批准 / 编排 / 策略）。
没写在本文里的，就是**还没做到**（见第五节 ✓ 我不编 ✗）。

---

## 一、能"做"（产生东西 / 改状态）

| 做什么 | 命令 | 说明 |
|---|---|---|
| 建组织 | `create company \| department \| project \| task` | 公司/部门/项目三层都能建（部门可选 ✓ Solo 零配置 ✓）|
| **需求 → 全链** | `chain "需求原话" --project P-…` | 一条命令跑完：会话 → 理解 → PRD → 分析产物（产品定义/交互/架构）→ 任务树 → 细拆 ✓ |
| 读代码库出事实 | `understand <目录>` | 把仓库读成"事实" ✓ |
| 舰队归属 | `org member set --company C-…` | 派活**按公司归属筛人** ✓ |
| 加/派/收员工 | `agent add \| assign \| release` | 注册 Agent 进舰队（`agents.json` ✓）|
| 配运行时 | `provider add` | 交互式配模型（选类型→贴 key→试连→落库 ✓）|
| **真执行** | `run --plan PLAN-… --project P-… --limit N --parallel M` | 派活 → agent 在**项目仓库**里改代码 → **自己提交** ✓ |
| 修卡住 | `recover --plan PLAN-…` | 把卡死的**认领**交回（`run` 起手也会自动做 ✓）|
| 出产物 | `product develop \| ux \| breakdown` | 让 PM/UX agent 出产物 ✓ |
| 备份/恢复 | `backup create \| list \| restore` | 数据目录级 ✓ |
| 升级/初始化 | `update` · `init` | ✓ |

| 看什么 | 命令 | 说明 |

| **跨项目运营** | `dashboard --workspace` | Workspace Summary 六面板 ✓（自动发现项目 ✓）|
| 项目详情 | `project show <项目>` | 四段：项目情况 / 任务情况 / **文档情况** / 团队与能力 ✓ |
| **项目文档** | `project docs <项目> [--show prd\|product\|design\|ux_ui\|facts]` | 列文档 + **打出内容** ✓（2026-09-25 新加 ✓）|
| 项目清单 | `project list` | 带**说明（需求原话）** ✓ 按他的话也能认出项目 ✓ |
| 任务树 | `tasktree list \| show \| todo \| flow \| dataflow` | 清单 / 全貌（依赖+验收）/ **人话待办** / **功能链路图** / **数据流程图** ✓ |

| 审计 | `event` · `history` · `evd` · `verification` | 事件流 / 历史 / 证据 / 验证 ✓ |
| 组织 | `org member list` · `agent list \| assignments` | 成员归属 / 舰队 / 派工 ✓ |
| 知识与经验 | `knowledge` · `memory` · `intelligence experience` | 事实 / 记忆 / 经验库 ✓ |

| 环境健康 | `validate` · `arch` · `verification` · `plugin list` · `tool` · `runtime` · `llm` · `checkpoint` | 自检 / 架构 / 插件 / 工具 / 运行时 / 模型 / 检查点 ✓ |

## 三、能"控制"（改行为 / 策略 / 批准）

| 控制什么 | 命令 | 说明 |
|---|---|---|
| **批准门** | `approval [<id>] [approve\|reject]` | 会改数据的命令**必须你点头**才跑 ✓ |
| 会话权限三档 | 会话里 1/2/3 档 | 只读直接跑 / 写命令挂起 / 全放开 ✓ |
| 任务树编排 | `tasktree edit`（标题·验收·人话名·依赖·**删节点**·指派）· `expand` / `decompose`（拆）· `confirm`（**人工门**）· `translate`（改名）· `declare`（声明读写数据）| 树是**你可编辑的** ✓ |
| 优先级 | `tasktree priority` | 人工 > 产线声明 > 自动 ✓ |
| 指派角色 | `tasktree staffing` | 调度器按**成员角色**匹配 ✓ |
| 挂流程 | `tasktree workflow` | 挂了 ⇒ 叶按步骤推进，走完才算完成 ✓ |
| 舰队调度 | `agent assign \| release` | 谁在做 / 放回池 ✓ |
| 模型与供应商 | `llm` · `provider` | 换模型 / 加 provider ✓ |
| 企业与空间 | `org` · `workspace init \| show` | 组织与统一入口 ✓ |
| 数据安全 | `backup create \| list \| restore` | ✓ |

## 四、会话里（唯一入口 ✓ 不用记命令）

- **说人话** ✓ 只读命令**自动跑** ✓ 会改数据的命令**念给你、点头才跑** ✓
- **工作目录**（2026-09-25 新加 ✓）：
  「**进入飞机大战项目**」⇒ 进入 ✓（之后只读命令默认只跑它 ✓）；「**退出工作目录 / 回到全局**」⇒ 退出 ✓
  · 项目名对不上你的叫法时，按**说明（需求原话）**匹配 ✓（说"飞机大战" ⇒ 找到 plane-shooter ✓）
- 「第一次用」六步写在 `factory help` 里 ✓
