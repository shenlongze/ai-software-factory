> 入口: 待办清单 §能力缺口与深化（B-1~B-8）· board 周边任务可见
> 规则: 每个新发现的能力缺口/遗留问题 → 记入本清单 + 待办清单 B 系列

## B-1 Skill 路由（同技能多 skill 分配）

- **现状**: skill 已注册 + 装配校验 + 执行注入（v1.1.82 真调用）; 但 Agent 执行时
  把**全部 skills 注入 prompt**, 不选
- **缺口**: 多个 skill 含同一技能时, 无"调用哪个"的分配机制
- **建议**: skill-aware 选择（任务技能需求 → 匹配 skill 版本/优先级/匹配度）
- **状态**: ⬜ 待做

## B-2 Agent 能力路由（相似能力 agent 选择）

- **现状**: `select_agent` 按 objective 关键词（前端→flutter-dev, 其余→backend-1）
- **缺口**: 相似能力 Agent 谁执行 — 不看能力覆盖度/负载/画像
- **建议**: skill-aware select_agent + 负载均衡（M4-5 前置）
- **状态**: ⬜ 待做

## B-3 MCP 路由

- **现状**: `factory tools list/doctor` 只有发现
- **缺口**: "任务需要某工具 → 选哪个 MCP" 无路由
- **建议**: MCP 能力声明 + 路由（A-3 关联）
- **状态**: ⬜ 远期

## B-4 统一能力路由层（Capability Router）

- **现状**: agent/skill/mcp 各自为政, 都"有注册无路由"
- **缺口**: 无统一"任务能力需求 → 资源匹配"机制
- **建议**: CapabilityResource{id,type,capabilities,status,load} + CapabilityRequest →
  匹配（复用 select_agent/ExpertFactory/tools）
- **状态**: ⬜ 待做（B-1/B-2/B-3 的统一底座）

## B-5 执行质量评估闭环（打分/优选/失败策略）

- **现状**: 执行结果只有 pass/fail; T5.3 多候选优选默认关; 失败只重试(≤2 轮);
  **M5-1 已补重放/对比基础**（v1.1.82: dry-run/re-exec/对比报告）
- **缺口**: 无执行结果**质量分**; 无多 Agent 优选; 失败不换资源/不诚实报分
- **建议**: Execution Quality Loop（复用 M3d 六维思路 → 执行结果评分 → 优选 →
  重试→换Agent→诚实报告; 重放/对比已就绪）
- **状态**: ⬜ 待做（重放基础 ✅, 评分/优选/失败策略待做）

## B-6 PRD/工程计划质量评估

- **现状**: M3d 评"拆解"质量; PRD/工程计划无评分
- **缺口**: 产出的 PRD/计划好不好没人打分（质量门控缺执行侧）
- **建议**: 复用 M3d 评估器思路扩展到 PRD/计划
- **状态**: ⬜ 待做

## B-7 M4-1 经验回写闭环

- **现状**: 记忆基础有（experience_store/检索）, 但"执行完→经验入库→下次引用"断
- **缺口**: Agent 用完即弃, 不成长
- **建议**: 执行结果/质量分 → 经验回写 → 画像 → 下次路由引用（M4 核心）
- **状态**: ⬜ 待做

## B-8 项目级 RAG

- **现状**: 文档管理完善（多目录+扩展名+文件树+搜索）, 但只能浏览/搜索
- **缺口**: 不能检索问答（"文档里有没有讲 X"答不了）
- **建议**: M5-2 KnowledgeStore + 向量检索（索引已就绪）
- **状态**: ⬜ 待做
