## 2. 系统结构（真源：`docs/ssot/architecture.md`）

七层，**依赖方向单向向下**：

| 层 | 职责 | 允许依赖 |
|---|---|---|
| `contracts/` | 全部跨层契约（dataclass / Enum / Protocol），无逻辑无 IO | 仅标准库 |
| `core/` | 平台本体：**scheduler**（下一步是谁）+ **events**（发生了什么），仅此两段 | `contracts/` |
| `services/` | 业务域服务（每域：service / store / rules / events / contracts） | `contracts/` |
| `plugins/` | 一切实现绑定（factories / agents / skills / tools / models / connectors / controllers / healers / notifiers / storages） | `contracts/` |
| `infrastructure/` | 技术底座（llm / storage / messaging / process / sandbox） | `contracts/` |
| `api/` | 对外接口层 —— **已删，待从 CLI 命令定义重建**（不是现役 ✗） | `contracts/` + `services/` |
| `bootstrap/` | 装配与启动（**唯一可 import 全部**） | 全部 |

CLI 侧：`apps/cli/main.py`（解析）+ `registry.py`（登记）+ `domains/`（13 个域的界面：architecture / audit / chain / chat / conversation / decomposition / governance / metrics / operations / organization / platform / validation / welcome）+ `dashboard/`。
运行数据在 `~/.factory`（不是仓库里 ✓）。

## 3. 干活前必守的规矩（违反即返工）

### 3.1 冻结架构约束（INV-001~015，不得违反）
- **任一事实只能有一个 Domain SSOT**（backlog `TASK-*` = Task SSOT · exec `T00x` = 执行记录域 · `execution_plan T-*` = 历史冻结）
- 跨 Domain **只引用/映射/投影**，不得形成第二个可独立修改的事实源
- 生产链：`Plan → Task → Run → {ExecutionRecord, Artifact, Verification}`；Artifact/Verification 归属 Run/Record
- Agent：`Task → Capability Constraint → Router → Agent`；Model：`Task/Agent → Model Policy → Model Selection`
- **改冻结决策要人工批准**（AI 不得自行重新设计 STEP10）

### 3.2 状态语义（冻结，别自己解释）
`FAILED` = 任务自身执行失败（Task SSOT 事实）· `BLOCKED` = 依赖失败传播（派生投影）·
`CANCELLED` = 用户取消 · `UNKNOWN` = recovery 无法证明 Run 结果 ·
`Ready` = todo + 全依赖 done（派生）· **真并行未实现**（单任务串行，不得宣称并行）

### 3.3 版本号（`docs/release.md`，守卫会查）
**每改一次就递增末尾号（patch +1）**，同一个提交里**三处同步**：
`pyproject.toml` · `README.md` · `CHANGELOG.md`。只改文档/守卫**也算改动**，照样递增 ✓
递增只能往上，禁止倒退 ✗

### 3.4 提交与留痕（每个版本的固定四件套 + 两个派生）
代码/文档改动 → 同提交带上：`CHANGELOG.md`（Added/Fixed/Changed/Known gaps，逐条带证据）·
`docs/WORKLOG.md`（**追加一行**，只往后加不改历史）· `docs/TODO.md`（改动到的项更新状态 + 版本号）·
`apps/api/status.html`（跑 `scripts/build_status.py` **重新生成**，不许手写 ✗）

### 3.5 禁令（`AGENTS.md` §7）
- 不得把 **FUTURE 当 CURRENT** / UNKNOWN 当 FAIL / 注册当生产
- 不得在**无指令**时：push · 修改生产代码 · 进 Fix Sprint
- 修复完成**不自动 commit**（等指令；指定文件时 `git add` 严格只加那些）
- 架构/UI 工作：**先审计（零代码）→ 计划 → 用户批准 → 才实施**；大改动先问

### 3.6 验证铁律
- **代码存在 ≠ 完成**；占位 UI 不可接受；**实测 bug 必补回归测试**；用户实测 confirm 才算 CLOSED
- 报「已删 / 已做」前**回读核实**；管道退出码会骗人 ⇒ 取 `${PIPESTATUS[0]}`
- 测试进程用完必 kill，且**只认本会话启动的精确 PID**（禁 `pkill -f` 模式匹配 ✗）
